# Frontend Interaction Conventions

Maintain shared navigation, form, notification, and feedback behaviors across themes. For component properties and examples, see [Component API](../../../packages/ui/COMPONENTS.md).

Conditionally rendered dialogs and drawers use shared `ModalPresence` to remain mounted until exit finishes, including settings forms, confirmations, resource permissions, plans, memories, plugins, and identity verification. Closing must not clear the body early. Permanently mounted Dialog / Drawer components retain their title and contents during exit. Nested modals close independently; closing a parent waits for its children. Docked chat panels retain their width animation, while modal panels use the shared exit lifecycle. Forms, subscriptions, and modal restrictions are released and focus is restored after exit; reduced motion completes immediately. Page navigation cleans up directly.

The chat plan panel switches horizontally between its list and details within the same drawer, reusing the standalone plan page’s detail rendering and styles. The header back button restores the list and the original item’s focus while preserving list scroll position. The inactive view is inert and hidden from the accessibility tree. Details remain mounted during the return transition; system or account reduced-motion preferences switch views immediately.

## Navigation and Account Entry

The mobile bottom navigation retains only business pages, using a floating rounded rectangle style with shadows. The selected item expands to show text, while others display only icons. Transition animations respect the "reduce motion" setting. The menu overlays content that fills the viewport. At the end of scrollable content on each page, space is reserved for the menu height, vertical spacing, and the device's bottom safe area, ensuring the last item is fully visible when scrolled to the bottom. On mobile, the status bar for Plans and Workbench scrolls with the content. The empty state of the plan list fills the available height, while the calendar maintains its full grid height. The status bar is positioned between the end of the content and the menu's reserved whitespace. Isolated plugin iframes shorten their own viewport to avoid content occlusion. When entering chat details, the menu fades out downwards; when returning to the assistant list, it fades in upwards. Interaction with the menu stops immediately upon exit initiation. Quick returns can reverse the transition from the current progress. If the system or account has "reduce motion" enabled, the switch is immediate. Both built-in themes provide a chat back button. When opening the mobile chat panel and returning to the list, an in-place opacity transition is used, unmounting after the exit completes. Interaction is disabled during the exit. If "reduce motion" is enabled, the switch is immediate. Desktop chat does not use this animation. The entry for hiring a new assistant on mobile is located to the right of the search button, using an icon-only ghost button. The desktop version retains the entry at the bottom of the list.

The default theme displays the user avatar and username in the original Logo position. The test theme reuses the same entry above the assistant selector, clicking which enters User Settings. The User Settings list is arranged in the following order: General, Profile, Security, Notification Settings, Theme, Usage, Memory, Personal Data Export, Departed Assistants, and About. Admin Settings are accessed via a button in the top-right corner of the User Settings page header; this button is not shown to regular members. The Admin page header allows returning to User Settings. Admin Settings → Components (`/#/settings/components`) lists browser component versions, status, installation progress, and install, update, and repair actions. Each row’s Settings button opens a shared Dialog for proxy settings, loading the configuration on demand. Saving closes the dialog and shows feedback; cancellation or Escape discards the draft and restores trigger focus. On narrow screens, the form unmounts after the drawer exit animation; reduced motion closes it immediately. The last section of User Settings, "About," displays the versions, commits, and consistency status of WebUI and Runtime, along with the recommended release version and a GitHub Star entry. The version consistency status and the last confirmation time are displayed on the same line, with the confirmation time right-aligned. On narrow screens where space is insufficient, it wraps to a new line. The Runtime name and address are placed in a separate "Service Information" group on the About page, located below the version information. Device and login times are viewed on the Security page. Logging out of the current device uniformly uses "Log Out," and no separate connection settings page is provided. The top of the About page displays the Logo and current version side by side, with update status and actions placed first. The version number and commit are aligned, and the GitHub entry is placed at the bottom of the page. Mobile maintains the same information order, with upgrade guides expanding on demand. After login, the host layer shares the update status, reading it every five minutes and when visibility/connection is restored. When the About page is active, it checks the release source according to the server-side cooldown policy. Inconsistencies between frontend and backend show an entry marker for all members; new release versions show an entry marker only for admins. Admins can view fixed-version upgrade guides generated from installation records. Pages are not automatically refreshed, and updates are not automatically installed. The full Logo uses `animation="daily"` and interactive mode, switching day/night cycles based on device local time and respecting the "reduce motion" preference. Profile reuses existing avatar selectors and thumbnail processing. Avatars saved to the account are displayed in the desktop sidebar, mobile top bar, and admin user list.

## Shared Components and Profile Synchronization

Chat history loads earlier messages through centered text between light divider lines, using the same color as list separators. When the distance from the scroll bottom exceeds one message-area viewport height (at least 600px), a floating “Back to latest messages” button appears at the bottom of the message area without taking composer space or changing scroll height. Returning clears search-message navigation and any pending pagination scroll restoration, immediately scrolls to the bottom, and resumes following the latest messages. Scrolling, message updates, and message-area resizing refresh the button visibility.

Desktop main sidebar buttons are uniformly 44px. Menu buttons have a transparent background by default, showing a rounded rectangle background on hover and selection. Search buttons and account avatars remain circular, with avatars and buttons being the same size. The Logo remains unchanged, and mobile continues to use the bottom navigation layout.

After saving an avatar or display name, account profile information is synchronized in the background to the current page and same-origin tabs, preserving workspace and connection. Login, logout, and identity switching still reinitialize the session.

Shared Tooltips in locations such as the sidebar close and clear delay timers when the window loses focus or the page is hidden. Restoring focus by switching back to the page does not trigger the tooltip; subsequent keyboard navigation or mouse hover displays it normally. This behavior is handled by shared components, so the host does not need to clear button focus. Tooltips share a set of window activity listeners. Keyboard and pointer presses only advance the input version; instances in the process of closing do not execute input callbacks individually. Shared listeners are removed when the last instance unmounts.

## WeChat Connection and QR Code

The "… → Switch chat channel" in the top-right corner of the chat page opens a standalone connection management modal. After binding, the bottom uses shared `ChatComposer.lock` to retain the input box outline, displaying only instructions for WeChat sending and unbinding to restore input. "Manage WeChat Connection" opens the same modal. Connected states use success `Alert` (`tone="positive"`) within this modal, while abnormal connection states requiring re-scanning use warning `Alert`. Proactive reminders for re-scanning follow general server-side notifications, displayed in the chat top queue. The assistant information page no longer includes connection operations. The default theme and test theme reuse this flow.

WeChat connection QR codes use shared `--color-qr-foreground` / `--color-qr-background` tokens. All color schemes and light/dark modes maintain dark modules and light backgrounds, preserving the quiet zone for the four modules. QR codes are encoded locally in the browser, and login content is not passed to third-party image services.

## System Reminders and Display Boundaries

The current chat is marked as read when the page is visible, the window has focus, and the reader is at the bottom of the conversation. Docked side panels do not pause this behavior. Dialogs and drawers that cover the chat pause it; closing, removing, or docking them triggers another check. Background pages, scrolled history, and search locations do not automatically clear unread messages. New-message alerts use the same panel obstruction rule.

The host layer `notifications/AssistantNotifications.tsx` provides a chat reminder queue shared by both themes. Reminders for WeChat delivery and connection anomalies, persistent assistant blocking, authorization requests, pending plan handovers, and task/background execution failures are generated by Runtime. Chat banners and proactive reminders share notification IDs. The client does not provide a standalone notification page or notification history list; long-term information is managed by the original chat, approval, plan, and task pages.

Chat displays one reminder at a time, selecting the next one in order of occurrence. New reminders do not replace the current one. Closing only acknowledges the current ID, advancing upon server success. Failure retains the current item and error feedback. After closing, keyboard focus moves to the close button of the next item. The reminder area has no internal scrollbar, but visibility of input and channel operations on short screens must still be checked. Brief model retry prompts are displayed only when there are no server-side reminders. Read status does not hide pending banners. Reminders are resolved by the server once the source issue is recovered.

Toast auto-dismissal and desktop notifications collapsed by the system do not automatically mark as read or ignored. Chat banners and Toasts for background execution failures display "View in Dev Workbench" only when Runtime supports it and the user has enabled the Dev Workbench, locating the execution based on the notification source event. Desktop notifications use the same target; no jump occurs if not enabled. Uncollected or expired executions are clearly indicated in the workbench. Viewing other reminders goes directly to the corresponding business page. View actions in chat and Toasts mark as read. Desktop notifications, sounds, and current browser settings follow existing device policies. Even if proactive reminders are not enabled, pending reminders within chat can still be viewed. New assistant messages continue to use session sequence numbers and read status. Proactive reminders for authorization request cards are handled by notification records to avoid duplicate pop-ups.

Field validation, connection test results, and dreaming conflicts remain in the corresponding forms or business areas. Closing feedback does not clear test results. Brief model retry progress, local network disconnection, privacy notices, and form validation are not written as persistent notifications. `DismissibleAlert` is used for local temporary prompts. General request and operation failures reuse shared Toast via `useErrorToast`, without occupying page layout. Ordinary errors are distinguished by call site; rate limiting and service unavailability are deduplicated within the current session. After closing or auto-dismissal, background polling does not repeatedly pop up. Proactive actions can re-prompt. Prompts are cleaned up upon error recovery, source unmounting, or session exit. Service unavailability Toasts are suppressed when connection banners appear. Errors with retries persist. Rate limit retries respect Retry-After. Timing stops when the countdown expires or the prompt is closed.

## Information Hierarchy in Security Settings

The Security page follows the flat list and fine dividers of other settings pages, arranged as "Login and Verification, Login Devices, Login Links." Changing the password is placed in the corresponding settings row, and logging out of the current device is placed at the bottom of the page. Group titles and settings items use the shared small body text scale, distinguished by font weight. Descriptions, dates, and history entries uniformly use the auxiliary text scale. Device and link names, statuses, and actions are laid out separately. Times use grouped label/value pairs. Wrapping is allowed on narrow screens, with actions remaining right-aligned. Login link history is collapsed by default.

## Resource Tool Directory

The Resource Tools page uses a compact grouped list. Search and categories jointly filter the directory, with category counts updating according to search results. Group definitions share `tool-groups.ts` with assistant information. Empty groups are not displayed. Plugin tools follow account plugin visibility settings. Shared `SearchField` and `Drawer` provide search clearing, keyboard operations, detail closing, and focus restoration. The top of the detail view centrally displays name, identifier, brief description, execution impact, and required operations. Below, shared `Tabs` switches between the original model tool description and parameter structure. The original text directly reads `Description` from the directory, preserving content as plain text. Long descriptions and parameters wrap automatically, sharing the drawer scroll area. Read/write impacts are distinguished by icons and text, using semantic colors adapted to each theme.

## Model Page Action Entries

The page header of the Model tab on the Resource page retains only the "More" menu, centrally providing entries for "Connect Provider" and "Default Model." The default model for the current account is managed in the modal via shared `ModelSelect`, following the immediate settings save flow: read latest settings, replace only `DefaultModelID`, validate version, disable controls during saving, and restore original values on failure. User Settings no longer provide a separate preferences sub-page. Models explicitly selected by assistants take precedence over the account's default model.

## Personal Data Export

The "Personal Data Export" page in User Settings directly explains that the default export includes memories, assistant and task plans, account settings and resource records, and dreaming records, and introduces optional chat history, attachments, and deliverables. Chat history is checked by default; attachments and deliverables are unchecked. Clicking "Export Data" opens a modal to select the scope. After generation, the ZIP file is downloaded on this page. Scope descriptions follow the settings page descriptions and grouped list styles.

## Browser floating window

The desktop browser defaults to a nonmodal floating window. It uses the shared Drawer's nonmodal mode to preserve the DOM, stream connection and control ownership. ChatSidePanel reserves no sidebar space while floating, and chat remains interactive. Docking follows the available-space rules; phones use a bottom drawer. Position and size live in page memory and survive closing and reopening the panel.

`useBrowserView` handles dragging, proportional resizing, arrow-key adjustments and viewport bounds. The page maintains the remote 1280×800 aspect ratio while browser chrome stays at its normal size. Sizing subtracts the measured chrome height and rechecks bounds when auxiliary input expands or the viewport shrinks. Pointer input maps the displayed image back to remote coordinates. `browser-panel.spec.ts` covers floating/docked transitions, chat interaction, aspect ratio, coordinate mapping, bounds and the phone drawer.

The bottom bar contains only connection status followed by the keyboard and end-session buttons. The bottom-right resize area is transparent, with no icon or hover background; it uses a resize cursor and retains an outline for keyboard focus.

## Workspace file explorer

The chat file button shares the single-panel selection with the browser. `WorkspaceFiles` uses Drawer and ModalPresence: a nonmodal desktop window, reserved ChatSidePanel width when docked, and a bottom drawer on mobile. `useFloatingPanel` handles independent dimensions, dragging, keyboard adjustments and viewport constraints; browser geometry retains its separate aspect-ratio constraint. Switching floating/docked modes preserves the component and draft. Per-assistant page memory retains directory, selection, scroll, sorting and hidden-file preferences.

Above 640px panel width, the directory and preview appear side by side; narrower panels switch between list and detail. Creation, renaming, moving, deletion and upload conflicts use shared overlays. Edit conflicts preserve drafts and offer reload or save as; ordinary failures use error Toasts. Application navigation and panel switching use the cancelable `molr:before-navigation` event to protect unsaved edits. Browser closing uses beforeunload; page memory also retains drafts for native history navigation.

`workspace-explorer.spec.ts` uses a real Runtime to verify desktop/mobile file operations, upload and version conflicts, and window geometry. Palette checks and screenshots remain in local internal records.
