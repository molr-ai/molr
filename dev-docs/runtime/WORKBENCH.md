# 开发工作台

工作台位于现有 WebUI 的 `/#/workbench`，共用登录、Runtime 连接和组件库。主导航可查看所有助理的执行，聊天更多菜单的「调试此助理」会打开 `/#/workbench/<assistant_id>`。聊天消息的本轮信息弹层也提供「在开发工作台中查看」入口，通过 `/#/workbench/<assistant_id>?turn=<execution_id>` 定位本轮执行，自动按游标补载目标轮次的起始记录，暂停跟随、选中轮次并打开触发快照；刷新保留定位目标，同一轮的多个执行尝试定位到最早保留的尝试。目标未采集或已过期时明确提示。仅在部署能力与个人开关均已开启时显示。后台执行失败提醒使用 `/#/workbench/<assistant_id>?event=<event_id>` 定位触发事件，依据已保留 Run 的 `EventID` 选择对应轮次的最早保留尝试，复用历史分页定位及未采集提示。通知的 `Source.ID` 是事件 ID，不能当作 `ExecutionID`。聊天横幅、Toast 和桌面通知仅在部署能力与个人开关均已开启时提供工作台跳转；关闭时保留提醒及关闭操作，Toast 的入口随开关更新。常规设置提供「显示开发工作台」开关；Runtime 未开启能力时禁用该开关，并在服务端拒绝强行开启。

## 采集与入口显示

部署配置 `debug.enabled` 是唯一的采集开关，默认关闭。开启后为所有账号采集新的执行，包括尚未打开工作台或尚未保存个人设置的账号。常规设置「显示开发工作台」（`Settings.WorkbenchVisible`）只控制导航、聊天菜单、本轮信息和通知中的入口显示，不影响采集、调试接口权限或已打开页面的实时连接；隐藏入口时仍可通过已有链接访问。打开显示后可查看保留范围内此前采集的记录，未采集或已过期的内容不会补录。关闭部署开关停止采集并禁止轨迹、详情、检查点和通知流访问，不立即删除已有记录。部署开关不能通过 WebUI 修改。

```json
{
  "debug": {
    "enabled": true,
    "max_runs": 1000,
    "max_payload_bytes": 4194304
  }
}
```

默认每个账号保留最多 1000 次执行，账号下所有助理共享条数，包含做梦执行。管理员在「管理员设置 → 开发工作台」设置执行次数上限（1–10000）；留空使用部署默认值。策略持久保存，覆盖部署文件的默认值，无需重启；保存采用版本检查和幂等键，在后续采集写入及执行结束时生效。

超过条数上限时，按开始时间、首修订号和 ID 从旧到新整次删除已完成执行；运行中的执行保留到结束，可能暂时超过上限。不再设置保留天数、详情总容量或最低保留数，不因旧详情占用而跳过新详情。删除元数据同时释放该执行的详情引用；共享上下文仍被业务检查点或其他历史记录使用时继续保留，最后一个引用释放后由后台回收。详见[上下文存储](CONTEXT_STORAGE.md)。

工作台不常驻显示保留策略。当前助理实际发生清理时，在加载到轨迹起点后显示「更早的事件已被清理」，悬停、聚焦或手机点击展示当时的条数策略；未清理时显示「没有更早的事件」。之后修改设置不会改写已有清理事件。

单个调试负载上限仍由部署配置控制，默认 4 MiB。超限负载标记 `too_large`，执行记录标为不完整；不再以单次执行 1000 条步骤为界停止采集。核心业务上下文写入失败会停止 Agent 推进；可选的调试采集失败只标记记录不完整，不重试业务操作。服务启动把上个进程留下的运行中轨迹标记为中断。

条数检查与步骤记录处于同一事务，执行数在 SQLite 内按账号汇总。未超限时不加载历史正文；超限候选分批读取，每批最多 200 条。详情引用、摘要、运行记录和清理策略快照同事务更新，回滚不留下部分清理结果。

## 页面与记录

工作台默认按助理展示跨 Run 的连续轨迹。主导航进入时选择第一个在职助理（没有在职助理时选择第一个助理），也可从助理选择器切换，选择器仅列出在职助理；通过已有链接打开离职助理及已打开的工作台行为不变，聊天菜单仍直接定位对应助理。Run 表示一次触发事件的执行尝试；同一 ExecutionID 的重试在界面合并为一轮，只显示一次触发消息和轴上触发标记，轮次状态取最新尝试。各次请求仍保留独立 Run ID、耗时、结果与详情，原始事件也不合并。折叠轮次会收起所有重试；从轴选择任一次调用会展开所属轮次并定位该调用。

页面采用紧凑事件表：顶部合并助理选择、连接状态和上下文入口，标题下方直接显示轴概览，模型／工具筛选、原始事件、跟随最新与搜索排列在概览下方的一行，搜索框靠最右侧；原始事件与跟随按钮共用尺寸、间距及选中配色，手机显示为带无障碍名称的图标。移除「连续轨迹」标题与执行／调用统计，标题和轴之间保留单条边框，轴不再显示「时间概览」文字。列表与详情区域共用顶部边框，事件行仅由行底部分隔，起点提示底部补充分隔线，避免首个事件缺线或相邻事件叠线。列表移除列标题行，执行编号直接显示整数，不补前导零；记录仍按类型、内容、状态和耗时对齐。普通请求不展示尝试次数或 HTTP 状态，仅重试请求标注「重试 1/3」；首次请求不标记；最多尝试 4 次时，后续依次显示「重试 1/3」「重试 2/3」「重试 3/3」。完整请求次数和 HTTP 状态保留在详情中。轮次分隔显示执行编号与触发时间，重试单独标明；移动端使用两行记录和独立列表滚动。工具摘要按工具含义展示：发送消息显示正文（无正文时显示卡片标题或附件数），读取聊天记录显示实际返回条数，文件操作显示路径，命令执行显示命令，记忆搜索显示查询，计划操作显示标题或动作。读取条数仅从成功结果计算；执行中、失败或缺失结果时仅显示操作名称，不把 limit 当成读取条数。列表和悬停共用摘要，搜索包含这些可见摘要；完整参数与结果仍在侧边详情中查看。

上下文压缩开始／结束记录之间的模型调用在轨迹列表及时间轴显示为「上下文压缩」，分类仍为模型调用，耗时、状态、详情和筛选保持不变；识别依据是已加载的压缩边界事件。

上方概览依次展示触发、模型、工具三条轨道。触发标记包括用户消息、计划、操作完成和恢复请求，位置采用已记录的执行开始时间；点击会定位对应轮次并打开触发快照。时长轴按真实起止时间展示持续时长与空闲间隔；两种模式都不显示底部横坐标，具体时间仍可在悬停和范围面板中查看。事件轴按采集顺序为每个触发／调用分配等宽位置，不表达耗时。两种模式都支持点击定位、拖选区间和缩放。范围面板复用组件库 `RangeSlider`，在同一条轨道上拖动两个手柄，时长轴显示时间范围，事件轴显示事件序号范围；也可使用 Tab、方向键与 Home / End 操作。事件范围按记录身份保存，加载更早历史或追加新记录后不会自动换成其他调用；切换坐标模式会清除原范围与缩放。下面的虚拟列表连续展示各次执行，模型与工具调用按 Run 内的 OperationID 聚合开始／请求／响应／完成步骤，工具可随所属模型调用折叠。记录直接展示工具名、参数／结果摘要或模型输出；「显示全部事件」切换到预算、权限和检查点等原始步骤。搜索只匹配已加载的名称、状态和摘要，不搜索尚未读取的完整负载；时间筛选也只覆盖已加载范围。

做梦事件复用普通模型调用详情，批次信息和记忆整理结果仅放在「概览」内容区，随内容滚动；其他标签不附加做梦面板。「概览」区分新增记忆、待确认的新记忆、修改建议及丢弃项。修改建议展示提交时保存的原文与建议内容，确认前不表示原记忆已修改；后续编辑记忆不会改写该历史原文。

桌面选中记录后打开右侧详情，窄屏详情覆盖轨迹区域并可关闭。详情优先展示输入与输出，把事件 ID、连接和操作状态收进「调用信息」；调用上下文、差异、供应商请求、响应内容及元数据、费用和原始数据仍可查看。独立的「最新检查点」与历史调用上下文分开，保留停止执行和重置上下文操作。

初始加载最新 100 条步骤，点击「加载更早轨迹」逐页补入历史，保持当前阅读位置。默认跟随底部；上滚、选择记录、折叠或筛选会暂停跟随，重新开启跟随会清除筛选并返回尾部。新记录通过游标补齐，即使断线期间超过一页也不会只保留最新一页。每次刷新同步保留范围，移除已被清理的运行。

调用缺少开始记录时标明尚未加载，缺少结束记录时不显示推算的完成耗时；开始／结束都存在才计算区间耗时。最新一次上下文重置使用 Runtime 已保存的重置时间显示边界，不从历史对话推断更早的重置。首 token 延迟、生成吞吐量、逐 token 更新和未采集的历史不可用。

记录包含触发事件和助理配置／权限快照、检查点加载、上下文构建、可用工具、模型调用前的完整逻辑上下文、预算校验快照、模型权限检查、脱敏后的请求、HTTP 响应元数据、模型输出引用及用量、工具参数与结果、最终上下文及检查点保存结果。每次检查点成功保存只采集版本号、前一版本、保存时间、原因、上下文原始字节数和 `ContextOmitted=true`，不再将完整检查点复制到每条调试事件。执行恢复仍持久保存完整的最新检查点；历史模型输入、请求和本轮起始／最终上下文快照继续采集。中间保存事件不提供该时刻的完整上下文或差异，UI 明确指向模型调用上下文和最新检查点。旧记录保持原格式并可继续读取。预算快照包含上限、已用与预留占用、所需金额、周期和换算规则。金额沿用原币种，展示复用多币种组件。

一次事件可以有多个执行尝试。每次尝试都有独立 Run ID，并关联原 EventID、逻辑 ExecutionID、Attempt、OperationID 与 Receipt，便于辨认每次请求和重试。已处理事件的幂等重放不会产生虚假的新模型调用。

上下文面板在历史调用和最新检查点中展示 system / assistant / tool / user 的字符占比进度条。按消息正文、工具名及参数值的 Unicode 字符数估算；不计消息封装、参数字段名、JSON 序列化增加的标点与转义、附件、工具定义或后端专属状态。工具调用归入 assistant，工具结果归入 tool；角色沿用实际上下文；新触发事件和 Runtime 通知使用 user，基础指令使用 system。该比例不是 token 用量。聊天界面不再展示上下文用量与压缩次数行。

上下文视图展示实际 `model.Input` 的角色、内容、工具调用及工具返回；模型请求视图展示序列化后的供应商请求体和模型配置。工具与会话历史只有实际进入请求时才出现在相应快照中。消息差异比较相邻模型调用，首次调用与加载的检查点比较。模型未返回的内部推理不属于可观测数据，未采集的历史请求不会反推生成。

新生成的自动上下文、控制、恢复、核对、交接和加急通知直接使用 user，旧检查点中已识别的 Runtime 通知在继续执行／请求投影时迁移。此前工作台「调用上下文」记录的是适配器转换前的内部 role，因此可能有多条 system，而「模型请求」里已只有开头一条 system。历史轨迹和检查点加载快照保留采集时的原始数据，升级后不会重写。

模型返回的后端专属状态可在上下文消息中展开查看，包括原始负载及所属协议、Provider、模型和端点。实际回传规则由[模型适配器](MODEL_ADAPTERS.md)决定；检查点保留状态不代表当前后端会接收该状态。

## Runtime 实现

凭证字段识别复用只读的字段名替换器，统一移除下划线与连字符并转为小写；替换器可供多个采集任务并发使用。每次采集仍独立解析和脱敏负载，不缓存业务内容。字符串中的嵌套 JSON 对象和数组允许前导空格、制表符、回车及换行，内部敏感字段仍递归脱敏；无需脱敏且无多余尾部内容的 JSON 字符串逐字保留。文本凭证模式、深度及大小限制继续生效。

`internal/debugtrace` 是单体 Runtime 中的固定模块，使用现有事务存储：`debug.runs` 保存运行和步骤元数据，`debug.summaries` 提供轻量列表与保留策略索引，`debug.payloads` 保存采集状态与共享内容引用标记，完整详情由 `contextstore` 按需还原，`debug.revisions` 提供实时通知游标。`debug.cleanup` 按所有者和被清理助理保存最新清理事件，与实际删除处于同一事务，不保存被删除的私有内容。Agent Loop、模型适配器和预算模块通过可选观察入口记录数据。调试读取接口与业务执行接口分开，工作台不能伪造运行身份、工具调用或结算凭据。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/status` | `workbench_available` 标明部署能力 |
| GET | `/api/debug/retention` | 生效策略及当前账号用量，不受个人显示开关影响 |
| GET / POST | `/api/admin/debug/retention` | 管理员读取／保存安装级保留策略 |
| GET | `/api/debug/trajectory?assistant_id=&limit=&cursor=&after=` | 跨 Run 的轻量轨迹分页及增量补齐 |
| GET | `/api/debug/runs?assistant_id=&limit=&cursor=` | 分页执行列表 |
| GET | `/api/debug/runs/{id}` | 时间线元数据 |
| GET | `/api/debug/runs/{id}/steps/{step}` | 选中步骤负载 |
| GET | `/api/debug/assistants/{id}/checkpoint` | 最新检查点 |
| POST | `/api/debug/assistants/{id}/context/reset` | 重置指定助理的私有运行上下文 |
| GET | `/api/debug/stream` | 独立实时通知流 |

轨迹接口返回 `Items`（RunID 与步骤元数据）、当前保留范围内的 `Runs` 摘要、`NextCursor`、`HeadCursor` 和指定助理的 `ContextResetAt`、`Cleanup`（最近一次真实清理的时间 `At` 与策略快照 `Policy`，未发生时为 `null`）。完整上下文和请求体仍由步骤详情接口按需读取。`limit` 默认 50、最大 200：不带游标读取最新一页；`cursor` 向前读取更早页；`after` 按采集顺序补入更新，二者不能同时使用。每页 Items 从旧到新排列；实时补齐时继续使用 NextCursor，直到为空，再保留 HeadCursor 等待下次通知。

游标绑定所有者和助理筛选，记录被保留策略移除后仍能继续分页。新采集的步骤持有同一事务生成的递增修订号，避免相同时间戳或系统时间回拨造成漏读；旧记录按时间、Run ID 与步骤序号排序。工具语义摘要 `Summary` 在截断前从已保存的完整脱敏负载提取，返回文本或实际结果条数，不为列表额外加载详情。步骤摘要仅从已脱敏内容生成，工具名最多 80 字符、摘要最多 240 字符（截断另附省略号），超限／不可用负载不生成摘要。旧记录按当前请求页从已保存负载提取摘要，不重放外部请求。运行摘要维护首尾修订号，实时读取可跳过没有新增步骤的运行。

通知流只发送记录修订号，不发送上下文。客户端按需刷新列表、时间线与选中负载，支持 `Last-Event-ID` 断线续接。与普通事件流共用连接数限制和写入超时。

工作台通知流按所有者监听已提交的版本变化；事务回滚不发送通知。空闲连接不定时查询版本或身份，只每 10 秒发送保活注释。账号变更、会话／令牌撤销和凭证到期会触发身份检查；发送新版本前仍校验当前身份和调试读取权限。连接重建按当前版本与客户端游标比较，客户端再读取持久化轨迹。

仅当前所有者会话或拥有 `debug.read` 作用域的所有者令牌可读取。助理身份不能读取，所有数据查询绑定所有者。不会记录 HTTP 请求凭证头；在写入前剔除明确的凭证字段、Bearer 值及可识别的密钥。上下文本身包含用户私有资料，不能复用普通聊天 SSE 对外广播。当前提供观察、历史定位、停止执行和重置上下文；单步调试、任意编辑上下文与重新执行尚未提供。

## 重置上下文

选择助理，打开「最新检查点」，点击「重置上下文」并确认。确认窗口显示助理名称与影响范围；没有检查点的助理也可重置。已离职助理不可重置。

请求包含 `Mutation.IdempotencyKey` 和必填的 `ExpectedSequence`（没有检查点时为 0）。服务端要求工作台部署开关已开启，个人显示设置不参与鉴权，验证所有者及助理写权限；令牌还需 `debug.write`。确认期间检查点变化返回冲突，需要刷新后重新确认。

同一事务取消当前及已排队的旧执行，写入空上下文并递增检查点序号，清除助理的等待原因并恢复接收新事件。重置时间还会阻止迟到的旧事件再次执行；活跃模型请求会被取消，旧执行无法覆盖新检查点。重复提交相同幂等键不会清空后来产生的上下文。

聊天记录、长期记忆、助理配置、权限、预算、日程、历史调试记录与费用证据均保留。重置不把业务任务标为完成，也不释放结果尚未核实的费用占用；已发出的外部请求仍可能产生效果或费用。重置本身不会调用模型，用户发送新消息或后续日程触发后才开始新的执行。

### 内容预览

用户消息轮次的选中背景及左侧标记覆盖整行（包括折叠按钮与详情入口），与模型、工具记录保持一致。左侧标记与时间轴共用类型及状态色：触发为中性色、模型为模型色、工具为工具色，失败为错误色。

轨迹列表用于快速定位：用户消息与轮次信息同行显示，模型输出及工具入参均采用单行省略摘要，工具结果保留在详情中。桌面记录行高 44px，手机调用行高 64px；点击用户消息或调用记录打开详情，左侧箭头单独控制折叠。最右侧箭头直接打开完整详情，按需读取已采集负载；长内容在详情内滚动。详情面板仅位于下方记录区域，打开、切换和关闭时，上方时间轴的宽度及位置保持不变；窄屏下详情覆盖下方列表，时间轴仍可使用。虚拟列表在补载历史时保持阅读位置。

新运行在开始时采集用户输入或对应版本的计划内容，与模型实际输入独立保存，并沿用凭证脱敏及负载大小限制。运行摘要中的正文最多 1000 字符、标题最多 128 字符；完整内容保存在起始步骤。旧记录缺少快照时只在所有者及助理范围内关联原始消息或同版本计划，并标注“关联原始内容”；来源已删除、计划版本不同或未采集时明确显示不可用，不用当前计划内容冒充历史快照。

完整详情中的参数、结构化结果、上下文、上下文差异、模型请求、响应元数据和原始数据统一使用共享 `CodeBlock` 显示 JSON 高亮；普通正文保留文本展示。代码区域支持换行，统一通过 Tab 内容区滚动；超大负载回退为完整原文，沿用既有采集与脱敏规则。


模型响应使用 small 尺寸的分段式 Tab 区分外层导航，默认打开「响应内容」，依次展示实际返回的 thinking（如有）、content 和工具调用；拒绝说明也会保留。thinking 与 content 可分别折叠，默认收起 thinking、展开 content。完成事件持有包含输出消息的上下文引用，读取详情时从最后一条 assistant 消息提取正文、后端状态与工具调用，不另存预计算结果。工作台摘要仍独立保存，用于列表和搜索。工作台清理时释放详情引用，当前检查点仍持有的消息不会被回收。

「响应信息」展示 HTTP 状态、Content-Type 和是否完整，不提供原始 HTTP／SSE 响应体。原始响应只有在部署配置 `diagnostics.model_responses=true` 后才写入轮转文件日志，默认关闭，与工作台采集开关独立。调用中断或完整输出未采集时明确显示不可用，不尝试从半截 SSE 恢复输出。



详情面板不再提供「原始步骤」入口。「原始数据」展示轨迹中当前选中记录的数据，切换详情 Tab 不改变选中记录、概览或标题。如需检查其他步骤，可在轨迹中开启「显示全部事件」后选择相应记录。



事件详情采用固定标题与 Tab 导航、独立滚动的内容区。概览将正文、工具调用、用量与调用信息分组，长 ID 收入调用信息；上下文按消息序号、角色与来源分组，角色占比始终竖排，每个角色独占一行，Runtime 上下文快照的 JSON 与说明分别显示。差异页汇总未变、移除与新增数量；模型请求将配置和请求体分开，响应信息展示 HTTP 状态与完整性。原始数据保留完整 JSON，所有视图共用标题、间距、折叠区与空状态样式。


详情中的正文与代码块不限制高度，也不单独提供纵向滚动，统一由 Tab 内容区滚动。请求体、响应体、原始数据、输入／输出、工具调用与非空差异区块均可折叠，默认展开；thinking 仍默认收起，content 默认展开。上下文消息沿用各自的折叠控制。
