# 微信渠道

固定 Go 适配器位于 `runtime/internal/im/weixin`。协议核查基于 `@tencent-weixin/openclaw-weixin@2.4.9`（2026-10-06）；参考 [腾讯协议说明](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol.md)。这是固定渠道适配器，不加载 OpenClaw 或常驻后端插件。用户操作见 [微信聊天入口](../../docs/weixin.md)，请求字段见 [HTTP API](HTTP_API.md)。

## 入口和身份

绑定属于 Molr 用户、助理及现有会话，同时固定微信机器人和扫码用户。扫码结果只由已认证、具有助理写权限的请求确认。二维码请求保存在进程内并在五分钟后失效，取消后迟到的确认不能生效；重启需重新发起尚未完成的扫码。已完成绑定持久化，不依赖浏览器会话存活。

一个微信用户或机器人不能跨助理或账号重复绑定。每条入站拒绝群消息、机器人回流和非绑定发送者。每次收发重新检查账号启用和助理状态；解绑删除绑定、取消队列，并使旧绑定代际失效。解雇暂停渠道，返聘恢复；克隆默认仍为 WebUI。

`conversation.ReceiveChannel` 是仅供可信装配使用的消息入站入口，不属于 HTTP `Client`。它在事务内通过 `AuthorizeChannel` 验证当前绑定，不伪造用户 Session 或创建全权限 Token。普通 `SendUser` 在同一事务内经过 `CheckWebInput`，绑定存在时拒绝 WebUI、SDK 和插件的聊天写入。读取、管理和审批维持既有权限。

## 持久化与投递

状态查询按当前账号与绑定筛选，以保留纳秒精度的创建时间取得最近 30 条投递；相同时刻按记录键倒序选取，再按会话序号与分段号升序返回。查询使用对应的复合索引，历史增长不要求先排序全部投递。

私有 keyspace 为 `weixin.bindings`、`weixin.incoming`、`weixin.deliveries`。绑定凭据使用 AES-GCM 和绑定身份 AAD 加密；不出现在状态 DTO、SSE、模型上下文或日志。网络仅允许经过域名校验的微信 HTTPS API，实际 DNS 地址必须为公网，禁止 HTTP 重定向转发令牌。

入站批次的消息去重记录、聊天写入、回复凭据及游标在一个事务中提交。消息 ID 无损保留 uint64 数值；同一机器人和用户的重复消息不重新触发助理。轮询只负责入库，不等待助理执行。

助理显式 Publish 时，`Published` 回调在同一消息事务中创建独立投递记录，不竞争调度器消费的 IM Outbox。默认只向当前绑定投递新发布的消息，不补发绑定前历史。内容拆分按 UTF-8 边界，每段最多 3500 字节；每个附件另建投递记录，成功的文字不会掩盖附件失败。图片上传后以图片消息发送，其他附件以文件消息发送。卡片转换成标题、摘要及需要登录的 Molr 链接。

投递先持久化 `sending` 再请求平台。HTTP 200 的合法 JSON 对象在 `ret` / `errcode` 均无非零错误时记为 `accepted`；与腾讯 2.4.9 客户端一致，成功响应允许省略 `ret`，不能因此标为未知。空响应、`null`、无效 JSON 仍属于未知。缺少上下文或 `ret=-2` 为 `waiting`，新入站上下文可重新唤起；HTTP 429 最多尝试五次、每次至少间隔一分钟。超时、普通 5xx、无完整成功响应为 `unknown`，不自动重发；进程重启时将遗留 `sending` 变为 `unknown`。`ret=-14` 暂停收发并要求重新扫码。`client_id` 在投递创建时固定，但不假设服务端提供严格幂等保证。

解绑或替换绑定时，取消查询按账号、绑定代际及 `pending / waiting / sending` 状态筛选，只加载仍可取消的投递；已完成、失败或未知结果的历史记录保留原状。取消投递、解决对应提醒及清理引用映射仍在同一事务内完成。

发送与解绑使用同一助理的锁串行化；在解绑返回前已经发起的请求可能已经被平台接受。账号撤权不能撤回已进入网络的外部请求。Runtime 生命周期取消并等待渠道 worker 后关闭数据库。

## 证据边界

协议文档来自客户端实现，不代表完整服务端契约。`context_token` 无固定有效期承诺；成功响应不是已读回执。真实账号扫码、验证码、客户端展示及长时间无交互后的行为仍需账号验收，模拟协议测试不能替代这些验证。原生历史同步、群聊及多入口发送不在本版范围。媒体协议与错误路径已由可控传输验证，真实微信客户端的图片/文件展示仍需账号验收。

## 错误展示与刷新

轮询调度同时保留 `connected` 和 `reconnecting` 绑定。可重试错误使用共享 `retry.Policy`，连续失败后依次等待 5、10、20、40、80、160、320、640 秒，之后保持 640 秒，不限制次数、不加随机抖动；等待从本次失败处理结束后开始计算，成功轮询并提交入站批次后重置为 5 秒。网络、凭据读取和入站处理失败共用这一退避计数，解绑或权限失效可取消等待。Runtime 重启后也会恢复重连中的绑定，但退避计数从头开始；需要重新扫码时停止轮询。退避计算集中在 `runtime/internal/retry`，模型重试复用同一计算，并保留自己的间隔配置、抖动、次数和总等待限制。

连接进入 `reconnecting` 或 `login_required` 时生成统一连接通知，分别说明自动重连和重新扫码。同一连接状态的重复失败不重复提醒，关闭提醒不停止重试；成功轮询或解绑后自动解决通知。错误原因变化但仍在自动重连时保留同一通知，需要重新扫码时更新为新的提醒。

聊天页仅在投递异常时显示一处提示，包含失败、未知、等待新上下文和限流重试；成功与正常排队不显示。投递写入同一事务内同步 `notification` 模块，按投递 ID 与状态／错误码区分异常。前端读取统一通知记录，关闭通过通知接口保存忽略状态，不再由组件内存决定。发送中不提前解决旧提示，成功或取消后解决；等待、失败、未知和限流结果生成提醒。不设置投递详情。历史未知记录不猜测改成成功，也不自动重发。

WebUI 的共享错误提示按错误码去重，优先显示在当前弹窗；关闭后后台查询不会反复重现，新的显式操作可重新提示。提示使用紧凑语义色样式，不默认展开请求编号。SDK 解析 HTTP `Retry-After`，同一登录身份在窗口内暂停普通 GET 请求；重试按钮显示等待时间。查询重试只刷新本查询，微信投递事件只刷新微信状态，二维码轮询不使页面数据失效。

## 图片、附件与模型上下文

媒体协议参考 [腾讯上传/发送实现](https://github.com/Tencent/openclaw-weixin/blob/main/src/messaging/send-media.ts) 与 [下载实现](https://github.com/Tencent/openclaw-weixin/blob/main/src/media/media-download.ts)。入站先校验发送者、绑定和去重记录，在 SQL 事务外下载/解密文件，使用 `files.ChannelStore.UploadChannel` 保存到现有文件体系，再在消息事务内复查绑定及文件归属并关联 `AttachmentIDs`。文件写入复用大小、配额、幂等和对象提交机制；绑定失效后不能继续写入或关联文件。部分附件接收失败时保留文字及成功附件，并明确标注失败内容未读取。

渠道附件上限取 Runtime `MaxUploadBytes` 与 100 MiB 的较小值；不配置时使用 20 MiB。图片和普通文件双向支持，视频入站保存为附件、出站按普通文件发送。媒体 CDN 只允许 HTTPS `*.cdn.weixin.qq.com`，沿用公网 DNS/IP 校验并禁止重定向，不携带机器人 Authorization。按腾讯格式使用 AES-128-ECB/PKCS#7，支持图片 hex key 及媒体 raw/hex-base64 key。下载和响应读取有字节及时间上限。

CDN 上传对网络失败、HTTP 408/429/5xx 和缺少下载参数头最多尝试三次，复用相同上传地址、file key 和密文，间隔 250/500 ms；其余 4xx、非法地址或取消立即停止。上传/本地读取失败发生在发送消息前，明确记为 `attachment_failed`；最终 `sendmessage` 的超时或异常回包仍为 `unknown`。出站只读取已通过正常 Publish 授权且固定到 outbox 的文件 ID，不接受外部文件选择器。

每次模型请求通过实时 `chat_channel` 自动上下文提示当前微信入口、图片/文件/语音接收能力、引用上下文边界、避免交互卡片和必要卡片的文字降级方式。解绑后上下文源移除，不写入助理永久指令。二维码连接页面在授权前显示腾讯可能保留消息和附件的数据隐私提示。


## 引用与语音

入站解析 `ref_msg` 的内嵌文字/附件、`svr_id`、`partial_text`。入站 ID 和发送成功响应中的服务端 `message_id` 均无损解析，引用映射按账号、绑定代际隔离持久化；同批入站也可引用前一条。每个绑定最多 4096 条映射、有效期 30 天，每条文字最多 16 KiB；附件复用文件存储，不在缓存中保存 CDN 密钥。解绑或替换绑定清理映射。局部引用按起止出现次数定位，并在提供 `quotemd5` 时校验；不匹配则标注未验证并保留可用原文，不猜测选区。缓存缺失/过期、文件被删时明确提示。引用附件通过当前绑定的受限文件入口关联，不能用外部文件 ID 访问其他会话。

没有转写的微信语音先下载解密，再由 `internal/voicecodec` 的内嵌 SILK WebAssembly 解码为 24 kHz 单声道 WAV。客体没有宿主函数导入，内存最多 32 MiB、执行最多 5 秒、压缩输入最多 4 MiB、解码输出最多两分钟；Runtime 保持纯 Go 静态构建。失败时保留原始 SILK 附件，并提示模型不能猜测未读取内容。已有微信转写优先使用文字，不重复下载。后续仍使用现有附件读取及音频模型能力、定价检查，不自动调用外部转录服务。来源、构建方式及许可证见 [语音解码器](../../runtime/internal/voicecodec/README.md)。

## 已有绑定识别

当前目标助理处于已连接状态时，登录接口直接返回 `already_connected`，不创建二维码。其他情况下获取二维码只携带该账号、该目标助理已有的令牌，不暴露其他账号或助理的绑定。收到 `binded_redirect` 后，必须匹配发起扫码时的绑定代际及服务端已提供的身份字段，再通过不消费消息的 `getconfig` 校验现有凭据；确认后保持绑定 ID、游标、回复上下文及待发送队列。缺少匹配绑定仍为冲突，凭据无效不报告成功。取消、解绑或权限撤销后迟到的结果不能恢复连接。
