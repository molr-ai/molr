# 上下文存储

`internal/contextstore` 为 Agent 和开发工作台提供共享、不可变的消息前缀树与文档存储。它使用现有 SQLite 事务，不向 HTTP 客户端提供按内容哈希读取或任意挂接引用的接口。

## 内容身份与复用

每个消息节点包含一条完整消息及父节点标识。根使用固定的全零标识，不占用数据库对象。节点标识为完整 SHA-256：

```text
SHA256("molr.context-node:v1\0" + parent_id_bytes + canonical_message_json)
```

父节点使用 32 字节二进制，消息为确定性 JSON 编码：对象键排序，数字不经过浮点转换，字符串内容、字段是否存在、空列表与 null 保持区别。角色、工具调用及关联、附件引用和供应商状态都参与身份计算；不会裁剪正文空白。哈希相同即视为相同内容，不逐字节读取旧内容比较，也不使用截短哈希或冲突桶。

`Intern` 计算候选前缀标识，先检查末尾节点是否存在；未命中时二分查找最长已存在前缀，只插入剩余消息。父节点和子节点同时存在的事务不变量保证存在性单调。`Append` 支持从已知父节点直接追加消息。两者都必须在同一写事务内建立持久引用，不能把未引用的新节点作为可跨事务依赖的返回值使用。

消息在相同父节点下才能复用。跨助理和跨账号允许复用完全相同的物理内容，但业务引用分别绑定 `OwnerID`、`AssistantID`、用途和记录 ID。公共读取先验证业务记录的所有者与权限，再由对应引用还原上下文；持有节点标识不授予访问权限，也不会向客户端暴露其他账号的去重命中情况。

## 文档与引用

`context.objects` 保存消息节点、共享内容块和内容寻址文档。文档把 `Inputs`、供应商 `messages` / `input` 中完整的消息数组替换为路径槽位，槽位引用末尾消息节点及消息数量；工具定义和自动上下文状态单独作为内容块复用，其他请求参数和普通详情随文档保存。文档也按内容寻址，完全相同的文档复用一份。实际供应商请求独立保存，不从逻辑上下文事后猜测生成。

`context.references` 保存带账号／助理边界的外部引用，`context.counts` 单独保存对象的入引用数，避免更新计数时重写消息正文。入引用包括文档对消息末尾节点及共享内容块、子节点对父节点，以及业务记录对文档的引用。读取会检查内容哈希和路径长度，发现损坏返回错误；这项校验用于检测存储损坏，不保证检测真实哈希碰撞。

消息链通过持久化层的 `Ancestors` 操作读取，SQLite 使用有深度上限的递归 CTE，在一条 SQL 中返回从尾到根的节点，再在应用层逐节点校验哈希、父链和数量并还原顺序。每条消息链最多 100 万条消息，写入与读取使用相同上限；缺失节点或损坏路径返回错误，不退化成空上下文。引用、文档与共享定义仍独立读取；这里没有进程内读缓存。

引用替换与业务元数据在同一事务内提交；旧引用释放、新引用建立、节点插入和检查点版本检查全部成功后，执行状态才生效。事务失败不能留下可见的半个上下文，也不能提前删除旧的恢复状态。

## Agent 恢复

正式运行时只读取独立存储格式，不自动迁移内嵌旧上下文。旧部署必须停机备份并完成一次性离线转换后才能启动此版本；临时工具与本地升级记录不属于 Runtime 发布物。

当前检查点、模型调用重试输入和做梦执行进度使用各自的持久引用。关闭 `debug.enabled` 不影响这些核心状态的保存。核心上下文无法写入时，Agent 必须停止推进；工具外部操作已发出时继续沿用操作回执与未知结果处理，不能因为保存失败而盲目重发。模型输出没有单独的恢复缓存；未进入检查点的输出允许通过新尝试重新请求，原尝试的费用与未知状态独立保留。

模型首次调用也从已持久化的规范编码快照加载输入和工具定义，保证重试及重启不会因为 JSON 对象键顺序变化而改变请求字节或幂等摘要。请求完成后，输入引用保留到该事件的完成／交接事务；完成、停止和重置释放不再用于恢复的重试引用。做梦进度在批次提交或停止后释放。当前检查点始终保留独立引用。

`agent.handled` 只保存幂等结果元数据，不再复制完整历史检查点。压缩前输入由当前检查点、摘要请求及已采集的工作台记录分别保留，不创建永久的完整上下文归档；这些引用全部释放后，旧分支可回收。压缩失败不会替换当前输入。

## 工作台与回收

工作台先按既有规则脱敏，再把详情写入独立历史引用；运行态原文不会因为工作台脱敏而被修改。不含敏感信息的 JSON 字符串保留原有空白和键顺序，以复用相同消息节点；只有实际脱敏时才重编码字符串。读取最新检查点时先还原，再脱敏输出。`debug.payloads` 只保存采集状态及存储标记，详情正文在共享存储中按需还原。模型完成事件保存包含输出消息的上下文引用，读取详情时提取正文、工具调用和后端状态；列表摘要仍单独存储。原始 HTTP／SSE 响应不进入数据库。历史清理不能删除仍被当前检查点或待恢复操作引用的消息。

工作台保留策略只有账号级执行条数 `MaxRuns`，包含普通执行和做梦轨迹。超过上限时按开始时间、首修订号和 ID 从旧到新删除已完成执行，运行中的执行保留到结束；不以天数或详情总容量拒绝新详情。单条调试详情的采集大小防护仍由 `debug.max_payload_bytes` 控制。

删除历史记录只释放对应引用。Runtime 启动后与后台定期执行孤立回收：每批最多 200 个对象，每批事务有 2 秒期限；一批清满后间隔 1 秒继续，否则每分钟检查。只删除入引用数为零的对象，删除后递减它依赖的父节点或消息节点计数。回收和引用更新共享写事务边界；回收失败回滚并稍后重试，不影响已提交的执行。此机制不保证数据库文件物理缩小，也不提供硬磁盘容量保证。

## 用量统计

个人用量页显示本账号所有业务引用可达的对象集合：遍历文档、消息父节点和共享内容块，在账号内按对象 ID 去重。管理员用量页显示全部已存对象的全局统计，跨账号共享对象只计一次，包括等待后台回收的对象；不随成员筛选变化。每次统计使用同一读取事务，分页读取引用／对象，避免遗漏超过单页的记录。

两处都显示对象 JSON 正文总字节数和唯一消息节点数；不包含索引、引用元数据或 SQLite 空闲空间，不等同于数据库文件磁盘大小。账号范围只含仍被引用的数据，全局范围包含尚未回收的数据，且账号之间可共享，因此不能把账号用量相加作为全局用量。

## 验证

`internal/contextstore` 测试覆盖确定性编码、跨账号物理复用与引用隔离、分支回收、并发引用与回收、事务失败、追加身份、最长前缀二分查找和连续快照的存储增长。Agent 与 Runtime 回归覆盖检查点版本冲突、压缩、重置、工具返回恢复、模型重试与重启、持久化失败阻止模型调用，以及工作台按条数清理后的最新上下文读取。

读取性能可用 `go test ./internal/contextstore -run '^$' -bench BenchmarkContextRead -benchtime=10x -count=3` 复测。基准对比逐条读取与递归读取，包含消息 JSON 解码与内容哈希校验；分别测同连接重复读取及重新打开连接后的首次读取，连接初始化不计时。不会主动清空操作系统文件缓存，因此后者不代表冷磁盘性能，也不是完整 Agent 回合或用量统计接口的耗时。
