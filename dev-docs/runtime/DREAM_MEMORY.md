# 做梦与分层记忆

Dream 自动把经历整理为主题记忆，再维护长期核心认知。正常整理不产生逐条等待用户审批的事实队列；查看来源、编辑、确认、遗忘和撤销作为纠错入口。模型的归纳质量仍需评估，来源校验不等于语义结论已被证明。

## 三层文件模型

| 层 | 内容与位置 | 使用方式 |
| --- | --- | --- |
| 经历 | 原始聊天、任务状态；`/work/.agents/reviews/YYYY-MM-DD/第N批回顾.md` 保存回顾及来源 | 显式追溯；不作为自动事实注入 |
| 主题记忆 | `/work/.agents/memory/**/*.md`，按语义目录和文件名组织事实、条件、偏好与经验 | `file_search` / `file_read` 或 Shell `rg` 按需检索 |
| 核心认知 | `/work/MEMORY.md`，从有效主题提炼的稳定、跨任务有用的认知 | 自动进入后续聊天上下文 |

同一账号共享文件位于 `/global/MEMORY.md` 与 `/global/.agents/memory/`，普通助理只读，由所有者管理。Dream 只写当前助理私有范围。每位助理只有一个 Runtime 本地工作区；远程电脑不存放记忆，也不参与自动上下文发现。

Markdown 是当前记忆正文的事实来源。文件通过账号内 `(Scope, AssistantID, Path)` 定位，没有独立记忆 ID 或 Category；目录是分类。Version 是完整文件字节的 SHA-256。移动后旧引用失效，不猜测新路径。只发现根目录 MEMORY.md 和 `.agents/memory/` 下的 Markdown；拒绝链接、特殊文件、非法 UTF-8、状态及未知 frontmatter。

可选 frontmatter 包含 `state`、`confirmed`、`context`、`evidence`、`dream_id`、`sources`、`dependencies`、时间及人工修订引用。`dependencies` 是生成核心认知所依赖的主题引用与精确版本。文件最多 64 KiB 正文／80 KiB 总量；目录枚举最多 4096 项、16 层，单次正文扫描最多 8 MiB。普通无元数据 Markdown 默认为 active。

SQLite 保存配置、会话、批次、历史输出、决策及文件引用／哈希，不作为可变记忆正文的副本。Runtime 私有 `memory-operations/` 保存操作回执，以及自动更新前的原始文件字节，供精确撤销；这些恢复副本不进入助理上下文，不参与检索。遗忘会清理相关撤销副本。导出保留当前记忆、回顾及遗忘记录，不把私有撤销副本当作当前记忆导出。

记忆列表先枚举有界路径，再按 scope、助理 ID、路径排序，从游标之后读取当前页与一条匹配的后续记录。游标绑定账号与筛选条件，使用逻辑文件位置；前页文件删除不改变后续位置，正文仍以本次请求读取到的文件为准。没有访问到的损坏正文会在后续读取到它时报告错误，目录和路径安全检查仍在枚举阶段执行。列表不会缓存正文或创建数据库镜像。搜索与做梦读取全部分页时，对每个作用域另外累计检查 8 MiB 正文上限；克隆和导出等完整扫描继续沿用原来的总量限制。

## 自动沉淀规则

每批模型请求同时完成两件事：整理经历、维护核心认知。输入包含当批 Sources、选中的 Existing 主题和当前 Core。没有新经历、但存在有效私有主题时仍创建维护批次，允许已有认知跨日沉淀；没有资料也没有有效主题时跳过模型调用。

- 一次明确的长期约定可以立即形成主题并提升到核心；多次临时请求不能仅凭频率变成长期偏好。同一来源的重复引用不是独立佐证。
- 保留适用项目、时间及场景，不将局部约定扩大为全局偏好。区分请求、完成结果和未解决问题。
- 主题使用 `create`、`update`、`retire`。更新需要精确 ExpectedVersion，保留仍有效的事实和来源；retire 将不再适用的自动主题标为 superseded。
- 明确的用户纠正可以自动修订同范围的自动主题；不同场景分别保留条件。无法确定的推断、矛盾放入回顾／deferred 决策，暂不写入长期事实文件，也不生成 pending 确认队列。现有人工 pending / superseded 文件不能当作有效事实。
- `explicit` 需要用户消息或已展示主题的明确来源支持；`verified` 需要完成任务或已展示主题的已验证来源支持。inferred 候选被保留为回顾中的观察。来源类型只是结构检查，模型仍负责语义判断。
- 用户确认、界面编辑、无自动生成来源的文件，以及与生成批次哈希不一致的外部编辑受到保护。Dream 不静默覆盖，也不为这些文件自动建立待确认修订文件。当前用户指令始终优先。

核心更新通过独立的 `Core` 输出字段表达：`ExpectedVersion`、`Text`、`Topics`、`Reason`。Topics 只允许本批可见或本批成功规划的有效私有主题，Runtime 固定其文件版本，并汇集来源。推断、失效主题和另一份摘要不能作为核心的依据。

核心正文上限 6 KiB，提示词要求简洁稳定的认知，不追加流水账。`Core: null` 表示不改动；空 Text 和空 Topics 显式将自动核心降级为 superseded，主题仍保留。核心可以包含有用的主题路径，但不能只有目录索引。当前比较上下文不完整时，不要求模型凭空重建全部认知。

## 比较上下文与使用

Runtime 读取所有分页后再选择比较材料，避免只看到按路径排序的前 200 个文件。优先当前核心的依赖、共享摘要和与证据有词项交集的主题；同分材料按日期轮换，允许安静主题在后续维护中被查看。每批最多 40 个比较文件、32 KiB 序列化材料；当前私有 Core 单独提供。已有内容只是比较资料，不重复计为新证据。

仅两份根目录 MEMORY.md 及账号回答偏好自动进入普通上下文，每份摘要最多 8 KiB；超过时提示主动读取。Dream 生成的核心在每次加载时核验依赖版本；支持主题被修改、移动、删除或失效后，使用失效提示替换旧核心内容，不继续注入旧结论。显式遗忘主题还会移除相关的自动核心文件。用户通过记忆接口手动保存核心后清除自动依赖，转为受保护的人工作品。

详细主题和回顾不隐式召回；`memory_search`、`memory_read`、`memory_write` 不注册。通用文件工具不会过滤状态，模型必须读取状态、来源及条件。最近最多 64 个读取／搜索过的记忆或回顾路径会核验版本；变更、删除或失去权限后使旧工具片段失效。记忆不能授予权限或覆盖当前用户要求。

## 触发、队列与容量

每位助理默认每天配置时区 03:00 开始，最长 600 秒，可设置 1–3600 秒。初始时区来自用户设置，之后独立配置。手动整理也只收集前一个完整自然日。

做梦与计划共用 `internal/trigger` 的 RRULE、IANA 时区及发生点去重；业务适配器独立保存配置、游标和会话，产生 `dream_due`，不生成 Plan／Task。做梦采用 Coalesce，离线恢复只考虑最近窗口，窗口过期记录 missed_window，不补跑全部历史日期。

Session 冻结资料范围、时区与截止时间；Run 是独立上下文的批次。开始前不抢占普通任务；开始后跨批次独占该助理队列，消息和计划等待，消息保持未读，加急被拒绝。其他助理正常工作。用户停止只结束做梦，保留普通队列。重启、重试不延长原截止时间，失败会话仅在原截止前允许手动重试一次。

每批最多 80 项来源、96 KiB 证据、8 项主题变更和 1 项核心变更。一天最多选择 320 项／384 KiB 新资料，再处理最多 80 项／96 KiB 遗留资料。未完成的新资料最多保留一批，仅下一个自然日补一次；旧积压不继续滚动。容量限制可能遗漏资料，扫描游标前进不等于所有来源已整理。

来源为原始聊天文本、卡片摘要及当天最后更新的任务状态和结果引用，不自动读取附件正文、外部资源或重放工具。可识别的凭证内容整条排除，提示词禁止敏感推断。任务记录在准备及提交时重新核验；来源变化可能导致批次冲突。

每批一个逻辑模型调用、无工具；供应商错误重试复用普通机制。输出 token 上限沿用模型配置和剩余上下文上限；结构化结果另有 64 KiB 字节上限。费用计入助理预算。已保存提交计划的重试直接复用原输出，不重新调用模型生成不同计划。

## 提交与恢复

Agent 在最终状态事务之外调用 Dream 文件提交：先独立持久化输出、目标引用及哈希，再逐文件原子替换，最后用数据库事务提交批次完成与下一批事件。文件 I/O 不处于数据库事务内，失败不能回滚已写文件，也不会丢掉此前独立提交的计划。

提交前检查来源、比较版本、权限、遗忘规则和截止时间。更新前将原文件字节保存在私有恢复目录。`committing` 表示正在保存文件；重试核对已开始文件的目标哈希，相同则跳过，缺失或被编辑则保留现场并报告冲突。外部进程不参与 Runtime 锁，文件版本检查不构成任意进程间全局 CAS。

截止时间约束模型、逐文件写入和最终进度事务。到期释放队列，已写文件保留，迟到结果不能继续写入。远端供应商是否停止计算取决于其取消支持。普通聊天 checkpoint 不被 Dream 覆盖。

## 纠错与撤销

遗忘先记录正文摘要哈希与来源引用，再删除当前文件，阻止同正文或来源再次提炼；同时删除相关自动核心、生成回顾和撤销恢复副本，清空相关数据库历史回顾／候选／输出。原聊天和历史调试记录由各自数据管理流程负责。按来源保守抑制可能阻止从同一长消息提炼其他事实。

普通删除和 Shell 删除不记录遗忘规则。撤销按批次操作：新建且未改变的自动文件删除；自动更新的主题和核心按私有快照恢复原字节；后续编辑、确认、遗忘和删除受保护，不盲目恢复。未修改的回顾一起删除，改过的回顾保留。被撤销批次仍视为已处理。

界面为“用户设置 → 记忆”：核心入口、主题目录、做梦配置与批次记录。“选择助理”只列在职助理及全局共享范围；做梦区域直接使用上方选中的助理，不再提供第二个选择器，全局共享范围下隐藏。切换助理时重置做梦表单和操作反馈，避免沿用上一位助理的状态。开发工作台展示核心更新、自动修订、已停止使用、留在回顾中的观察和丢弃项，并链接实际记忆文件。自动整理无需逐条确认，手动保存会保护文件。

计划页页脚显示只读预留窗口，不计入计划数量；创建、编辑和详情提示安排冲突但允许保存。调试轨迹用 `dream.batch_committed` 表示梦境批次，不误报普通 checkpoint。开发期 Dream 调试记录不参与普通自动保留清理；不要把协议测试视为真实模型归纳质量评估。

## 接口与验证

配置、立即整理、历史、窗口、冲突和撤销入口分别为 `/api/dreams/config`、`/run`、`/api/dreams`、`/windows`、`/conflicts`、`/undo`；`/api/dreams/runs/{id}` 返回单批及 Session 状态。历史最多 60 个批次，不返回来源快照原文和原始模型输出。Memory 接口使用 Scope、AssistantID、Path、Version；具体请求见 [HTTP API](HTTP_API.md)。

行为测试包括核心提升／降级、安静日维护、明确纠正无 pending 队列、推断不得提升、超过首分页的比较、比较文件变化、核心失效、遗忘恢复副本、撤销保护和 Agent 外层失败保留提交计划。应用协议测试覆盖 Dream 形成核心后自动进入后续聊天，并继续通过普通文件工具检索主题。调度、时限和来源隔离测试继续适用。
