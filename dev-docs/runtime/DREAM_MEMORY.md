# 做梦与记忆使用

每位助理默认在配置时区的 03:00 整理前一个完整自然日。初始时区来自用户设置，之后可单独修改。用户设置 → 记忆按助理／全局范围浏览目录和 Markdown 文件，支持新建目录、创建文件、编辑、重命名／移动、删除、来源查看、确认与遗忘；选中助理后提供做梦设置、立即整理／重试及撤销整理。

## 文件是唯一事实来源

所有助理位于 Runtime 本地，每个助理只有一个持久工作区，没有 project 存储层级。远程沙盒是显式选择的远程电脑，不持有助理工作区、记忆或自动上下文来源。

| 范围 | 沙盒路径 | Runtime 路径 |
| --- | --- | --- |
| 助理摘要 | `/work/MEMORY.md` | `AssistantWorkspace(DataDir, WorkRoot, owner, assistant)/MEMORY.md` |
| 助理详细记忆 | `/work/.agents/memory/**/*.md` | 同一工作区下 `.agents/memory/` |
| 同一账号共享摘要／记忆 | `/global/MEMORY.md`、`/global/.agents/memory/**/*.md` | `DataDir/users/sha256(owner)/global/` |

`/global` 按账号隔离，普通本地 Shell 只读挂载；文件工具只允许读取。所有者通过记忆 API／界面修改共享记忆。显式 Full Access 使用真实宿主路径，本地命令提供 `$MOLR_WORKSPACE`、`$MOLR_GLOBAL`，其权限仍由 Full Access 授权决定。

普通 Markdown 即可被发现；可选 YAML frontmatter 描述 `state`、`context`、`confirmed`、`evidence`、`dream_id`、`replaces`、`replaces_version`、`sources`、`created_at`、`updated_at`。未知字段、非法状态、非 UTF-8、链接和特殊文件被拒绝，不作为完整扫描返回。没有记忆专用 ID。认证账号内 `(Scope, AssistantID, Path)` 唯一定位一个文件，Scope 为 `assistant` 或 `global`；全局引用不带 AssistantID，Path 相对于 `/work` 或 `/global`。重命名或移动后旧路径失效；`Version` 是完整文件字节的 SHA-256 字符串，直接编辑后重新读取即可发现变化。文件元数据是参考数据，不能授予权限。

每个文件最多 64 KiB 正文、80 KiB 含元数据；单次账号扫描最多 4096 项、16 层目录、8 MiB 正文。只发现根目录 `MEMORY.md` 和 `.agents/memory/` 下 Markdown，不按项目目录分组，也不扫描远程电脑。仅两份根目录摘要自动进入上下文，每份最多 8 KiB，超出时仅注入提示要求主动读取；详细记忆不再按关键词隐式召回；Shell 可直接运行 `rg` 检索相同文件。

API、界面和 Dream 创建时必须提供语义路径，例如 `.agents/memory/用户偏好/沟通偏好.md`。目录就是分类，不再保存 Category 枚举。一份文件围绕一个稳定主题，可以包含多条相关事实。Runtime 校验规范相对路径、UTF-8、隐藏控制目录和长度；语义由创建者表达，不用规则猜测标题。不存在自动哈希、ID、随机后缀或无意义时间戳命名。同名创建返回冲突，不隐式覆盖；重试复用原路径。修改正文不会自动改名，跨范围移动不作为一次原子操作提供。

数据库不再保存可变的记忆正文、记忆副本、遗忘规则或记忆搜索索引。`internal/business/memory` 负责文件存储与业务边界，`internal/textfiles` 提供无业务依赖的固定描述符读写原语；SQLite 继续保存任务、审计、Dream 历史与文件引用／哈希。操作回执和克隆清单保存在 Runtime 私有 `memory-operations/` 文件中，只含摘要、引用和提交状态，不保存记忆正文。没有旧数据库记忆迁移或兼容读取。

写入使用同目录临时文件、同步和原子重命名；删除核对文件版本。提交前重新检查执行权限与截止时间。文件工具、记忆接口、Shell 和编辑器访问同一份文件，但外部进程不参与 Runtime 锁；版本检查不构成任意进程间的全局 CAS。

克隆复制授权范围内的 Markdown 和记忆遗忘记录，先固定文件引用／哈希清单，复制成功才初始化新 Loop。重试不覆盖目标修改或重建已删除目标。导出 ZIP 中 `memory/global/`、`memory/assistants/<id>/` 保存当前 Markdown、回顾文件和遗忘 JSON，每个文件单独检查变更，不宣称跨文件快照事务。全局搜索实时读取授权文件；重建索引不会保存记忆正文。设置清理先固定授权文件版本，再逐文件遗忘；重试不扩大删除范围。

## 通用定时触发层

用户计划与做梦共用 `internal/trigger`。通用层只负责 Rule 校验、RFC 5545 重复规则、IANA 时区、下次发生点、Skip／Coalesce／CatchUp 漏执行策略、有限计算和发生点去重；不依赖业务、Agent、IM、HTTP 或具体数据库，也不创建计划、任务或消息。计划日历投影同样使用此处的规则计算。

- 计划适配器保留现有 Schedule／Plan／Task 业务记录、依赖检查和交付规则。
- 做梦适配器保存独立配置、定时游标和回放进度，生成 `dream_due`。
- 两者按所有者、类型、标识、规则版本和 UTC 发生时间写入 `trigger.occurrences`，与对应业务效果和游标同事务提交。旧 `business.occurrences` 保留兼容读取，升级后不重复投递既有计划发生点。

做梦使用 `Coalesce`，离线恢复只考虑最近一次预留窗口，错过窗口直接记录 `missed_window`，不会补跑所有历史日期。配置变化不改变已开始会话的资料范围和截止时间。

## 执行与时限

默认每天配置时区 03:00 开始，最长 600 秒；可设置 1–3600 秒。Session 冻结前一个完整自然日的来源快照、时区和截止时间；多个 Run 批次共享同一截止时间，重启、重试均不延长。普通任务正忙时不抢占，只使用预留窗口剩余时间；窗口已结束则跳过。

一旦开始，会话跨批次独占该助理的调度队列。普通消息、定时消息、计划及其他事件排队；UI 隐藏加急，后端拒绝加急，过期的加急请求也不能取消新开始的做梦。同一助理此时不会处理普通事件，不同助理可继续工作。消息保持“已发送／未读”，实际处理后才是“已读”，不新增“已收到”状态。状态展示为 `dreaming`／“正在做梦”。用户主动停止只取消做梦，保留普通队列。

每批最多 80 个来源、96 KiB 证据、16 KiB 比较记忆，一次模型请求、无工具，最多 4096 输出 tokens、8 条候选。当天最多选择 320 条新资料／384 KiB，之后最多处理 80 条／96 KiB 的上次遗留资料，优先新资料。超时、取消或容量不足时，新资料剩余部分至多保留一批，且只允许下一个自然日补处理一次；旧积压不再次滚入后续日期。扫描游标前进不代表所有资料已成功整理，Session 记录未处理数及结束原因。失败会话只允许截止前手动重试一次。

截止时间同时约束模型请求、每个文件的原子提交与最终进度提交。到期取消运行上下文、结束会话并释放队列；已经提交的记忆文件保留，迟到结果不能继续写入文件。远端供应商是否真正停止计算取决于其取消支持，不能据此声称不会产生远端费用。

来源为当前助理的原始聊天文本、卡片摘要，以及当天最后更新的任务状态和结果引用。不自动读取附件正文或外部资源，也不重放历史工具调用。任务资料采用当前可核验的状态记录。可识别的凭证内容整条排除，提示词也禁止保留凭证和敏感推断。

模型结果必须符合固定结构。Runtime 校验来源快照、原始内容及版本、权限、遗忘规则；先保存历史输出和计划文件引用／哈希，再逐文件写入，最后以数据库事务保存完成标记和下一批事件。文件写入不嵌套于数据库事务。`committing` 表示正在保存文件；中断时已写文件保留。重试核对既有文件哈希，相同则跳过；已开始但缺失、被编辑的文件报告冲突，保守保留现场，绝不盲目覆盖或重建。各批上下文独立，通过 Session 串联；普通聊天 checkpoint 不被覆盖。复用模型权限、预算预留、费用回执和恢复机制。

## 可见性与保留

计划页在页脚独立入口中显示只读的做梦预留时段，日期格子不显示做梦标记或背景，不生成 Plan／Task、不计入普通计划数量，不能在计划页修改。创建或编辑同一助理的自动计划时，使用项目 Alert 显示冲突，仍允许保存；计划详情检查选中的一次安排，尚未结束的计划执行详情也显示提示。重复计划从当前时间与系列起点中的较晚者开始检查 90 天，保留原始 DTSTART、COUNT 和 UNTIL，避免较早创建的系列编辑时漏报；一次性安排按自身时间检查。页脚展开箭头向上，数量明确标为“个时段”，指所选日期及负责人筛选范围内的窗口条数，每位助理每天可配置一个自动时段。手动做梦显示实际预留区间。

开发工作台显示 `dream_due` 来源、Session、批次、证据范围、截止时间、候选处理决策、记忆链接和结束原因；梦境使用 `dream.batch_committed`，不误报普通聊天 checkpoint 保存。开发期间做梦调试记录不参与普通调试记录的自动数量／容量／时间清理，原始输入及输出保留；显式遗忘仍清除关联回顾、候选和保存的输出，原始聊天与历史调试记录由各自的数据管理流程负责。

## 主题与确认

- 用 `用户偏好/沟通偏好.md`、`工作约定/发布前检查.md` 等目录和文件名组织主题；没有 project 实体或固定分类枚举。
- `active`：有效；`pending`：待确认；`superseded`：已替代。没有 frontmatter 的普通 Markdown 默认为有效。
- `explicit` 候选需引用实际用户消息；`verified` 需引用完成状态的任务；`inferred` 始终待确认。来源类型检查不能替代对模型归纳准确性的人工判断。
- 内容完全相同的候选去重，语义去重和适用条件由模型对照提示负责。对旧记忆的修订先作为待确认项保存，用户先将旧文件标为已替代，再激活候选，并携带重新读取的旧文件哈希；两个文件分别提交，不伪装为一次跨文件原子替代。并发修订产生冲突，不静默覆盖。
- 自动形成的记忆只写入当前助理私有范围。用户手动管理共享记忆；助理读取继续受现有所有者及助理范围限制。

## 使用与文件检索

1. 两份 MEMORY.md 摘要和用户回答偏好自动进入上下文；详细文件不隐式召回，没有单独置顶字段。
2. 先在相关分类目录调用 `file_search`，用 `file_read` 阅读完整内容、状态、适用条件和来源；必要时扩大到私有记忆根目录，再搜索全局目录。有计算授权时可用 `rg` 访问相同文件。
3. `memory_search`、`memory_read`、`memory_write` 均不注册、不保留别名。通用文件搜索不解析记忆语义、不替模型过滤 pending/superseded；系统提示词明确这些状态不能当作当前事实。
4. Dream 回顾是独立 Markdown，保存于 `/work/.agents/reviews/YYYY-MM-DD/第N批回顾.md`，可以显式检索。日期与批次具有内容含义，不使用运行 ID 命名。正文包含当批回顾和来源引用，不参与长期记忆自动注入。

最近最多 64 个已读／已搜索的记忆及回顾文件路径会在后续上下文中核对文件版本。变更、删除或失去访问权时提供失效标记，不继续复用旧工具片段。更早的引用使用前必须重新读取；系统不猜测改名后的新位置。记忆是参考数据，不能授予权限或覆盖当前用户要求。

Dream 输出包含 `Action: create|update`、语义 `Path`、`Text`、`Context`、`Evidence`、`Sources`。更新只允许未确认文件，必须提供当前 `ExpectedVersion`；不确定内容不能直接覆盖有效文件。确认内容或冲突项必须创建另一个语义路径的待确认建议，用 `Replaces: {Scope, AssistantID, Path}` 引用原文件。后台不替模型生成文件名。

## 遗忘与撤销

遗忘先在同一范围 `.agents/memory/.forgotten/` 写入仅含正文摘要哈希和来源引用的 JSON，再删除当前文件，阻止同一正文及相同来源的再提炼；关联的生成回顾文件删除，数据库中的相关历史回顾清空。原始聊天和历史调试记录继续由各自的数据管理流程负责。首版按来源保守抑制，可能同时阻止从同一条长消息重新提取其他事实。

界面的普通删除以及直接用 Shell／编辑器删除 Markdown 仅移除当前记忆，不等同于遗忘，也不会写抑制记录。

撤销完成的整理只删除本批新建、哈希仍匹配且未被用户确认的自动记忆；更新已有文件的结果保留，不通过历史正文回滚覆盖。未修改的本批回顾文件同时删除，已改动的回顾保留；后续用户编辑和确认被保留。回顾清空，该批次保持已处理。设置导出包含记忆、做梦配置、定时游标、回顾和遗忘规则。

## 接口

- `GET /api/dreams/config?assistant_id=…`
- `POST /api/dreams/config`：Mutation、AssistantID、Enabled、Hour、Minute、Timezone、MaxDurationSeconds。
- `POST /api/dreams/run`：Mutation、AssistantID。整理已结束的日期，不提前整理今天。
- `GET /api/dreams?assistant_id=…`：最近 60 个批次，来源仅返回引用与时间，不返回快照原文。
- `GET /api/dreams/runs/{id}`：单批次及所属会话状态。
- `GET /api/dreams/windows?from=…&to=…&assistant_id=…`：只读预留时间，最多 125 天。
- `GET /api/dreams/conflicts?assistant_id=…&start_at=…&timezone=…&recurrence=…`：未来 90 天的重复计划冲突。
- `POST /api/dreams/undo`：Mutation、ID。
- `GET /api/memories/file?scope=assistant&assistant_id=…&path=…`：读取明确文件引用；旧 ID 路由不存在。
- `GET /api/memories/directory?scope=…&assistant_id=…&path=.agents/memory`：当前目录及直接子项，目录版本用于移动／删除。
- `POST /api/memories`、`/update`、`/delete`：请求包含 `Scope`、`AssistantID`、`Path`；创建必须明确路径。删除默认普通删除，显式 `Forget: true` 才保存遗忘记录。
- `POST /api/memories/mkdir`、`/move`、`/rmdir`：目录创建、同范围重命名／移动、空目录删除；移动还需 `ToPath`、`Directory`。目标不覆盖；根摘要与记忆根目录位置固定。
- `Version`、`Mutation.ExpectedVersion` 用于版本检查；文件使用完整内容 SHA-256，目录使用文件系统版本。没有 ID、Category、Pinned 字段。`Replaces` 是文件引用。
- 设置清理用 `memory_files` 数组传明确文件引用，不接受 memory ObjectIDs；审计保存结构化文件范围与路径。

## 验证

定时层测试覆盖三种漏执行策略、COUNT 游标、夏令时墙上时间、跨重启恢复、不同业务类型去重隔离、并发发生点登记及事务回滚；业务适配测试覆盖旧计划记录兼容、离线过期窗口跳过、资料上界、修改时区保留已开始窗口，以及不生成计划／任务记录。

行为测试覆盖形成／召回／遗忘闭环、非法来源、推断隔离、83 条记录分批、跨批次队列独占、整个会话共享时限、迟到提交拒绝、已提交批次保留、单次有界积压、消息未读与加急拒绝、手动停止保留排队消息、并发用户修订、来源删除、时区调度、失败重试、敏感凭证排除、撤销保护，以及真实模型协议下的摘要注入、通用文件搜索和文件读取。模型协议测试使用确定性外部服务，不代表真实模型的归纳质量已经评估。
