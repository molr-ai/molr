# 多用户、共享资源目录与成员配额

更新：2026-10-03。用户操作见[用户与用户组](../../docs/administration/users-and-groups.md)。本次范围是独立账号及用户组授权，没有空间、群聊或用户间数据共享。

沙盒引用增加 `AllowFullAccess`（默认 false）。只有管理员明确勾选「允许授予 Full Access」，组成员才可为自己的助理授予对应节点的 Full Access 计算权限；仅引用沙盒不足以提权。Full Access 调用不受组资源配额限制，普通调用继续使用组配额；撤回该选项会在后续授权检查和运行任务检查中生效。Full Access 直接继承系统账号访问范围，多用户部署应据此决定是否委派。

## 身份与目录

`auth.accounts` 按账号 ID 存储，登录按唯一用户名查找。`auth.bootstrap/owner` 只标识最初账号及稳定资源目录命名空间，不代表当前请求用户。服务只接受按账号 ID 存储的格式；构造认证服务仅校验数据，不执行转换，也不回退读取旧单例。

内置 `administrators` 是唯一管理员组：全部资源、无组额度，禁止编辑资源列表及删除。`users` 为无资源的初始普通组。账号只有一个用户组。组成员变更或停用撤销会话、访问令牌及登录链接；最后一个未停用管理员不可被停用或降级。所有管理 API 在服务端重新验证当前管理员身份。用户列表的每页授权、账号与组信息共用一个读取事务；同组用户复用本页已经读取的组配置，后续请求重新读取，及时反映组名和权限标记的变化。

## 私有数据与资源目录

助理、会话、消息、附件、计划、记忆、授权、预算、审计、上下文、工作区和个人设置继续使用请求身份的 OwnerID。管理员身份不会绕过这些对象的所有权检查。统计只输出用户标识、组、模型／工具／HTTP 连接调用数、占用与待核实数量、币种金额及附件总量，不包含详细业务内容。

仅资源、连接绑定、资源凭证、沙盒连接和插件安装记录使用 `persistence.CatalogOwner` 解析全局命名空间。原目录前缀和加密 AAD 保持不变。私有工作区仍由用户 ID 与助理 ID 共同确定，不能使用目录所有者替代运行身份。

管理资源／凭证／沙盒以及插件安装、全局启停需要管理员；普通用户的资源描述与模型列表按组引用过滤。模型目录收集在同一读取事务内加载资源绑定与一次用户组快照，按模型 ID 集合筛选；快照仅用于当前请求，后续请求重新读取权限，返回列表仍经过逐项模型授权。插件对普通用户只呈现管理员全局启用且用户组有 `plugin` 引用的安装项，不暴露其他用户助理绑定或管理员设置声明。个人启停独立保存；页面、主题、设置及工具调用都检查插件组权限和个人启用。助理能力还受工具引用与自身计算授权约束；HTTP 工具另检查 connection 引用，不要求计算资源。可选个人设置按真实用户隔离，共享管理员配置仅管理员可读写，详见[插件机制](../extensions/plugins.md)。

## 双层配额

用户组只保存 `Kind + ID + Quota`，不保存 endpoint、secret、manifest 或沙盒连接定义。模型引用具体 ModelID，工具引用工具名，沙盒引用连接 ID。

检查顺序在各执行路径中保持“当前身份与组资源范围 → 原助理授权与额度 → 成员累计额度”的合取约束。管理员跳过组约束，仍经过原助理约束。用户组配额按 OwnerID 与稳定资源 ID 累计，换组、删后重加引用、重建 Grant 不会生成新余额。

- 模型：组级检查和原助理费用 Reserve 同一个写事务，按 ModelID 汇总所有助理的已结算费用及执行中的预留费用；多币种按现有汇率模块换算。本地调用退出即结束预留与并发占用；unknown 保留未知费用但不占额度，后续可信回执仍可结算。
- 工具：在工具操作进入 Running 的同一个事务里计量，按用户＋工具名限制调用次数及并发。被拒绝的请求不启动外部操作。只有 Running 计入工具并发；unknown 保留历史调用次数与副作用信息，按原周期统计。
- 计算：Linux cgroup 层级 `account-<owner hash>/quota-<owner+assistant hash>/molr-<execution>`，账号父级限制聚合 CPU、内存、进程数，助理层继续生效。时长与临时内存取两层较小值；执行任务管理器额外限制每位成员在该沙盒的并发数。
- 网络：`quota.Ledger.ReserveMany/SettleMany` 在执行端同一 SQLite 事务中处理助理与账号两份账本；提交失败整体回滚，已有预留保持占用。`ClaimMany` 继续用内存槽位控制连接并发。账号键为 `owner/group/sandbox`，不包含易变的组 ID。变更日历周期时将重叠旧周期已用量保守搬入新周期，挂起预留保留结算令牌。
- 存储：依赖现有沙盒硬配额，将同一账号所有助理获授权的工作区容量与文件数之和约束在组额度内。撤权后保留基准容量，显式缩减才释放预留，避免通过撤权重建助理绕过限制。

远程协议以 `Info.UserGroupQuotas` 宣告支持，新 Request 携带组级计算及网络约束；需要这些约束而服务端未宣告支持时拒绝执行。组授权收回和在途授权刷新仍使用现有取消／检查机制。

未分配沙盒或 `permission_list` 工具时，自动上下文跳过相关可选来源，普通聊天仍可运行。普通用户不开放无身份验证的公开端口转发，以免该通道暴露账号工作区内服务。

账号头像随 `auth.accounts` 保存，使用与助理相同的 `internal/avatar` 缩略图校验。个人资料更新只针对当前会话所属账号，显示名称和头像使用同一次版本校验原子保存；认证快照与个人资料读取均返回已保存头像。

## 前端身份与设置

`/account/*` 为个人设置，`/settings/*` 为管理员设置。底部头像与齿轮分别导航；普通用户无齿轮和资源配置入口，手工进入管理员路由也显示拒绝，API 独立拒绝越权。旧个人设置登录链接会映射到 `/account/*`。

账号切换通过按 origin 隔离的 BroadcastChannel 通知；窗口恢复和周期刷新补充检查。DataProvider 按 SessionID 重建，清除旧账号快照，草稿仍按 OwnerID 隔离。SDK 忽略属于旧 CSRF 身份的迟到 401，避免旧请求清除新登录。

## 验证范围

测试覆盖账号认证与会话撤销、管理员保护、跨账号数据隔离、组资源范围及双层额度。真实隔离测试还需检查账号父 cgroup 和助理子级限制。测试覆盖不等于完整安全证明，实际部署仍需进行认证与隔离能力检查。

普通成员可以审批／拒绝自己助理的授权请求，审批入口检查私有请求归属，实际授权继续经过组资源引用和两层限额校验；管理员也不能代为读取或审批其他成员的私有请求。`TestMemberCanResolveOwnPermissionRequestsWithinGroup` 覆盖这些边界。
