# 主题与 UI 包

## 产品交互

用户设置 → 主题只有一个「主题」选择器，内置选项为：

- Molr 默认主题
- Molr 测试主题

「主题、显示模式、减少动态效果」放在同一组，「主题配色」作为最后一组。显示模式仍提供跟随系统、浅色和深色。主题配色提供森林、海盐蓝、鸢尾紫、暖砂、玫瑰和素墨；素墨覆盖界面基础色与 SVG 品牌资源，状态、分类和代码语法继续使用共享语义色。设置列表只允许操作控件本身，点击标题或行空白不再展开选择器或切换开关；键盘操作和无障碍名称保留。

用户选择一个完整主题。**替换哪些页面由主题清单决定，用户不能逐页组合。** 测试主题只替换聊天页，把助理列表改为顶部选择器；其余页面自动使用默认主题。聊天业务、消息、附件与草稿继续共用。

不提供独立主题管理页面或逐页选择器。外部主题由管理员通过“插件”页面导入、授权和启用，随后出现在主题选择器；插件版本和安装统一由插件管理。个人主题页地址为 `/#/account/theme`；`/#/settings/*` 用于管理员设置。

移动端底部导航只保留业务页面，采用带阴影的圆角矩形悬浮样式，选中项展开文字，其余项仅显示图标，切换动画遵循减少动态效果设置；菜单覆盖在铺满视口的内容上方；各页面滚动内容末尾预留菜单高度、上下间距和设备底部安全区，滚动到底后最后一项完整露出。移动端计划与工作台的状态栏随内容滚动；计划清单空状态填充可用高度，日历保持完整网格高度，状态栏位于内容末尾和菜单退避留白之间；隔离插件 iframe 则缩短自身视口以避免内容被遮挡。进入聊天详情时菜单向下渐隐，返回助理列表时向上渐显；退出开始即停止菜单交互，快速返回可从当前进度反向过渡，系统或账号开启减少动态效果时直接切换。两种内置主题均提供聊天返回按钮。移动端聊天面板打开和返回列表时使用原地透明度过渡，退出完成后卸载；退出期间不可交互，减少动态效果时直接切换，桌面聊天不使用该动画。移动端聘请新助理入口位于搜索按钮右侧，使用仅图标的 ghost 按钮，桌面保留列表底部入口。

默认主题在原 Logo 位置显示用户头像和用户名，测试主题的助理选择器上方复用相同入口，点击进入用户设置。管理员入口收纳到用户设置，普通成员不显示；管理员页头可返回用户设置。用户设置最后一栏「关于」展示 WebUI 和 Runtime 的版本、commit、一致性状态，以及推荐发布版本和 GitHub Star 入口。关于页顶部将 Logo 与当前版本并排展示，更新状态和操作前置，版本号与 commit 对齐展示，GitHub 入口收于页尾；手机端保持同样的信息顺序，升级指引按需展开。登录后宿主层共享更新状态，每五分钟和恢复可见／连接时读取；关于页激活时按服务端冷却策略检查发布源。前后端不一致对所有成员显示入口标记，新发布版本仅对管理员显示入口标记；管理员可查看按安装记录生成的固定版本升级指引。不会自动刷新页面或安装更新；完整 Logo 使用 `animation="daily"` 和交互模式，按设备本地时间切换昼夜循环并沿用减少动态效果偏好。个人资料复用已有头像选择器和缩略图处理；桌面侧栏、手机顶部和管理员用户列表均显示账号保存的头像。

## 实现边界

- `packages/sdk` / `@molr/sdk`：Runtime 客户端、DTO、分页、幂等写入、上传下载、错误、SSE 和 UI/Host 协议，不依赖 React 或 `@molr/ui`。
- `packages/ui-host` / `@molr/ui-host`：清单校验、固定版本主题身份、主题拥有的页面映射、原型隔离适配器的权限策略及插件主题类型。
- `apps/webui/src/App.tsx`：登录、导航、主题解析与页面加载、故障恢复。
- `apps/webui/src/ui-host/ThemeSelector.tsx`：主题设置中的主题选择器。
- `apps/webui/src/interfaces/official`：默认主题和原有产品组件。
- `apps/webui/src/interfaces/test`：仅声明聊天页的测试主题。

`@molr/ui` 继续作为稳定的官方组件底层。未来不兼容的组件可以新增版本导出；组件、CSS 变量和资源都需要保持已有版本的兼容性。

侧栏等位置的共享 Tooltip 在窗口失焦或页面隐藏时关闭并清除延迟计时；切回页面恢复焦点不触发提示，后续键盘导航或鼠标移动悬停仍正常显示。此行为由共享组件处理，宿主无需清除按钮焦点。 Tooltip 共同使用一组窗口活动监听；键盘与指针按下只推进输入版本，关闭中的实例不会逐个执行输入回调。最后一个实例卸载时移除共享监听。

## 主题选择与页面解析

账号设置只保存一个主题身份，不保存用户自定义的页面映射。Runtime 的 `Settings.UITheme` 使用 `id@version`，前端解析为：

```json
{
  "schema": 2,
  "selected": { "id": "molr.test", "version": "1.0.0" }
}
```

主题本身声明页面实现：

```ts
const testTheme = {
  runtime: 'builtin',
  manifest: {
    id: 'molr.test', name: 'Molr 测试主题', version: '1.0.0', apiVersion: 1,
    pages: { assistants: 'test-chat' },
    permissions: ['chat.read', 'chat.write', 'files.read', 'files.write'],
  },
};
```

解析时先查选中主题的 `pages[page]`，未声明时使用 `molr.official@1.0.0` 的对应页面。内置主题和已授权的插件主题遵循同一条规则；部分主题无需实现全套页面。

目录保留两个内置主题，并加入 Runtime 返回的已启用、已授权插件主题。浏览器中的 `installed`、`routes` 等旧字段不参与解析，未知主题身份回退默认主题。上一版逐页配置原型的数据不会重新启用。

主题选择、主题配色与显示偏好统一保存在 Runtime 的账号设置中，在设备间同步。新设备登录时读取已保存的选择；已打开设备沿用设置快照刷新，在页面重新可见或周期刷新时更新。主题选择不依赖 localStorage；保存失败保留原选择，主题不可用时使用默认主题。写入采用设置版本校验，只合并主题字段；旧客户端省略 `UITheme` 时保留已保存值。主题切换后的聊天草稿继续保留。

## 共享状态与恢复

主题切换不影响 Runtime 中的助理、消息和任务。聊天草稿以 `{ text, files }` 格式按账号和助理 ID 存储于管理壳的内存和当前标签页 `sessionStorage`，默认主题与测试主题使用同一份草稿。其他临时页面状态由各页面管理。

默认主题和测试主题的当前助理均由路由 ID 决定；`/#/assistants` 保持未选择状态，不回退到首个助理。列表或选择器操作通过导航更新 URL，再打开对应会话。

页面加载失败时保留壳的导航，并提供恢复默认主题与主题设置入口。恢复默认主题会先更新账号设置，成功后重新载入应用，清除浏览器缓存的模块加载错误；Runtime 暂时不可用或保存失败时，保留当前会话内的默认主题恢复，不刷新页面。正常 API 错误由业务页面处理。

## 后续扩展预留

SDK 中的 `connectUI()`、独立页面清单和隔离 iframe 适配器保留为后续开发基础，产品外部页面使用 [插件机制](../runtime/PLUGINS.md) 的独立、较窄契约；早期通用 iframe HTTP 代理不作为插件接入入口。

插件主题可以使用或不使用 `@molr/ui`，只需遵守 SDK/Host 契约。远程页面必须经过来源与权限确认；不能仅修改浏览器配置就获得执行权限。页面映射始终由主题定义，用户仍然只选择主题。

已有隔离适配器使用不带 same-origin 权限的 iframe 和私有 MessageChannel；逐请求校验方法、规范路径和授权范围，不向页面传递宿主 Cookie、CSRF 或 Bearer。权限表位于 `packages/ui-host/src/permissions.ts`。发布者需维护不可变版本资产；仅固定入口 URL 不等于锁定远程资产内容。

## 验证

`apps/webui/tests/ui-packages.spec.ts` 验证单主题选择、主题拥有的部分页面替换、未声明页面回退、拒绝旧浏览器配置接入、跨浏览器同步、共享草稿与真实发送、服务端保存失败，以及原有聊天加载流程。主题和登录回归覆盖深浅模式、主题配色、账号隔离与一次性登录。

## 聊天时间格式化

聊天时间与完整悬停文本使用同一时区判断当天、当年和跨年。共享 `formatChatTime` 对显式语言／时区组合复用 `Intl.DateTimeFormat`，最多保留 32 组，超出后移除最早加入的组合；不缓存格式化结果，因此当前日期变化仍会重新判断。未指定时区时沿用浏览器或服务端当前默认值，避免把隐式时区固定在缓存创建时。无效时间和时区保持原有行为。

`npm run test --workspace @molr/ui` 覆盖跨天、跨年、夏令时、语言切换、默认时区变化及缓存上限。`npm run test:webui -- chat-time.spec.ts` 使用 500 条分页消息夹具验证桌面／移动端逐字输入不会重复创建聊天时间格式化器，并检查账户时区切换。

## 前端颜色开发规范

适用于 UI Design、WebUI、官网及它们使用的共享组件。**页面和组件不得硬编码颜色，必须通过 CSS 自定义属性 `var(--…)` 使用语义颜色。** 此规则包含 CSS、内联 `style`、JS/TS 动态样式、SVG 图标的 `fill` / `stroke`、边框、渐变、遮罩、阴影以及 `var()` 的兜底值；`white`、`black` 等命名颜色同样属于硬编码。

- 基础色和语义角色集中定义于 `packages/ui/src/tokens.css`，主题配色及其明暗覆盖集中定义于 `packages/ui/src/palettes.css`。这些定义文件是颜色值的来源，允许使用字面量；不要在业务 CSS 中新增一组固定颜色变量来绕过规范。
- 优先复用表达用途的变量，例如 `--color-text`、`--color-positive`、`--color-plan-item`、`--color-trace-model`；新用途缺少变量时先补共享 token，并检查明暗模式和全部主题配色。不要仅因颜色接近而混用不同语义的 token。
- 透明度或渐变通过 `color-mix(in srgb, var(--color-…), transparent)` 等形式派生；共享阴影使用 `--shadow-*`。允许 `transparent`、`currentColor`、`inherit`，它们不指定固定主题配色。遮罩只需要不透明度时可复用现有不透明颜色变量。
- WebUI 普通业务页面使用纯色背景：共用 `.workspace-main` 使用 `--color-page-background`，各页面可按语义覆盖为其他纯色背景 token；空状态和故障恢复状态沿用同一规则。登录页等独立页面可使用装饰性渐变，骨架屏及时间轴等组件的功能性纹理不受此限制。
- 动态样式仍传入 `var(--…)`。必须获得具体色值的 DOM API，通过 `getComputedStyle()` 读取变量；不要额外维护一份主题颜色表。色卡的对比文字使用固定对比色 token，不能直接返回十六进制字符串。

允许的特殊情况必须有明确用途和边界：

| 例外 | 当前位置 | 原因与约束 |
| --- | --- | --- |
| 固定插画、预设头像和示例图片 | `AssistantAvatar.tsx`、UI Design 的附件/路线 SVG | 颜色属于画作内容，可以保持固定；普通界面图标、状态圆点和装饰背景不属于此例外 |
| 独立品牌资源与导出素材 | `packages/ui/public/brand/`、`logo-assets.json`、`palettes.ts` 及品牌生成/替换代码 | SVG 作为图片或下载文件时不继承页面 CSS 变量；配色映射集中管理，不复制到业务组件 |
| 图片编码 | WebUI `AssistantAvatarField.tsx` | Canvas 将透明图片铺白后导出 JPEG，底色属于生成图片，不能随界面主题变化 |
| CSS 加载前的首屏与浏览器元信息 | 三个应用的 `index.html` | `meta[name="theme-color"]` 不解析 `var()`；WebUI 最小首屏变量用于样式加载前防闪烁。仅保留初始化值，加载后由主题脚本读取真实 CSS 变量更新，不扩展成第二套组件主题 |

新增例外时在代码或本节写明原因、使用位置及为何不能使用变量；不能因为“更方便”就放行。主题定义与固定素材的颜色字面量不应被机械替换；外部依赖自身的样式也不作为本项目业务样式修改。

### 同屏颜色辨识检查

不能仅按十六进制相近程度判定问题。先明确同一页面、同一主题和同一显示模式下是否实际同时出现，再检查控件尺寸、透明度叠加、背景、文本/图标/形状辅助标识，以及悬停、选中、禁用等状态。全部主题的浅色和深色均需检查；不同主题之间的颜色相似不构成同屏冲突。前景与背景的可读性检查、两种分类色之间的辨识检查要分开，不能把两种背景的对比度比值当作文字可读性合格线。

检查应覆盖六套配色、明暗模式及桌面和窄屏。详细截图与验收结果保存在本地内部目录，注明日期、提交及环境；本文只维护当前规范。

聊天页右上角「… → 聊天入口」打开独立的连接管理弹窗；绑定后底部使用共享 `ChatComposer.lock` 保留输入框轮廓，框内仅展示微信发送与解绑恢复输入的说明；「管理微信连接」打开同一弹窗，已连接状态在该弹窗中使用成功 `Alert`（`tone="positive"`），需要重新扫码等异常连接状态使用警告 `Alert` 展示；重新扫码的主动提醒沿用通用服务端通知，在聊天顶部队列中展示，助理信息页不再包含连接操作。默认主题与测试主题复用此流程。

微信连接二维码使用共享 `--color-qr-foreground` / `--color-qr-background` token，所有配色及明暗模式保持深色模块和浅色背景，保留四模块静区。二维码在浏览器本地编码，不向第三方图像服务传递登录内容。

## 系统提醒与展示边界

宿主层 `notifications/AssistantNotifications.tsx` 提供两种主题共用的聊天提醒队列。微信投递与连接异常、助理持续受阻、授权请求、计划待交接、任务及后台执行失败由 Runtime 生成提醒；聊天横幅和主动提醒共用通知 ID。客户端不提供独立通知页或通知历史列表，长期信息由原聊天、审批、计划和任务页面管理。

聊天一次展示一条，按发生顺序选择下一条；新提醒不替换当前条。关闭仅确认当前 ID，服务端成功后推进；失败保留当前条及错误反馈。关闭后键盘焦点移至下一条的关闭按钮。提醒区无内部滚动条，仍需检查短屏输入及渠道操作可见。短暂模型重试提示只在没有服务端提醒时显示。已读不隐藏待处理横幅；源问题恢复后服务端解决提醒。

Toast 自动消失、桌面通知被系统收起不自动标记已读或忽略。后台执行失败的聊天横幅和 Toast 仅在 Runtime 支持且用户已设置显示开发工作台时显示「在开发工作台中查看」，按通知来源事件定位执行；桌面通知使用相同目标，未开启时无跳转。未采集或已过期的执行在工作台明确提示。查看其他提醒直接进入对应业务页面；聊天及 Toast 的查看操作标记已读。桌面通知、提示音与当前浏览器设置沿用现有设备策略，未开启主动提醒仍可查看聊天内的待处理提醒。助理新消息继续使用会话序号与已读状态；授权申请卡片的主动提醒由通知记录负责，避免重复弹出。

保存、连接测试、做梦冲突等当前操作的反馈保留在表单附近；连接测试反馈关闭不清除测试结果。短暂模型重试进度、本机断网、隐私说明和表单校验不写成持久通知。`DismissibleAlert` 用于本地临时提示；`ErrorNotice` 对普通业务错误按组件范围区分，只将限流与服务不可用作为会话级重复错误抑制。

## 安全设置的信息层级

安全页沿用其他设置页的平面列表与细分隔线，按“登录与验证、登录设备、登录链接”排列。修改密码放在对应设置行，退出当前设备放在页尾。分组标题和设置项使用共享小号正文尺度，通过字重区分；说明、日期与历史入口统一使用辅助文字尺度。设备与链接名称、状态和操作分别布局，时间使用成组的标签／值；窄屏允许换行，操作保持右对齐。登录链接历史默认折叠。
