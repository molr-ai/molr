# 主题与页面解析

主题决定页面实现，用户选择主题身份。架构分工见[前端架构](https://molr.ai/zh/docs/dev/frontend/architecture/)，颜色与同屏检查见[设计系统](https://molr.ai/zh/docs/dev/frontend/design-system/)。

## 产品交互

用户设置 → 主题提供一个「主题」选择器，内置 Molr 默认主题。

「主题、显示模式、减少动态效果」放在同一组，「主题配色」作为最后一组。显示模式仍提供跟随系统、浅色和深色。主题配色提供森林、海盐蓝、鸢尾紫、暖砂、玫瑰和素墨；素墨覆盖界面基础色与 SVG 品牌资源，状态、分类和代码语法继续使用共享语义色。设置列表只允许操作控件本身，点击标题或行空白不再展开选择器或切换开关；键盘操作和无障碍名称保留。

用户选择一个完整主题。**替换哪些页面由主题清单决定，用户不能逐页组合。** 未声明的页面自动使用默认主题。

不提供独立主题管理页面或逐页选择器。外部主题由管理员通过“插件”页面导入、授权和启用，随后出现在主题选择器；插件版本和安装统一由插件管理。个人主题页地址为 `/#/account/theme`；`/#/settings/*` 用于管理员设置。

终端窗口可独立选择跟随应用、浅色或深色，偏好以 `molr.terminal-theme` 保存在当前浏览器。`data-ui-theme` 作用域复用共享明暗语义 token，`data-palette` 跟随应用配色；窗口标题、控件和 xterm 使用同一作用域。xterm 观察根节点与窗口的主题属性，通过 `getComputedStyle()` 更新 ANSI 颜色，无需重建终端或连接。

## 主题选择与页面解析

账号设置只保存一个主题身份，不保存用户自定义的页面映射。Runtime 的 `Settings.UITheme` 使用 `id@version`，前端解析为：

```json
{
  "selected": { "id": "molr.official", "version": "1.0.0" }
}
```

主题本身声明页面实现：

```ts
const officialTheme = {
  runtime: 'builtin',
  manifest: {
    id: 'molr.official', name: 'Molr 默认主题', version: '1.0.0',
    pages: { assistants: 'official', plans: 'official', resources: 'official', workbench: 'official', settings: 'official' },
  },
};
```

解析时先查选中主题的 `pages[page]`，未声明时使用 `molr.official@1.0.0` 的对应页面。内置主题和已授权的插件主题遵循同一条规则；部分主题无需实现全套页面。

主题目录包含内置默认主题，以及 Runtime 返回的已启用、已授权插件主题。未知主题身份回退默认主题。

主题选择、主题配色与显示偏好统一保存在 Runtime 的账号设置中，在设备间同步。`Settings.PluginsVisible` 默认 `false`；关闭时不读取插件清单，主题目录只包含内置主题，已保存的插件主题身份保留并暂时回退默认主题。插件路由转到常规设置，导航、插件工具目录、登录链接的插件目标、用户组插件／连接选项及用量连接明细同步隐藏；编辑用户组仍保留未展示的资源引用。此设置不改变服务端插件启停、授权或执行。新设备登录时读取已保存的选择；已打开设备沿用设置快照刷新，在页面重新可见或周期刷新时更新。主题选择不依赖 localStorage；保存失败保留原选择，主题不可用时使用默认主题。写入采用设置版本校验，只合并主题字段；旧客户端省略 `UITheme` 时保留已保存值。主题切换后的聊天草稿继续保留。

## 验证

`apps/webui/tests/ui-packages.spec.ts` 验证单主题选择、主题拥有的部分页面替换、未声明页面回退、拒绝旧浏览器配置接入、跨浏览器同步、共享草稿与真实发送、服务端保存失败，以及原有聊天加载流程。主题和登录回归覆盖深浅模式、主题配色、账号隔离与一次性登录。
