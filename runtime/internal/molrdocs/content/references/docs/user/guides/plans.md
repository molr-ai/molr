# 计划与执行

把事情安排进计划，查看每次执行的状态、费用和产物。

## 计划与执行记录

“计划”汇总本人和助理的待办、日程、定时执行和持续关注，可以按负责人、类型和状态筛选；聊天内的计划面板默认查看当前助理。

聊天中的计划侧边面板或抽屉按「接下来」「逾期」「未设日期」「持续关注」切换当前助理的清单；接下来和持续关注每页展示 10 项，可继续加载。点击计划后，面板内容整体向左滑动切换到详情，布局与独立计划清单页一致；点击标题栏的返回按钮回到列表，并保留原滚动位置。

清单默认按发生时间升序展示接下来的 50 个事件，可继续加载。「清单 · 持续关注」是独立范围，不混入接下来、逾期或未设日期清单。页面只请求当前范围对应的列表；首次加载显示加载提示，刷新时保留现有内容，失败可重试。普通清单的类型筛选不包含持续关注；持续关注清单隐藏类型筛选，保留负责人和状态筛选。重复计划的每次发生单独列出；无日期事项和逾期未完成的一次性安排通过独立入口查看。点击具体事件查看的日期、完成操作都对应那一次安排，系列编辑仍作用于整个计划。

计划页默认打开本周日历，周一至周日按列展示，纵向时间轴覆盖全天。安排按时间和时长显示，重叠事件并排排列，跨天安排在各天分段展示；无结束时间的安排以短块标记发生时间。今天和当前时间线会高亮，颜色与图标区分事项、时间安排和自动执行。支持上一周、下一周、返回本周及日期跳转；窄屏可在时间轴内横向滑动。点击安排打开详情，点击日期查看当天完整清单。

日历工具栏中央显示正在查看的周范围或月份，随前后翻页更新；点击中央日期打开日期选择组件，确认后跳转，取消保留原范围。浏览其他周／月时，左侧显示“返回本周／返回本月”；已在本周／本月时隐藏该按钮。右侧小号开关切换周／月模式，也可切回清单；负责人、类型和状态筛选共用。月模式提供上月、下月及月份选择。格子放不下的事件以 +N 折叠，点击 +N 或日期打开当天完整清单。做梦不是日历事件；自动时段可在助理信息的做梦设置中调整。

清单前的实心圆点表示类型：绿色为待办、蓝色为日程、紫色为定时执行、橙色为持续关注，仅用于区分，不能点击。创建、编辑、计划详情及未结束的执行详情会提示做梦冲突，每位助理每天只有一个可配置的自动时段。

新增事项可以先填写标题，再指定负责人、日期或时间。指派给助理只表达责任，不等于立即启动。一次性执行和重复计划的每次发生都有独立记录，查看记录可以了解当时的说明、状态、费用和产物。

打开计划详情后，执行记录按开始时间从新到旧分页显示，每页 20 条；点击“加载更多记录”查看更早的执行。选择某条记录时加载当时的说明、结果和任务详情。记录旁的数字表示该计划的执行总数。没有记录时显示「暂无执行记录」，不显示零计数；首次加载期间显示加载提示，加载失败时可重试。空记录不用于判断计划或持续关注的运行状态。

计划详情分为「计划信息」和执行信息：计划信息显示负责人、启用／暂停、时间安排、重复规则和下次执行；没有安排日期时显示「未设时间」。计划描述沿用属性行样式，默认最多显示六行；超出时可以展开全文或收起，保留换行和完整内容，并随窗口宽度、字号调整判断是否需要折叠。从计划入口打开时只展示计划信息和执行记录，记录按时间倒序排列，不另设「最近执行」区块。从日历事项或某条执行记录打开时，展示计划信息和「本次执行」的状态、实际开始和结束时间、历时、结果与费用，不同时展示记录列表。「查看执行记录」切回当前计划的记录列表，并清除地址中的发生时间和执行 ID。一次性计划的开始、完成操作保留在计划信息下；操作成功后直接显示对应执行。执行状态、时间和费用使用统一的属性行；执行时的说明默认折叠，修订记录默认折叠，不重复初始说明，保留追加要求、验收条件和附件。查看具体某次日程或定时执行时，没有执行记录且安排时间未到显示「尚未开始」，到达安排时间后显示「未执行」；已有记录始终显示实际执行状态，不借用其他日期的结果。待办的截止时间只用于判断是否逾期，不用于推断执行状态；持续关注按实际运行状态展示，整个重复计划不根据某次安排的时间判断状态。页面停留期间会在安排时间到达时更新文案，切回页面也会重新判断。

整个计划的地址不带执行定位参数；未执行事项只带 `at`，已有执行只带 `execution`，安排时间从执行记录恢复。事项产生执行记录后，地址自动替换为执行 ID，不新增浏览器历史。刷新、浏览器返回和一次性登录跳转后恢复同一选择。执行历史分页加载，点击记录切换执行信息；已知执行 ID 可以直接查看分页之外的记录。实际开始时间来自 Runtime 的运行计时，缺失时显示「未记录」；只有开始和结束时间都已记录才显示历时。执行状态通过提交后事件更新。

重复安排完成的是某次执行，不是一次勾选就结束整个系列。暂停只停止后续启动，不中断已有执行。删除会移除整个计划及重复系列、取消未结束的执行，并停止持续关注；已有执行历史或关注事件不阻止删除。被其他未删除计划依赖时，需要先解除依赖。删除采用逻辑删除，底层历史和文件保留，不提供恢复入口；计划修订不覆盖旧执行的说明快照。

## 交接与定时执行

计划可以设置前置事项。当前前置依赖支持一次性计划；前置完成后可以在应用内提示交接，或者由用户明确启用自动启动后续助理执行。

交接不会附带扩大权限或预算。个人填写的结果说明和前置产物可成为后续依据，资料读取仍受助理权限限制。当前应用内交接提示不等于系统推送或邮件通知。

定时执行以服务中保存的时区与重复规则为准，受执行设备在线状态、资源、权限和预算约束。客户端关闭后，在线 Runtime 可继续已接收的工作；Runtime 停机期间不能执行，错过安排的处理取决于计划策略。

## 结果与修订

在执行详情查看等待原因、用量和交付物，并按当前状态暂停、恢复或取消。追加修订保留历史产物及已发生费用；不能把取消理解为删除历史结果。

“已收到消息”“助理已发布回复”“执行已完成”是不同状态。任务交付依赖实际产物和检查证据，当前没有可自动判断任意内容质量的通用验收器。重要结果需要自己核对。

自动整理的时间设置见[记忆与自动整理](https://molr.ai/zh/docs/user/guides/memory/#做梦自动整理)。

## 持续关注

计划清单区分待办、日程、定时执行和持续关注。持续关注由助理准备 watcher 程序，在变化发生时再处理；检查没有变化时不调用模型。可委托“有新的 Issue 时通知我”，未指定结束日期就不设置计划期限。

全局计划页与助理内计划面板均通过「清单范围 → 持续关注」单独查看关注。全局每页 20 项，助理面板每页 10 项，均可加载更多。每项关注只显示一行，不进入日历网格，也不把检查或重启展开成日历事件。详情可查看运行状态、最近检查成功时间、变化与执行记录，并暂停或恢复。只有完成计划目标才标记已结束；某次变化处理完成不会结束整个关注。

运行使用助理已有的计算、文件和网络授权。授权到期后停止监听，计划保留并显示受阻；助理可以通知你或申请所需授权。权限恢复后重新校验，再恢复执行。暂停的计划或自身已到期的计划不会自动恢复。发生中断时，是否能够补取遗漏变化取决于数据源和 watcher 程序。

Watcher 由助理通过现有计划工具创建；界面支持查看、修改处理说明与结束日期、暂停和恢复。程序协议见[持续关注与 watcher 协议](https://molr.ai/zh/docs/dev/runtime/watchers/)。
