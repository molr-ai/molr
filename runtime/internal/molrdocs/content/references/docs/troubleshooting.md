# 故障排查

先根据页面现象检查账号权限、模型连接和服务状态。需要修改资源配置时联系实例管理员，涉及服务配置时由部署者处理。

## 等待与失败

| 页面现象 | 可以检查什么 |
| --- | --- |
| 模型无权限 | 当前助理是否已获得该模型的调用授权，授权是否过期 |
| 模型价格缺失 | 模型配置是否有明确价格；不要为了绕过等待而随意填零 |
| 预算不足 | 当前周期用量、执行中预留、助理额度，以及当前用户组授予该账号的额度 |
| 提供商认证失败或限流 | 连接地址、Key 和供应商配额；等待后再决定是否重试 |
| 本机模型连接被拒绝 | 地址是否指向 Runtime 主机，部署网络策略是否允许 |
| 命令环境不可用 | 查看 [Linux 命令环境诊断](https://molr.ai/zh/docs/sandbox/linux/#检查与验证)，不要改为无隔离执行 |
| 客户端断线 | 网络和 Runtime 是否在线；页面重连后核对消息与执行记录 |
| 结果待核对 | 先确认实际操作和产物；不要直接重复可能已生效的操作 |

导航连接图案反映客户端连接状态，不代表所有任务成功。调整权限、资源或预算后，按任务当前提供的操作继续；不要仅因保存设置成功就认定旧任务已经恢复。

## 收集诊断信息

在「用户设置 → 关于」核对 WebUI 与 Runtime 的版本和 commit；前后端不一致时先保存输入，再刷新或让管理员核对部署版本。

开发工作台需要部署者启用 `debug.enabled`。用户常规设置中的「显示开发工作台」只控制入口显示，不能补回未采集或已清理的记录。查看已采集的模型请求、工具结果和上下文时，参考[开发工作台](https://molr.ai/zh/dev-docs/runtime/workbench/)。

部署者可按[模型响应诊断日志](https://molr.ai/zh/docs/deployment/maintenance/#模型响应诊断日志)临时记录原始响应。账号无法登录时使用[本机恢复流程](https://molr.ai/zh/docs/deployment/maintenance/#备份恢复与升级)。
