# Molr 产品文档

> **本文档面向使用和部署 Molr 的用户。** 架构设计、接口合同、安全模型与沙盒实现等开发者内容，请移步[开发者文档](../dev-docs/README.md)。

Molr 是可自托管的个人 AI 助理：在自己的设备上运行服务、连接自己选择的模型，通过持续对话把日常事情交代给助理，并在计划中查看安排与执行结果。支持家庭和小团队使用独立账号，通过用户组分配资源与额度，不提供公开注册或用户间交互。

## 设计理念

- **持续协作，而非一次性问答**：助理围绕持续对话与计划工作，执行状态、记忆和授权跨会话保留；关闭页面不丢失上下文。
- **以计划组织执行**：事情可以安排进计划，包括时间、负责人、重复规则与前置依赖；进展、费用和产物在同一处查看。
- **权限与预算由你决定**：每位助理能访问哪些目录、调用哪些模型、花费上限多少，都由你明确设置，可随时调整或撤销。
- **后台执行，多设备接续**：服务运行期间，助理按计划在后台执行并记录进展，无需保持页面打开；用其他设备登录同一服务即可接续对话与计划。
- **记忆可以管理**：助理定期回顾对话与任务，把值得保留的内容整理为记忆；你可以查看来源、编辑、确认，或让助理遗忘。
- **模型自选**：云端与本地模型均可接入，可按助理分别配置。
- **自托管**：运行自己的服务、连接自己的模型，数据保存在你自己的设备上。

## 主要能力

- **助理与持续对话**：每位助理有独立的记忆、权限和预算；桌面与手机浏览器连接同一服务，聊天与计划跨设备可见。
- **计划与定时**：日历视图、重复安排、前置交接与执行记录，任务产物可追溯、可修订。
- **资源与权限**：连接自己的模型服务和文件目录，按助理精确授权、随时撤销；助理默认只能访问自己的工作区。
- **命令执行（Linux）**：助理的命令在隔离沙盒中运行，只能访问授权目录和白名单网络，接触不到服务本身的数据与密钥。
- **自动整理与记忆**：助理每天在预留时段回顾对话与任务，把值得长期保留的内容整理成可管理的记忆。

## 当前能力边界

WebUI 使用真实 Runtime 数据，支持桌面与手机浏览器访问。同一服务内的聊天和计划可以跨设备查看，这不意味着任务可以在多台 Runtime 之间迁移。

Linux 提供受控目录工具与命令沙盒；其他操作系统目前不能视为具有同等文件与 Shell 能力。基础命令环境包含 BusyBox，不默认包含 Python 或 Node。模型的图片、音频和视频能力取决于实际模型配置与部署依赖。

使用云模型或外部网络服务时，输入可能发送给对应服务；自行部署 Runtime 不等于推理全程离线。预算依据配置价格和供应商返回用量核算，未知价格不会被当作免费。
