# 插件

先在 **用户设置 → 常规** 开启 **显示插件**，再通过侧栏 **插件**（`/#/extensions`）管理主题、页面和 HTTP 工具。此开关默认关闭，按账号保存并跨设备同步。关闭后隐藏插件入口、插件主题、插件工具目录、登录链接的插件目标、用户组中的插件和服务连接选项，以及用量中的连接明细；直接打开插件页面会转到常规设置。已选择的插件主题暂时使用默认主题，重新开启后恢复。已有插件配置、授权和后台工具执行不受影响。CLI 和 Skill 直接安装在助理工作区，无需导入插件包。

## 添加插件

管理员点击 **安装插件**，在弹窗中选择 **上传插件包** 或 **从链接安装**，提供 ZIP 文件或公开 HTTPS ZIP 地址，点击 **安装**。下载不携带账号凭证，不跟随重定向，不访问私网。页面搜索范围为本实例已有插件，没有在线插件目录。

导入只保存并校验包，不执行脚本。管理员全局启用插件、批准所需权限，通过 **授权用户组** 允许成员使用，并为助理绑定 HTTP 工具。普通成员只看到全局启用且本组获准的插件；个人启停只影响自己的使用。

## 安装 CLI 或 Skill

直接在聊天中告诉助理来源与用途，例如：“把这个 CLI 安装到你的工作目录，并按文档验证可用。”助理使用普通 Shell 和文件工具安装程序及依赖，需要计算或网络资源时沿用现有权限申请流程。

CLI 安装在助理的 `/work` 内。Skill 放入 `/work/.agents/skills/<名称>/SKILL.md`，系统自动发现，助理按需读取。不同助理拥有独立工作区，文件跨执行和重启保留。登录按 CLI 自身支持的流程完成，登录文件保存在工作区；更新、检查和删除也由助理使用普通工具完成。

这类安装不会在插件列表中生成记录。插件启停、版本切换和卸载不管理这些工作文件。

## 插件配置与连接

个人设置、管理员共享设置和 HTTP 服务连接由插件按需声明。只有提供设置的插件才显示配置入口。HTTP 连接由管理员配置，API Key 加密保管，通过已授权连接注入固定请求。

连接支持累计调用、并发、超时和用户组额度。“测试连接”会发送供应商请求并计入额度；页面加载和保存不会自动测试。配置错误或权限不足时不会自动换用其他连接。

## 版本与卸载

导入新版本仅暂存，管理员切换启用版本时保留仍适用的权限和工具绑定。配置或连接摘要变化后需要复核。

停用、撤权或卸载会关闭相应的页面、主题和 HTTP 能力。卸载保留已发布版本与历史调用记录；删除 HTTP 服务账号需单独删除对应连接。

## 编写插件

以普通目录开发，根目录包含 `plugin.json`，通过 `node scripts/pack-plugin.mjs <插件目录> <输出.zip>` 打包。当前包协议为 Plugin API 3，页面通信协议独立使用 API 2。

包内文件为 UTF-8 文本；包最多 8 MiB、256 个配套文件，每文件最多 1 MiB，不接受链接或越界路径。包结构、页面通信和 HTTP 合同见 [插件架构](../dev-docs/runtime/PLUGINS.md)。
