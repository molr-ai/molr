# 插件

侧栏 **插件**（`/#/extensions`）展示本实例添加的插件。插件可以提供 Skills、脚本、主题、页面和可选 HTTP 工具。CLI 由助理安装到自己的工作目录；不同助理分别管理依赖和登录状态。

## 添加插件

管理员点击 **导入插件包** 选择 `.zip`，或通过 **从链接添加** 提供公开 HTTPS ZIP 地址。远程下载不携带账号凭证，不跟随重定向，不访问私网地址。页面搜索范围为本实例已有插件，没有在线插件目录。

ZIP 根目录包含 `plugin.json` 和配套文件，使用 Plugin API 3。添加包只校验和保存文件，不执行安装脚本，也不自动授予资源权限。相同 ID、相同版本的内容不能覆盖；新版本导入后先保留在版本目录中。

管理员通过卡片全局启用插件、批准页面和 HTTP 能力，并用 **授权用户组** 允许成员使用。普通成员只看到全局启用且本组获准的插件。个人启停只影响自己的使用。

## 为助理安装 CLI

打开卡片更多菜单中的 **助理环境与账号**：

1. 选择自己的助理和插件版本，开启 **为此助理启用**。这一步准备工作副本，不安装宿主软件。
2. 点击 **交给助理安装或登录**，在聊天中说明要完成的操作。助理按需读取 Skill，检查自己的环境，申请缺少的计算或网络权限。
3. 助理通过普通 Shell 下载并安装 CLI、运行依赖，然后执行插件的检查步骤。
4. 需要登录时，按 CLI 支持的扫码、浏览器或设备码流程完成授权。

插件工作目录为 `/work/.local/plugins/<插件 ID>/`：`versions/<版本>/` 存放 CLI、依赖和包副本，`config/`、`data/`、`cache/` 分别保存账号配置、业务数据和缓存。工作区跨执行和重启保留。

安装和日常操作都遵循助理已有的沙盒、资源权限和额度。插件声明的需求只解释用途，不直接授予权限；管理员没有开放的资源不能由插件自行放行。Shell 支持的网络、后台任务和交互能力继续使用其原有规则。

**环境** 和 **账号** 分别显示助理最近一次检查的结果，不是实时健康检查。安装失败时可以让助理检查任务输出并重试。提供安装及检查脚本的包会获得 `prepare.sh`，串行执行安装和检查，只有检查成功才更新活动版本；中断残留的安装锁需要先检查相关 Shell 任务再恢复。

## 账号与配置

CLI 支持自己管理登录状态时，登录文件保存在该助理工作区。插件声明凭证字段时，环境弹窗提供密码输入框，保存到 `config/secrets/<字段 ID>` 的 `0600` 文件中；不会回显或发到聊天。该助理的其他程序也能读取这些文件。开启敏感操作验证时需要完成验证，留空保留已有值。

个人设置、管理员共享设置和 HTTP 服务连接仍由插件按需声明。只有提供相关设置的插件才显示相应配置入口。HTTP 连接由管理员配置，API Key 加密保管，通过已授权连接注入固定请求，与工作区 CLI 的凭证文件分别管理。

HTTP 连接支持累计调用、并发、超时和用户组额度。“测试连接”主动发送供应商请求并计入额度；页面加载和保存不自动测试。配置错误或权限不足时不会自动换用其他连接。

## 版本、停用和清理

每个助理选择自己的 CLI 插件版本。管理员切换页面／HTTP 版本不会改变这些选择，仍适用的能力授权和工具绑定予以保留；HTTP 连接摘要变化后需要重新复核。助理升级时新版本写入新的目录，原版本及账号数据保留；检查失败不会替换 `prepare.sh` 管理的活动版本。账号或数据格式变化需按插件说明处理，切回 CLI 版本不自动恢复数据。

停用插件或取消用户组授权会撤下 Skill、页面及受管 HTTP 能力，并拒绝继续读取插件原包。已经安装到助理工作区的程序仍是普通工作文件；需要阻止它访问服务时，应撤销相应网络授权或账号凭证。

卸载插件保留工作区内容。**助理安装记录** 在卸载或撤权后仍可访问，用于停用并清理自己的安装。清理前停止相关 CLI 任务；清理会删除所选助理的此插件所有版本、配置、登录状态和数据，不影响其他助理。删除 HTTP 服务账号仍需单独删除对应连接。

## 编写插件

以普通目录开发，通过 `node scripts/pack-plugin.mjs <插件目录> <输出.zip>` 打包。配套文件目前为 UTF-8 文本；CLI 二进制和第三方依赖由助理在工作区下载，页面图片可内联。包最多 8 MiB、256 个配套文件，每文件最多 1 MiB，不接受链接或越界路径。

包结构、Skill 接入、工作区状态和 HTTP 合同见 [插件架构](../dev-docs/runtime/PLUGINS.md)。
