# 资源、权限与预算

## 连接与授权

管理员连接资源并通过用户组分配可用范围；用户再为自己的助理授权具体动作、范围和额度。登录成功不会让助理获得部署设备的全部文件或网络。

模型以提供商连接组织，一个连接可以有多个模型。百炼、智谱和 Moonshot 预设通过 OpenAI 兼容接口连接，使用 API Key，可保存、编辑连接并刷新模型列表；模型价格未覆盖时仍需手动配置。聘请助理时授权所选模型；后续在助理信息的权限页查看、增加或撤销权限。授权精确到所选模型，不会自动覆盖同一提供商的其他模型。

文件目录需要明确连接并选择读写范围。每位助理还有独立工作区，默认可通过文件工具读写；这不代表可以读取宿主其他目录。命令执行另需就绪计算资源的执行权限，网络也单独授权，见 [Linux 命令环境](deployment/sandbox.md)。

当前可手动连接模型与本地目录，本机计算环境由 Runtime 自动登记；其他类别的可用操作以实际界面和能力状态为准，不应把资源分类当作已经接入的服务清单。

模型服务收到的请求统一携带 `User-Agent: molr/<版本号>`，便于在服务端日志中识别客户端；未注入版本的开发构建使用 `molr/development`。该标识也用于连接测试与模型列表查询。

## 连接 vLLM 与 SGLang

在「资源 → 模型 → 连接提供商」选择 vLLM 或 SGLang，也可通过「本地」筛选找到。默认连接 Runtime 所在设备：vLLM 为 `http://127.0.0.1:8000/v1`，SGLang 为 `http://127.0.0.1:30000/v1`。在「更多配置」修改地址以连接其他部署；这里的本机地址指 Runtime 所在机器，不是浏览器所在设备。

默认无需认证；服务启用 API Key 时选择对应认证方式并填写密钥。可先测试连接，保存后自动获取 `/v1/models` 中的模型，后续可以刷新列表或编辑连接。Runtime 必须通过 `network.allowed_private_ips` 允许目标私网／回环 IP，选择预设不会绕过网络限制。

两种预设使用 OpenAI 兼容 Chat Completions。服务端需配置适合模型的聊天模板；助理工具调用还需启用服务端对应的工具解析器。图片、音频等能力按实际模型配置，不从模型名称猜测。模型列表返回的 `max_model_len` 会作为上下文上限；手动覆盖值在刷新后保留。自托管不自动视为免费，使用前请配置实际价格（免费部署可明确填 0）。

若模型提示聊天模板或工具解析错误，先核对服务端模板配置；维护者可参考[模型适配说明](../dev-docs/runtime/MODEL_ADAPTERS.md)。修复后发送新消息发起新的调用。

## Full Access 权限

授权表单先选择资源类型「模型／工具／沙盒」。选择沙盒后，再选择具体沙盒和权限类型「存储／计算／网络／完全访问」。存储继续选择存储资源和路径，网络继续选择网络范围，计算填写计算额度。部署已允许 Full Access 时，可以选择「完全访问」。普通用户组还需管理员明确允许授予此权限。它允许助理显式选择不隔离、无资源限额的文件和命令调用；未选择的调用继续遵循原权限。同一资源可以同时保留普通计算授权和 Full Access 授权，分别设置有效期、修改和撤销。

选择完全访问后不填写配额，也不需要另授目录和网络权限。详情见 [Full Access 部署与执行语义](deployment/sandbox.md#按需授予-full-access)。

## 助理请求授权

助理使用 `permission_list` 查看「已获授权」「可申请权限」和「内置能力」。可申请目录只提供已连接资源的名称、标识、支持的操作与资源内范围，不暴露宿主路径、凭证或资源内容，也不会自动授予使用权限。已经授权但沙盒离线时，需要恢复资源可用性，无需重新授权。

缺少权限时，助理先按最小权限原则选择完成任务所需的资源、操作、范围和授权时间，再调用 `permission_request`。助理必须从可申请目录选择真实的资源 ID，并明确填写到期时间；存储申请还必须明确目录范围，不默认申请永久或整个资源的权限。未连接的资源需先由用户连接，不能只用资源描述发起审批。

创建卡片前会校验每一项申请：资源是否存在且处于当前账号可申请的范围、类型是否匹配、操作是否受支持、模型是否属于所选提供商，以及待调整授权的归属与版本。参数无效时立即向模型返回申请失败、具体字段和原因，不创建审批卡片，也不进入等待审批；组合申请任一项失败则整组失败，模型可以修正后重新申请。

申请以助理消息卡片发送到聊天，包含用途、申请操作、范围、授权时间和处理状态。点击「查看并授权」直接打开已预填的表单；可以修改资源、模型、操作、范围或时间，点击「批准授权」后才按最终确认值创建授权。点击「拒绝」不会增加权限。申请原文与实际批准内容分别保留，卡片在刷新或其他设备上也会显示最新状态。

授权请求卡片与其他消息卡片使用相同布局，分别列出资源、允许操作、目录范围和授权时间。批准后，卡片展示你最终确认的授权内容；若在表单中调整过权限或有效期，以卡片中的实际批准内容为准。

提交申请后，当前 loop 保存进度并等待；批准和拒绝都会注入明确结果并恢复 loop。助理按最终有效授权继续工作，或在拒绝后说明限制。手动停止、暂停或已经结束的任务不会因为旧请求被处理而自动恢复。其他授权新增、修改、撤销和到期也会在下一次模型调用前更新授权上下文，不沿用历史权限判断。

同一任务、相同申请内容会复用待处理请求和已有聊天卡片。助理权限页保留申请记录（最多 200 项，待处理优先）。批准记录表示曾经批准，后续访问仍受实时授权、有效期和资源状态约束。

## 修改与撤销

授权可以限定动作、资料范围及有效期。断开资源、撤销或到期会限制后续执行，相关运行可能被停止；已经完成的写入或已经发出的数据无法通过撤权撤回。

Shell 读写挂载要求同时具有读取和写入权限，并会直接修改原目录；取消不回滚。仅写权限可以由支持该操作的文件工具使用，不自动获得 Shell 读取权限。

模型和外部服务凭证由 Runtime 管理，不在普通聊天中填写密钥。更换 Provider Key 时不会回显旧密钥。删除提供商会清理连接、相关模型和权限，保留助理与聊天；失效模型需要重新选择。

## 助理预算

在聘请助理或“助理信息 → 概览”中设置金额、币种及每日／每周重置周期。所有聊天、后台和定时执行共享所属助理额度；没有全局默认预算或任务独立预算。

模型调用前会占用预留费用，取得实际费用后结算。本地调用结束时自动结束费用预留和并发占用；费用未知时保留历史记录，不按零费用结算，也不要求手动处理。运行中的调用跨周期仍占用额度，结束后费用归入调用原所属周期。Runtime 重启会先补结算已有回执，再清理上一进程遗留的调用占用；未知调用不会因此自动重试。修改预算、修订任务或周期重置不会删除历史账单。

预算用于个人使用时防止意外大量消费，依据服务配置的模型价格及返回用量执行，不等于供应商账号的最终账单或支付限额。中断请求可能已在供应商侧收费但未计入本地消费；后续取得实际费用时会补记，超过预算后阻止新调用。价格未知时需要补充配置，不按免费处理。手动价格与币种应按实际服务核对。

常规设置的币种只影响新输入默认值和展示，编辑已有金额时保留原币种和精度。金额展示统一按偏好币种换算，多币种费用显示一个合计，不并列原币金额；固定两位小数，不足一分向上取整，换算金额带 `≈`。暂时无法换算时显示 `—`。换算使用带版本的参考汇率，不是实时交易报价。重置时间按账号时区计算，设置时区后留意页面显示的下次重置时间。

## 数据发送范围

使用远程模型时，提交给模型的资料会发送到该服务；本地部署 Runtime 并不能消除这类传输。允许 Shell 读取资料并连接某个目标，也意味着脚本可以向获准目标发送可读数据。

网络目标授权限制可连接的主机和端口，不等同于网站内某项业务动作授权。HTTPS 隧道不承诺检查加密内容中的路径、请求正文或具体动作。

## 沙盒资源

资源页的三个入口为「模型 / 工具 / 沙盒」。存储、计算、网络在所属沙盒内配置，助理权限页可按电脑筛选授权，助理工作区固定在 Runtime 本地。本机沙盒无需另起服务，远程机器运行独立 Linux Sandbox 服务。目录与网络只能选择部署允许的范围，连接不自动授权。远程操作必须显式指定目标节点，远端没有助理工作区。使用文件传输工具上传或下载单个文件，目录不会自动同步。详见 [独立 Sandbox 服务](deployment/remote-sandbox.md)。

助理可以查询网络的实际地址、端口、协议、额度和当前用量，不应从资源名称推测访问范围。查询失败或沙盒离线时不会把旧快照当成当前权限。命令默认自动使用同一沙盒中的有效网络授权，也可显式关闭本次出站联网；查询和资源连接本身都不构成授权。工具返回字段由[资源与文件工具合同](../dev-docs/runtime/FILE_TOOLS.md#网络范围查询)维护。


## 计算、网络与工作区额度

计算与网络的额度在助理授权中设置，也可由助理通过聊天卡片申请。用户可以修改申请值后批准；同一张卡片最多组合八项计算、网络或存储申请，任一项验证失败均不创建部分授权。组合审批先显示每项资源及额度摘要，展开后可修改；顶部统一设置授权时间，整组权限共用此有效期，批准后的卡片也只显示一个授权时间。临时额度另有恢复基础额度的时间，该时间不得晚于授权到期。调整已有授权时使用其 ID 和版本，不叠加重复授权。

| 类型 | 授权属性 | 用量口径 |
| --- | --- | --- |
| 计算 | CPU 算力、内存、进程／线程数 | 同一助理在同一沙盒中的执行共享 |
| 计算 | 单次最长运行、内存临时盘 `/tmp` | 分别限制每个执行；不限运行时长须显式批准 |
| 网络 | 双向流量、周期、时区 | 按助理与实际网络来源跨执行累计；支持累计、每天、每周、每月 |
| 网络 | 并发连接 | 同一网络来源的所有执行共享 TCP 连接与 UDP 会话名额 |
| 工作区 | 容量、单文件大小、文件和目录数量 | 同一助理在此沙盒中的 `/work`，所有写入入口共用文件系统额度 |

网络页展示访问范围，流量和连接额度在助理的网络授权中设置与查看；计算页显示可申请的计算能力范围。权限页显示实际获批额度及用量。CPU 的 1 核算力等于原来的 100%。授权有效期与单次最长运行时间分别设置。

周期按授权记录中的时区计算，重启或重新执行不清零；修改额度保留已用量。已有周期与时区不能通过编辑更换，避免重复领取额度。临时额度保留基础值，到期恢复；当期临时追加可将临时流量上限提高到基础额度加追加量，并把到期设为当前周期结束。已用量超过恢复后的额度时停止继续消耗，不删除历史账单。

命令默认自动使用该助理在当前沙盒内已获批、有效且仍有部署目标的网络权限。模型不必传入网络资源 ID；没有授权时仍可执行离线命令。流量耗尽不能靠重开命令绕过。网络提额可用于运行中的任务；网络授权到期或撤销限制其连接，不因其他未使用网络权限的到期而停止计算。计算授权修改会停止受影响的任务，新执行采用批准后的额度；已结束的命令不会自动重跑。

工作区容量需要部署启用并预配置 Linux 文件系统项目硬配额。未配置的工作区明确显示不支持容量额度，不能仅修改界面数字宣称已扩容。达到容量或临时扩容到期不会删除文件，仍可读取和清理；单文件上限适用于 Shell 与文件写入工具。外部共享目录不计入某个助理的工作区额度。原 `execution.max_disk_bytes` 的 10 GiB 是 Runtime 上传附件库限制，并非 `/work` 容量。

不再支持无额度的旧版计算、网络和工作区授权。已有旧授权作为一次性数据维护直接删除，需要重新明确批准额度后才能使用相应能力；程序不包含启动清理或自动转换逻辑。已有独立额度、模型／工具权限、外部目录范围权限和审批历史保留。远程沙盒需要同步升级到权限与额度协议版本 4，不支持时明确报告升级要求。

`/tmp` 是计算授权中的内存临时盘（`temp_bytes`），每次执行独立，写入按实际占用计入计算内存，执行结束后清空。64 MiB 是可调整的申请示例值，不是持久存储容量；需要保留的文件应写入 `/work`，其容量由存储授权管理。
