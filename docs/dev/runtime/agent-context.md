# 自动上下文更新

每次模型请求前，Agent Loop 重新获取当前可用工具、账号偏好、工作区说明以及 Runtime 本地助理工作区中的项目指令、Skills。按内容哈希比较已应用版本；变化时生成私有 `context_changed` 通知，包含完整有效内容、来源、作用范围及撤销记录；版本和 add / replace / remove 变化保留在内部状态与调试记录中。首次请求将现有来源视为新增。未变化时不追加通知，也不生成新的 `context.changed` 调试记录。

工具同时更新模型请求的 `Tools`。工具定义只通过 `Tools` 发送，不在自动快照或基础提示中重复描述。内部工具摘要仍由同一次 Definitions 结果生成，用于检测定义、权限元数据与可用性变化。工具调用仍在执行时校验实时权限；上下文更新不能授予权限。发生在模型生成期间的更新，在该轮全部工具结果收集完成后的下一次模型请求生效，不中断生成，也不拆开 tool call / tool reply 配对。

基础提示词将 `conversation_publish` 规定为与用户沟通的唯一途径，明确直接 `content`／最终回复对聊天用户不可见；需要回复时必须先发布并检查工具结果。旧检查点中的已知基础提示词会在模型请求边界精确匹配并替换为当前模板，不改写自定义系统指令，也不将内部文本自动发布到聊天。

用户消息轮次收到无工具调用的模型结束响应时，如果整轮尚未实际尝试 `conversation_publish`，Runtime 插入一条 user role 的私有提醒，询问是否忘记发送消息，并说明无需回复时仍可直接结束；提醒不要求必须发送。随后继续原执行循环，每轮最多提醒一次，包括该轮加急接管的用户消息。纯后台事件不触发；后台轮次接管用户消息后也适用。`PublishAttempted` 与 `PublishReminded` 随当前执行游标保存，提醒与标记原子落盘，模型重试、重启和上下文压缩不会重置次数，新用户轮次重新计数。已尝试但失败或结果未知的发布也不触发此提醒，避免误导重发；被跳过的调用不计为尝试。停止、执行错误、等待权限不触发补跑，继续请求仍受原步数、预算及取消限制。提醒和直接回复均不自动发布到聊天。

用户消息事件的 user 输入在首行 JSON 后附自然语言约束：响应前调用 `conversation_read`，从最近历史开始并按 `NextCursor` 向更早历史翻页；每页按消息序号正序返回，最新消息在最后。读全当前未读消息，按顺序综合处理补充、纠正和取消；不能只读触发 `MessageID` 或最新一条，也不能凭事件引用猜正文。无法确认已读边界时继续读取到历史末尾。这是提示词约束，消息投递、队列和确认机制保持原有行为。

自动上下文、控制、恢复、核对、交接及加急通知直接使用 user role；旧检查点中已识别的 Runtime 通知在继续执行／请求投影时转换为 user，保留来源、正文和恢复元数据。首条基础指令仍为 system，自定义系统指令不由此迁移改写。历史工作台记录与检查点加载快照保留原始 role。

## 来源与加载

- 聊天入口：连接微信时增加 `chat_channel` 来源，说明图片/文件能力并提示避免交互卡片，必要卡片将转换为文字和链接。每次请求重新读取当前绑定，解绑后移除该来源；不写入助理永久指令。
- 工具：`Tools.Definitions` 每轮重新授权、筛选。名称、描述、参数只进入请求的 `Tools`；自动通知不列工具清单或工具撤销清单。完整内部定义的哈希仍检测所需操作等元数据变化。
- 当前授权：`permissions` 在每次模型请求前刷新当前助理的有效授权，新增、修改、撤销和到期都改变快照版本，替换旧授权信息。范围与有效期来自真实 Grants；未变化不重复注入，实际工具执行仍重新授权。
- 授权请求：`permission_requests` 来源仅按当前助理读取待审批与近期决定（最多 40 项），批准、拒绝后整体替换快照。审批记录不是有效授权或可执行指令；用户可以修改提议的授权范围与期限，继续工作前仍须查询 `permission_list`。拒绝后不得在没有新指示或需求变化时反复申请。
- 用户偏好：授权当前执行后，按所属 OwnerID 读取时区、语言、币种，作为 `user_preferences` / `runtime/user_preferences` 注入。只按这三项有效值和各自来源计算版本，不包括设置总版本、其他设置或当前时钟。未保存时区或时区无效时标记为 unknown；语言与币种缺失时沿用 en / USD，并标记为 default，保存的有效值标记为 user_settings。它们是用户可覆盖的默认偏好，不是额外指令或权限。语言决定默认回复语言；币种不重写原始金额或预算，换算需要有依据的汇率。现有事件时间字段保持原语义，不新增实时 current_time。
- 工作区：`workspace` / `runtime/workspace` 来源描述本地 `/work` 的可用状态、助理级持久性、默认目录用途、账号共享只读 `/global` 和单次 Shell 临时目录 `/tmp`。首次使用初始化缺失的默认目录，不创建或覆盖 AGENTS.md、记忆正文或用户文件。禁用本地沙盒、缺少组引用时标明不可用，不注入该工作区的文件指令。普通文件数量、正文、时间戳和磁盘占用不参与此来源的版本；目录说明不授予权限，不包含宿主路径。
- 项目指令：固定读取 `/work/AGENTS.md` 和 `/global/AGENTS.md`；子目录按成功的本地工作区 `file_list`、`file_read`、`file_search` 访问路径读取该目录及上级的 AGENTS.md；搜索结果用 `TargetKind` 区分文件和目录，文件目标从父目录加载指令，目录目标从自身加载，零命中也遵循同一规则，不递归枚举项目文件。首次进入目录应先单独调用 `file_list`，下一次模型请求加载指令后再修改文件或执行 Shell；进入更深目录时重复。每份文档仅适用于所在目录及子目录，更具体的指令优先。已加载作用范围保存在自动来源中，压缩和重启后继续刷新；删除时撤销。外部资源、远程、Full Access 和失败的读取不触发本地发现。
- 指令排除范围：根目录 `inbox/`、`outputs/`、`.local/state/molr/`，以及任意层级 `.agents`、`.git`、`node_modules`、`.cache`、`.venv`、`vendor`、`dist`、`build` 中的 AGENTS.md 不自动加载。Skills 仍使用独立入口。导入材料和执行输出仅作为按需读取的数据。
- Skills：从助理工作区发现 `/work/.agents/skills/<目录名>/SKILL.md`。初始目录信息包含目录名、读取路径及原样保留的 YAML frontmatter（不在 Runtime 内解释 YAML）。成功的工作区 `file_read` 会激活该 Skill，下一轮自动注入完整正文；部分读取也会激活完整正文。后续修改刷新正文，重启后仍保持加载状态。通过 Shell 读取不作为可靠的加载信号；目录提示要求使用 `file_read`。

不会读取 Runtime 项目仓库、宿主 home、其他助理目录或自动遍历已授权的外部存储。远程电脑不提供工作区，也不作为自动上下文来源；远端同名 AGENTS.md 或 SKILL.md 只是显式读取的任务资料。项目指令和 Skill 内容属于有作用范围的工作区指引，不能覆盖 Runtime 规则或用户明确指令，也不会自动变成更高权限的指令。

目前文件来源沿用 Linux 目录工具的受限读取：拒绝符号链接、硬链接、特殊文件和越界路径。使用内容哈希识别变化，文件时间戳仅用于检测采集过程中的并发修改。采集遇到读取错误、并发修改或超限会明确失败，不把未读到的内容当作删除，也不发起模型请求或预留本次模型预算。

Skills 目录仅浅层枚举，最多 4096 项；指令最多检查 256 个访问目录及其祖先、32 层深度，不扫描普通项目树；单文件最多 64 KiB，总读取量最多 512 KiB。发现阶段只注入元数据，但为检测 Skill 正文变化也需要有界读取该文件。frontmatter 的目录展示上限为 8 KiB；无 frontmatter 时仍按目录名和路径发现。全部来源最多 256 个（含工具），撤销记录保留异常容量防护，不静默截断有效指令。模型上下文按下文 token 容量与自动压缩规则管理。

CLI 配套 Skill 同样放入普通工作区的 `.agents/skills` 目录；插件不提供独立 Skill 类型或虚拟文件路径。

## 通知和持久化

通知是 Loop 内部的模型上下文事件，新通知直接使用 user 角色，并保留 RuntimeContext 标记以识别、替换快照。旧检查点中已识别的 Runtime system 通知在继续执行／请求投影时迁移为 user，保留来源内容及权限边界。当前基础 system 指令只有一条，不将通知合并进去。触发事件本身使用 user 角色。它不是用户消息，不发布到聊天，也不作为独立 scheduler Job 排队。因此运行中的同一个 Handle 可以在后续模型调用中立即使用新版本。

模型可见通知包含：

- `sources`：除工具外的当前有效来源。保留类别、来源、作用范围；结构化正文直接使用对象／数组，文件正文仍是原始字符串。只有 Skill 需要显示加载状态。
- `removed`：仍有效的非工具撤销记录；同一来源重新加入会清除此来源的撤销记录。
- 完整替换、来源信任边界、权限及偏好含义的模板说明。没有变化清单、快照哈希或重复的来源版本；记忆暂时保留原来的条目格式。

`Automatic` 内部仍保存完整来源标识、版本、变化及撤销状态。工具只保存元数据摘要，不保存另一份 schema 正文。

更新时整体替换先前的自动通知，只保留一个有效快照，避免旧正文不断积累。历史模型消息、工具调用结果和供应商推理状态保持原样，通知明确旧内容已被替换或撤销。

Checkpoint 的 JSON 保留 `Inputs` 和 `Automatic`（有效快照、已应用版本、撤销记录、Skill 加载状态）；执行中同时保留通知在请求中的准确位置，以便模型请求按原样恢复。这些字段通过[上下文存储](context-storage.md)引用共享消息前缀，数据库检查点行不重复保存正文。恢复后先与当前来源比较，再重新装配通知；来源未变时沿用同一版本，不把恢复误记为新变化。重置上下文同时清除这些状态。自动压缩保留 `Automatic`，不会仅总结 `Inputs` 后丢弃来源状态。

当前不因文件变化主动唤醒空闲助理。空闲时在下一次正常事件执行前加载最新版本；连续多次文件修改自然合并为该边界看到的最新内容。

## 验证与观测

工作台记录私有 `context.changed` 步骤；`model.start` 展示实际注入内容和相同版本的 Tools，checkpoint 可查看 `Automatic`。这些信息不通过普通聊天流公开。

行为测试覆盖：运行中工具撤销及指令更新、通知去重、工具定义一致性、重启恢复与撤销、Skill 目录/按需加载/更新/删除、路径隔离、读取失败与预算边界，以及既有推理状态和 checkpoint 兼容测试。

## 模型上下文模板规范

`runtime/internal/agent/prompt/templates/` 集中维护基础指令、自动快照、事件、停止、交接、恢复、加急和压缩摘要的模板。结构化来源与每种内置工具结果使用 `prompt/schemas.go` 中显式选择的字段树，经 JSON 文本模板输出；禁止把业务结构体或任意 map 直接序列化成模型提示。新增内部字段不会自动进入上下文；新增工具或字段必须明确它的模型展示契约。

`presentation.go` 在每次实际模型请求前生成独立展示副本，普通请求与压缩请求共用此路径；token 估算和 `model.start` 也使用同一展示结果。检查点、操作回执及历史原始工具结果保持内部结构，供 Skill 激活、消息投递证据和恢复使用。工具调用 ID、参数、角色、媒体及供应商状态仍按模型协议处理；不通过文本模板改写用户原文或供应商推理内容。

权限、偏好和 Skill 元数据不再双重 JSON 编码；文本只保留 JSON 必需的引号、反斜线和控制字符转义，不进行 HTML 转义。省略空的可选字段，但保留有意义的 false、0、空列表和文件空正文。空授权明确表示没有显式授权；空授权请求来源省略，并明确它清空旧请求窗口。`ExpiresAt=null` 表示无计划到期，缺失表示未提供该信息；截断、媒体未加载、未知副作用与失败必须保留。大工具结果保留归档路径、所在沙盒、大小和退出／分页证据，不再注入内部 JSON 的头尾片段。

模板不会为模型重复提供工具定义中的使用说明；来源说明只解释当前状态与其信任边界。工具 schema 以请求 `Tools` 为唯一权威。结构化自动来源格式错误会在模型调用和预算预留前失败，不能伪装成空来源。无法展示的工具结果明确标记不可用，并说明操作可能已完成、不能据此重复副作用。

恢复时即使内容哈希未变，也会重新检查自动通知的展示格式，替换旧格式；旧事件和工具结果在请求边界投影，不改原始持久化证据。记忆来源和记忆工具保持现有行为与内容。做梦使用独立的固定 Markdown system 整理规则和 user 证据批次，不复用普通会话上下文。

## 执行期间的会话加急

WebUI 在助理工作且存在未读用户消息时提供“加急”。工作期间仍可继续发送消息；停止按钮保留。请求使用 `POST /api/assistants/{id}/expedite`，包含 `Mutation`、`ConversationID`、`ThroughSequence`。截至该序号的未读用户消息按发送顺序读取，后续消息需要另一次加急。重复请求幂等，跨所有者、跨助理、已归档会话与未来序号被拒绝。助理已经结束或停止时返回 `not_running`，不恢复执行。

加急请求先落盘，再取消当前模型子请求。工具调用不被强制取消，已运行的工具返回后，未开始的同批调用获得明确的“未执行”结果，随后读取加急消息。正文和附件元数据通过已授权的 `conversation_read` 获取，以用户级输入进入模型，不能提升为系统权限。原任务和已完成工具结果保留。模型调用、工具回复、接管消息及恢复位置持久化，接管的普通消息队列项在当前轮次完成前不会独立执行，轮次确认后一次性消费。加急不绕过停止、权限、额度、上下文或步骤上限。

`AcceptedAt` 继续表示调度接收；`ReadAt` 表示携带消息正文的模型请求已收到供应商成功 HTTP 响应，由可信投递元数据生成。WebUI 使用 `ReadAt` 显示已读，`message.read` 事件通知各客户端刷新。已读不代表已完成。被加急取消的调用仍保存账单证据，已知费用正常结算，未知费用保留待确认。

状态接口的 `Expedite` 包含 `ThroughSequence` 和 `State`：`pending`、`waiting_tool`、`waiting`、`read`。工具执行中显示“已加急，当前操作结束后读取”；执行受限时保留待处理状态。

输入框始终保留发送按钮；执行中在其左侧显示“处理中”ghost 按钮，默认透明背景与 loading 图标，悬停时显示灰色背景、停止图标与“停止”文案，点击中断当前一轮并回到 `idle`。该操作持久化 `user_stopped` 控制事件，并将它连同已完成操作、被中断操作的不确定结果保存进私有上下文。控制事件本身不会触发新的模型请求；后续用户消息、计划、操作完成等普通事件均按正常调度继续执行。停止事务取消此前已产生的待处理事件，并保存中断边界。尚在 IM outbox 的消息、延迟投递或重启后恢复的旧事件也不会唤醒执行；停止后产生的新消息和正常事件仍可唤醒。旧未读消息保留在会话中，但不再自动加入后续加急批次。取消信号仅绑定旧执行 ID。

`Lifecycle("stop")` 是独立的持久停用机制（例如解雇助理），仍使用 `stopped` 状态，不能与输入框中断按钮混用。

## Token 容量与自动压缩

上下文窗口按「用户手动覆盖 `ContextLimit` → 服务商声明 `ProviderContextLimit` → 系统兜底 256K（262,144 tokens）」解析。手动字段以 0 表示未设置，WebUI 留空；兜底只在运行时生效，不写回模型配置。模型目录同时返回 `EffectiveContextLimit` 和 `ContextLimitSource`，资源列表展示数值与来源。服务商刷新会更新声明值，保留手动覆盖。旧版自动发现记录中的 32,768 无法区分猜测与服务商声明，因此先视为未知，刷新模型目录可恢复声明；旧版手动配置保持不变。

每次模型请求的上下文用量优先使用最近一次成功响应的 `InputTokens` 作为基线；缓存 token 已包含在输入计数中，不重复相加。最近的助手响应、新增/变化输入与工具定义补充增量估算，不直接加入可能包含未回传推理的 `OutputTokens`。估算与适配器共用 reasoning 选择逻辑：OpenAI-compatible 不计私有推理状态，DeepSeek 只计当前后端身份匹配且实际回传的 `reasoning_content`，其余不发送的扩展字段不计入。没有基线、切换后端或压缩重建上下文后才建立初始估算；后续请求以新回执更新基线。估算明确标注来源，不等于模型 tokenizer 的精确计数，也不能用于拒绝模型请求、缩小输出额度或拒绝有效摘要。服务商完全缺失必要 usage 时，模型适配器仍明确报错，不将未知费用记为免费。

助理的 `ContextCompressionTokens` 保存 token 阈值，0 表示自动：`min(128*1024, floor(有效模型窗口*0.8))`。自定义值限制在 `min(64*1024, 上限)` 到上限之间，上限为 `floor(有效模型窗口*0.8)`；小窗口固定为上限。执行引擎在安全检查点读取最新助理设置，并按本轮实际模型窗口重新限制生效值。创建、更新和克隆保存此设置；更新省略字段保留原值，0 恢复自动。部署级比例配置已移除。原来的 180/200 条输入及 1 MiB JSON 限制已移除；仅保留 256 MiB 的异常/存储防护上限，不作为模型容量判断。上限检查按单条输入复用 JSON 编码缓冲，只累计长度，不分配完整历史的临时 JSON 副本；计数包含转义、私有元数据及数组分隔符，与完整 JSON 编码长度一致。检查仍验证全部输入，编码错误保持原有优先级；单条输入本身仍需要编码缓冲。

压缩统一由 `context_compression_requested` / `after_step` 事件执行。自动检测在完整模型响应后、工具批次结束后及下一次模型请求前检查窗口，达到助理的 token 阈值时只入队；当前轮次已经结束也消费待处理压缩事件。手动 `/compress` 使用相同投递方式，绕过自动阈值；重复请求合并。实际压缩只在完整工具调用批次结束后执行。摘要请求完整保留当前上下文的消息、自动来源、供应商状态、顺序和工具定义，仅在末尾追加一条 user role 的压缩指令，尽量复用供应商 KV cache；不裁剪近期或较早消息，不序列化切块，不做滚动摘要。摘要输出上限取模型输出上限和窗口 1/4 中较小值，不根据估算输入做容量预检。实际超窗由模型 API 错误码判定，失败保留全部原始上下文。

摘要只接受正常 `stop` 结束且正文非空、无工具调用的结果；`length` 即使已有部分正文也拒绝提交。终止原因保存在模型回执中，已产生的费用正常结算。成功后在同一事务保存新检查点、状态和成功记录：保留基础指令，以标明来源的 user 历史参考消息保存完整摘要，恢复最近 Runtime 事件及当前自动上下文。摘要请求的推理状态只保留在回执/调试证据中。新摘要不因估算偏大而拒绝提交，下一次普通模型响应更新用量基线前不再次自动压缩，手动压缩仍可执行。失败不自动反复尝试；同一历史、模型、工具和输出预算的重试复用已知请求回执，配置变化生成独立请求 ID。

压缩前输入由当前检查点、持久化摘要请求和已采集的工作台历史分别持有引用；不再建立永久的 `agent.context_archives` 副本。事件完成后释放不再需要的请求输入引用，历史按工作台条数策略保留；全部引用释放后后台回收旧分支。压缩失败时当前输入保持不变，聊天记录、工具操作回执和费用凭据不受历史清理影响。

状态接口 `Context` 返回当前窗口、用量来源、token 数、实际 token 阈值 `CompressionThresholdTokens` 和压缩次数；开发工作台可查看上下文用量与压缩记录，聊天页面不再显示上下文占用行。工作台记录 `context.usage` 和 `context.compaction`（原文指纹、压缩前后占用、单次请求策略和保留消息数）。指纹用于关联调试证据，不表示保留永久原文副本。

## 助理唯一当前执行状态

普通聊天、计划触发和手动继续共用 `agent.checkpoints` 中的一份权威当前状态。检查点在接收事件、实际模型请求前、收到完整模型响应、每个工具结果、加急接管和压缩成功等恢复边界递增 `Sequence` 保存，不再等整轮成功后才更新。事件级 `agent.turn_progress` 仅保存版本 2 的助理 ID、检查点版本引用和接管标志，不再保存第二份完整上下文。

Checkpoint 的私有 JSON 增加 `Current`（当前事件、执行 ID、工具定义、模型响应位置标记、工具/模型步骤游标、加急消息处理位置）及 `PendingEvidence`（需再次核对的操作引用）。同一事件的模型重试从该检查点的执行位置继续；服务重启打断运行中执行时，由独立恢复事件接管，已经写入检查点的模型消息直接复用，工具仍使用原操作 ID / 回执；历史 `agent.handled` 仅用于重复投递确认，不能覆盖当前状态。

新事件接手保留最近一次模型返回的 token 用量基线，只估算新增内容，不因切换事件改用更低的全量估算。新事件接手未完成轮次前，先读取本地工具回执：补回已提交但尚未写入上下文的工具结果，为旧响应中未执行的调用补充明确的 `not_started` 回复，对运行中、取消后结果不明及 unknown 操作保留副作用不确定性。模型结果没有独立恢复缓存；尚未进入检查点的响应不补回。恢复过程不执行旧工具队列；新事件按当前指令和新任务身份执行，旧目标只作为历史事实保留。旧事件标记为已被接管，延迟重试不能重新执行它或覆盖新上下文。模型/工具账单及原操作回执不删除，不因接管假定费用为零或副作用已回滚。

停止会把当前上下文、已完成结果、未知操作引用和停止事件一起保存；后续新事件会重新核对迟到回执。工具回复使用可信 `ToolOperationID` 匹配操作，避免不同轮次复用同一模型 tool-call ID 时替换错误结果。所有检查点更新按版本比较，并检查执行身份、停止边界和显式重置时间，拒绝旧执行的延迟写回。显式重置清除当前恢复状态和待核对引用，保留原始会话、操作回执与账单；调试历史按工作台策略保留。

旧部署须先停机备份并通过一次性离线工具转换检查点与待恢复进度；运行时不再导入旧版完整事件快照，发现不支持的存储格式返回错误。做梦仍使用独立批次上下文和进度，不覆盖普通助理检查点。

新增回归覆盖：失败后计划接续已确认事实、工具结果保存失败后从回执恢复且不执行未开始的调用、模型响应尚未写入检查点时重新请求并保留原费用记录、停止后迟到结果、重复 tool-call ID 的隔离、旧执行写回拦截，以及拒绝未转换的旧版进度。既有加急、暂停/停止、重置、预算、做梦与压缩测试继续适用。

## 服务重启后的自动恢复

Runtime 停止时，正在执行的普通任务保留为可恢复状态，不显示“执行已取消”。启动后为每个被中断执行原子创建一个独立的 `resume_requested` 事件，旧作业记为 `interrupted` 并关联恢复事件；尚未领取的恢复事件在再次启动时保留，不重复创建。正常停机记录已知中断时间和 `runtime_stopped` 原因；异常退出仅说明 `runtime_interrupted`，不推断崩溃原因或发生时间。原本已经进入模型退避等待的任务继续原重试计划，保留次数、截止时间和供应商要求的等待时间。做梦仍沿用独立批次及固定截止时间。

恢复事件带入原事件、执行、任务和停止边界引用。接管使用最新检查点及工具回执：补回已完成结果，为未开始的调用补齐 `not_started` 回复，对结果不明的操作保留 `side_effects_possible` 与原操作 ID，然后向模型发送恢复提示。模型输出未完整进入检查点时不补造输出，旧工具队列不重放；恢复执行使用新的身份，保留原任务、已消耗步骤、历史调用和费用证据。新模型请求使用当前权限、模型配置及预算。

恢复提示以私有 user role 输入，要求先读取未读用户消息，再核查文件、命令输出、进程、发布记录或远端状态，按证据继续、修复或安全重试。结果未知本身不阻止模型继续调查，不要求用户处理内部操作状态。恢复成功不生成聊天或失败通知；任务正常交付，只有无法自行继续且需要具体决策或条件时才向用户求助。恢复事件失败使用助理等待提示，不另外重复生成执行失败通知。

用户停止、停用、暂停、上下文重置和较新事件接管均优先于自动恢复。停止判定使用恢复链最初事件的时间及消息序号，不能用新恢复事件的时间绕过停止边界。连续三次恢复执行都没有推进模型步骤或工具游标，再次启动时停止自动恢复并提示检查服务；有执行进展后重新计数。无法读取检查点时仅将对应助理标为恢复失败，不继续使用空上下文。

## 检查点与工作台记录

服务端开启 `debug.enabled` 后，执行期间、轮次结束、用户停止和上下文重置的检查点保存统一采集 `checkpoint.saved`。记录与检查点加入同一持久化事务：版本冲突、事务回滚或提交失败不会留下成功记录，也不会推进调试 revision；提交后通过调试事件流刷新工作台。普通执行进度保存复用上下文存储的规范化内容标识判断变化；完整恢复状态和执行／事件身份均未变化时不写入检查点、不递增版本或修改保存时间，也不采集保存事件和推进调试 revision。版本冲突及停止检查仍先执行。模型调用完成后强制保存，轮次结束、用户停止和上下文重置也保留保存记录；每次实际保存只采集一次。没有运行中轨迹的控制操作创建独立的检查点更新记录。

`checkpoint.saved` 只保存版本、时间、大小、`Cause` 及 `ContextOmitted`，不重复复制完整上下文；`context.build` 在读取检查点后立即采集，尚未加入新触发事件。内部 CAS 校验读取不重复记录加载。历史输入从已采集的 `context.build` 或模型调用上下文读取；最新检查点从当前状态读取。旧记录保留，缺少快照时明确提示未采集，不借用附近模型输入冒充历史检查点。

记录受服务端调试开关、按账号执行条数保留策略、单条负载大小及脱敏规则约束，工作台入口是否显示不影响采集；诊断失败不阻止业务保存，超限数据明确标记，不改变原检查点或原始会话历史。

压缩失败原因区分 `model_context_exceeded`（模型 API 明确返回上下文超限）、`context_summary_truncated`（输出额度截断）和 `context_summary_invalid`（无有效完整摘要），其他模型错误沿用统一请求错误分类。工作台记录失败结束及原文指纹。只识别明确的供应商错误码，不根据估算或解析可能含私有内容的错误正文猜测超窗。

## 统一事件投递

`AssistantEvent.DeliveryMode` 明确事件的介入边界：`interrupt` 取消当前模型子请求，已开始工具返回后为未开始调用补齐未执行结果；`after_step` 等本次模型响应及其整批工具结果完成；`when_idle` 在没有当前执行时按队列领取，不要求队列为空。执行时机与事件处理行为分开，停止控制事件立即结束执行但不发起模型请求。

普通用户消息、定时计划、任务启动／修改／继续和权限决定产生的 `resume_requested` 使用 `when_idle`；加急把选定消息提升为 `interrupt`，仍使用授权读取、已读证据和原任务身份。Shell 完成／运行提醒、操作完成和上下文压缩使用 `after_step`。做梦使用 `when_idle` 并保持低优先级及会话独占，其独立上下文不接收普通上下文的压缩与通知。

事件写入时保存明确方式；旧记录通过 `Delivery()` 兼容解析，领取或消费时写入归一化的作业记录。Scheduler 与 Loop 共用待处理作业筛选、停止边界和同助理串行约束。通知接入与检查点保存处于同一事务；压缩成功的检查点、计数、事件结果及作业确认也在同一事务中提交。加急消息保留现有接管与已读确认机制。服务重启后的普通执行由独立恢复事件接管，使用检查点和工具回执保留事实，不重放旧工具队列。

压缩事件等待期间保持原状态，处理时 `Status.Compression.State=running`，界面显示“正在压缩上下文”；结束后恢复实际状态。结果可为 `succeeded`、`not_needed` 或 `failed`，重试等待期间不显示压缩进行中。摘要错误不替换原始上下文，沿用模型重试、账单及执行限制。

## 当前助理资料

`profile` 自动来源在每次模型请求边界读取当前助理的名称、状态、头像摘要及资料 `Version`，随用户手动修改和 `profile_update` 成功结果更新。固定 `Source=profile`、`Scope=assistant`；自定义图片只包含类型和摘要，不把 data URL 注入上下文。使用工具时提供此版本；冲突先检查返回的 `current_profile`，不得盲目覆盖。提示词投影为 profile 来源、成功回执及冲突详情分别配置白名单。

## 本地共享文件来源

Runtime 同时从本地 `/global` 与 `/work` 按上述固定入口和访问范围发现 AGENTS.md，并浅层发现 `.agents/skills/*/SKILL.md`，路径及作用范围保留原前缀，共享来源在助理来源之前组合。Skill 只有对应本地 file_read 成功才加载正文，远程结果不能激活本地技能。记忆独立作为参考数据，仅根目录 MEMORY.md 摘要自动加载；详细文件通过通用 file_search/file_read 主动检索。最近的文件读取／搜索引用按路径核验版本，变更或删除后旧片段失效。远程电脑不参与自动发现。详见 [文件记忆](dream-memory.md#文件与上下文)。

## 内置文档 Skill

`molr-docs` 从二进制内嵌的只读 `/molr/.agents/skills/molr-docs/SKILL.md` 提供，所有账号和助理共用同一份资料，不依赖本地工作区、沙盒或资源授权。执行身份和文件策略仍在读取时校验。初始上下文仅包含元数据，成功的本地 `file_read` 激活完整 Skill；元信息读取、失败结果、远程结果和同名工作区 Skill 不激活内置正文。来源路径区分内置、账号共享和助理技能。

资料包只包含 `docs-routes.json` 显式登记的中文文档，官网仍发布中英文。正文由 `docs/` 和 `docs/dev/` 生成，索引区分中文正文路径与中英文标题、主题和公开链接；引用默认匹配回答语言，用户指定文档链接语言时优先遵从，不从中文正文链接推断引用语言。生成命令为 `npm run docs:generate`；生成文件随代码提交，`npm run docs:check`、CI 和发行构建检查源文件与资料包一致。直接 Go 构建与 Docker 构建使用已生成资料，无需运行时访问仓库或网络。

文件工具支持内置路径的读取、列举、搜索，并拒绝写入、编辑、移动、删除、远程和 Full Access 路径。内置路径不是 Shell 挂载。文档正文分页上限为 12 KiB，搜索结果也限制为 12 KiB，保留续读和截断信息，避免依赖工作区归档。资料包摘要随任何正文、索引或 Skill 变化而更新；恢复的已加载 Skill 使用当前正文，并要求版本变化后重新读取相关参考资料。
