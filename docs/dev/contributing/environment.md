# 开发环境

本文维护开发机器目录、共享下载缓存和开发服务约定。任务隔离见[协作流程](workflow.md)，验收实例与交付要求见[验收规范](acceptance.md)。

## 开发机器目录与共享下载缓存

每台开发机器（包括通过 SSH 使用的远程机器）推荐将源码主工作目录放在 `~/workspace/molr.ai`，将开发运行资料放在独立的 `~/workspace/molr`，共享下载固定使用 `~/workspace/molr/.cache`。`~` 指实际执行命令的机器上当前用户的主目录。已有仓库可以保留原路径；使用 Molr 开发自身时，将源码仓库作为沙盒外部目录接入，源码树与实例私有运行目录必须互不包含。

| 内容 | 固定目录（相对于 `~/workspace/molr/.cache`） |
| --- | --- |
| npm 下载缓存 | `npm/` |
| Go 模块与自动下载的 Go 工具链 | `go-mod/` |
| Electron 二进制下载缓存 | `electron/` |
| Electron Builder 下载缓存 | `electron-builder/` |
| Playwright 浏览器 | `ms-playwright/` |
| 其他工具链、安装包和可复用下载文件 | `downloads/<工具>/<版本>/<系统>-<架构>/` |
| 需要解压后复用的独立工具链 | `tools/<工具>/<版本>/<系统>-<架构>/` |

- 所有任务、worktree 和重复验收均复用当前机器的固定下载缓存。通过工具支持的缓存选项或环境变量传入展开后的绝对路径，不使用随当前目录变化的相对缓存路径。例如 npm 使用 `npm_config_cache`，Go 使用 `GOMODCACHE`，Electron 使用 `electron_config_cache`，Playwright 使用 `PLAYWRIGHT_BROWSERS_PATH`；安装和运行时使用相同设置。配置仅作用于相关命令或开发会话，不擅自改写用户全局配置。
- 下载前先检查固定目录和该工具已有的默认缓存。已有文件匹配所需版本、系统、架构及工具提供的完整性校验时，优先复用，并将可复用文件归入固定目录；缺失或校验失败时才重新下载。使用工具自身的缓存锁和完整性校验；手动下载先写临时文件，校验后原子替换，避免其他任务读到未完成的文件。同一下载进行中时等待或复用该任务，不再启动重复下载。
- 共享范围包括下载包、工具管理的模块缓存及按版本安装的公共工具。`node_modules`、应用构建产物、编译缓存、测试输出和验收实例数据仍归各 worktree 所有；不得通过共用可写安装目录破坏任务隔离。数据库、凭证、登录会话和用户资料不进入共享下载缓存。
- 缓存独立于任务生命周期，清理 worktree 或临时验收目录时保留共享下载。需要清理缓存时，仅处理已确认损坏或不再使用的条目，不清空其他任务可能正在使用的目录。

## 实例私有目录与源码隔离

主服务与验收实例的配置、数据库、密钥、登录会话、助理工作区、运行缓存和日志存放在源码树外。以下路径为推荐布局；已有仓库外的受管安装目录可以继续使用，避免为统一名称搬迁程序和配置。

| 内容 | 推荐位置 |
| --- | --- |
| 主服务私有文件 | `~/workspace/molr/instances/main/` |
| 独立任务验收实例 | `~/workspace/molr/instances/acceptance/<task>/` |
| 唯一的开发环境备份与回退副本 | `~/workspace/molr/backups/latest/` |
| 项目需求、研究和推广等内部资料 | 源码仓库根目录的 `internal-docs/` |

- 每个实例使用独立目录，记录其任务分支、源码 worktree、服务名、端口和实际路径。目录在仓库外不改变任务隔离及验收清理责任；不得共用数据库、密钥或可写助理工作区。实例目录不是共享下载缓存。
- 源码、`node_modules`、构建产物和编译缓存可以留在 worktree。运行中的 Runtime/helper 应部署到仓库外实例或受管安装目录，避免开放源码写权限时连带开放正在运行的程序。前端开发服务可以继续以源码目录为工作目录，私有日志和会话文件写入对应实例目录。
- 使用 Molr 开发自身时，项目需求、研究和推广资料继续保存在仓库根目录 `internal-docs/`，可供获授权的开发助理使用。将 Runtime 数据库、密钥、登录会话及运行备份与源码分开，避免仓库路径与沙盒受保护目录重叠；不得因此整体搬迁内部文档。Git 忽略和公开发布规则继续适用，沙盒目录授权不改变仓库的发布范围。
- 迁移既有实例时先盘点实际进程、配置及安装记录，正常停止对应实例，再复制完整数据并校验摘要、权限和数据库完整性。同步更新配置、安装记录及启动入口中的路径；保留原安全设置、账号和会话。备份与回退副本也必须位于拟接入沙盒的源码目录之外，不在旧位置保留私有数据或指回新位置的软链接。
- 重启后按[Runtime 验收](acceptance.md#runtime-构建与沙盒验收)验证 HTTP 就绪、已有会话及已认证的沙盒能力；配有 WebUI 时同时验证代理。最后通过实际目录添加流程验证源码根可接入，且新实例私有目录仍被拒绝；验证使用的临时资源在完成后断开，不授予助理权限。

### 验收资料与备份保留上限

- 验收资料只服务于当前任务。等待用户验收或合并期间保留所需实例和记录；合并并确认主服务生效，或任务明确结束后，删除该任务的验收数据库、账号与登录文件、日志、截图、录屏、测试输出、临时程序和安装包。历史验收资料无需保留，不另建归档、不打包转存，也不随 `internal-docs/` 搬迁继续积累。
- 本开发环境最多保留一份最新已验证的完整备份，统一放在 `~/workspace/molr/backups/latest/`。数据、必要配置、密钥和匹配的程序属于同一恢复集；不得按任务或日期再保留多份回退目录、数据库副本或 `.previous` 文件。生产部署的备份策略不由本开发约定替代。
- 更新备份时先在临时目录生成一致性副本并校验文件摘要、权限、数据库完整性及恢复所需文件，再替换唯一保留备份并删除旧份和临时文件。切换完成后的保留数量必须不超过一份；新备份校验失败时保留原有效备份，删除失败的候选副本。
- 清理前核对任务状态、进程和实际路径，不删除运行实例、等待验收的资料、共享下载缓存，以及产品需求、研究、推广文案等非验收成果。长期有效的技术结论整理进负责该主题的文档；当次验证结果在交付消息中说明，无需永久保存完整验收过程。

## 开发与预览服务

- 本地日常开发只使用开发服务。主工作区常驻 WebUI、官网、UI Design 各一个实例，不同时运行同一应用的构建预览或重复开发实例；官网首页和文档共用同一个官网服务。
- 以下默认端口适用于主工作目录；独立 worktree 按任务需要使用各自分配的空闲端口，每个涉及的前端应用同样只运行一个开发服务。下文的“仓库根目录”指当前任务 worktree 的根目录，主分支服务则使用主工作目录。
- 启动前核对进程所属目录、命令和监听端口。已有符合要求的服务就复用；切换启动方式时停止同一工作区的旧实例，不通过另开端口保留重复服务。
- 开发服务默认监听 `0.0.0.0`，允许同一局域网内的设备访问。除非用户明确要求，否则不要绑定 `127.0.0.1` 或 `localhost`。

| 应用 | 仓库根目录启动命令 | 主工作区端口 |
| --- | --- | --- |
| WebUI | `npm run dev`（或 `npm run dev:webui`） | `5191` |
| 官网及文档 | `VITE_SITE_MODE=live npm run dev:website` | `5189` |
| UI Design | `npm run dev:design` | `5188` |

- 官网本地开发和验收在启动命令中显式带上 `VITE_SITE_MODE=live`。未设置该变量或留空时，程序仍使用 `coming-soon`；检查其他模式时调整同一实例的环境变量并重启，不另起常驻服务。
- 现有 `build`、`preview` 等命令保留，构建预览仅用于明确需要验证产物的临时检查，检查完成后停止，不作为日常开发或合并后的常驻服务。官网预览沿用构建产物中的模式。
- 启动或调整后确认实际监听地址、端口、开发模式和实例数量，并提供可用的局域网访问地址 `http://<本机局域网 IP>:<端口>`。
