# 前端架构

WebUI 管理账号会话、导航与页面装载；SDK、Host 和共享 UI 包分别维护协议、主题解析及基础组件。

桌面入口位于 [`apps/desktop`](../../../apps/desktop/README.md)。可信管理界面负责连接和本机服务；独立、启用沙盒的 Electron `WebContentsView` 加载所选 Runtime 自带的 WebUI，每个连接使用独立持久化会话。远程主页面仅通过独立 preload 获得受限的 `window.molrApp` 接口，不能调用桌面管理 IPC；插件子 frame 不获得该接口。Linux、macOS 和 Windows 包均携带独立原生 Runtime，由安装器管理专属实例。关闭桌面窗口不停止服务。

## 实现边界

- `packages/sdk` / `@molr/sdk`：Runtime 客户端、DTO、分页、幂等写入、上传下载、错误、SSE 和 UI/Host 协议，不依赖 React 或 `@molr/ui`。
- `packages/ui-host` / `@molr/ui-host`：固定版本主题身份、主题拥有的页面映射、插件主题类型。
- `apps/webui/src/App.tsx`：登录、导航、主题解析与页面加载、故障恢复。
- `apps/webui/src/ui-host/ThemeSelector.tsx`：主题设置中的主题选择器。
- `apps/webui/src/interfaces/official`：默认主题和原有产品组件。

`@molr/ui` 提供官方共享组件、CSS 变量和资源。修改共享契约时同步检查 WebUI、官网和 UI Design 的调用点；项目尚无稳定版，不保留额外的旧版兼容层。

官方助理、计划、资源、设置、工作台页面及聊天侧栏、渠道连接弹窗按需加载。`OfficialPage` 负责路由、全局搜索和共享的助理列表、账号设置、服务状态查询；`AssistantsPage` 管理聊天、列表排序及专用查询和面板操作。离开助理页释放其订阅，路由壳保留列表筛选、浮窗偏好和文件浏览记忆；全局导航与通知所需的会话订阅继续保留。搜索任务通过 `panel=tasks&task=…` 路由定位，支持首次加载和刷新恢复。`lazy-pages.spec.ts` 验证生产模块边界、查询范围与搜索跳转。工具栏按钮的轻量状态订阅与面板代码分离。通知提醒关闭或通知属于首次快照时，未展示的通知不再单独读取详情；同一通知的并发变化按版本串行合并，新版本保留后续读取。已经展示的通知仍同步已读、关闭和恢复状态。

共享查询保留未变化 JSON 子树的引用，不能只凭领域版本号忽略实时状态字段。`useQuery` 继续发布加载和错误状态；仅展示计数的工具栏通过 `useQueryValue` 订阅原始子树或基本值，后台刷新和无关字段变化不触发其重渲染。助理导航项独立订阅未读总数，会话更新不再带动工作区宿主重渲染。权限失效仍清除数据。`query-store.spec.ts` 与 `query-selection.spec.ts` 覆盖引用复用、加载反馈、计数变化及访问撤销。

聊天页通过 `useChatChannel` 读取 `/api/assistants/{id}/chat-channel` 的绑定摘要，一次请求替代六个渠道详情查询，不加载投递历史。服务端在同一授权快照中判断已确认绑定并保留显示优先级；未取得摘要时保持输入保护，未确认配对不等同于已绑定。渠道变更事件和操作同时刷新摘要；连接弹窗继续按需读取各渠道详情。

桌面主进程的 `RuntimeSession` 管理当前视图的加载／握手、超时、首次登录许可及通知和 OAuth 清理。连接替换或关闭时统一释放旧视图，旧视图的回调不能完成新连接；IPC 身份与来源校验继续由主进程入口负责。

## 共享状态与恢复

`query-invalidation.ts` 集中维护查询路径、SSE 事件、写入操作与刷新主题的映射，以及主题间的单次依赖扩展。映射函数不发请求、不修改缓存；`DataProvider` 继续负责消息版本标记、通知订阅者和合并刷新。消息反馈仍按消息／会话更新，终端与浏览器高频输入不触发无关列表读取，未知事件沿用原有刷新兜底。`query-invalidation.spec.ts` 固定这些范围，聊天同步和主题订阅回归验证实际请求与渲染行为。

查询主题的版本由账号作用域内的 `TopicStore` 保存，查询 effect 直接订阅主题，读取 store 的当前版本并调用 `QueryStore.refresh`，版本变化不发布 React 状态；React 仅订阅查询快照或选中的值。首次同步在注册主题监听后读取版本，路径切换或卸载时释放监听。需要展示版本本身的视图仍可使用 `useTopicVersion`：局部主题只通知对应订阅者，领域主题同时通知其局部订阅者，全量刷新通知全部订阅者。同批变化合并通知；无人订阅时仍保留版本，重新订阅可读取当前状态。`DataContext` 保持稳定引用，连接状态通过独立的 `useConnection` 订阅；消息变化不会仅因 Context 更新让无关页面重渲染。账号切换重新创建数据作用域，SSE 握手与断线恢复继续触发全量刷新。`topic-subscriptions.spec.ts` 检查渲染次数、查询请求、取消订阅及账号隔离。

主题切换不影响 Runtime 中的助理、消息和任务。聊天草稿以 `{ text, files }` 格式按账号和助理 ID 存储于管理壳的内存和当前标签页 `sessionStorage`，草稿由独立 `DraftStore` 按助理订阅，每次输入只持久化当前助理的条目，不更新主题宿主 Context。聊天历史直接订阅消息主题并安排增量读取；消息、游标、元数据和错误未变化时保留快照，后台校准不切换首次加载状态。`interactive-updates.spec.ts` 验证草稿订阅范围和空刷新渲染次数。默认聊天的 `ChatComposerContainer` 独立订阅草稿，管理上传、发送、停止和斜杠命令；`Chat` 保留历史、滚动、定位与已读逻辑，发送成功通过回调恢复最新消息跟随。输入和附件草稿更新不触发历史消息遍历；`chat-composer.spec.ts` 在实际聊天页统计组件渲染次数，`chat-send-navigation.spec.ts` 验证异步发送后的导航与草稿保护。其他临时页面状态由各页面管理。

默认主题的当前助理由路由 ID 决定；`/#/assistants` 保持未选择状态，不回退到首个助理。列表操作通过导航更新 URL，再打开对应会话。

页面加载失败时保留壳的导航，并提供恢复默认主题与主题设置入口。恢复默认主题会先更新账号设置，成功后重新载入应用，清除浏览器缓存的模块加载错误；Runtime 暂时不可用或保存失败时，保留当前会话内的默认主题恢复，不刷新页面。正常 API 错误由业务页面处理。

周日历由 WebUI 的 `PlanWeekCalendar` 渲染，计划页默认进入周模式，聊天内嵌计划仍使用清单。周／月模式按可见日期范围读取同一计划接口，重复发生沿用 Runtime 的投影与事件标识。时间轴使用浏览器本地时区，按本地日期拆分跨天事件，以最小可点击高度计算重叠分栏；无结束时间的事件仅标记发生时间。切换日期按日历日期运算，跨夏令时不假定每天都是 24 小时。颜色复用共享计划类型 token，并以图标和状态样式辅助辨识。

## 后续扩展预留

外部页面和主题统一通过 `connectPlugin()` 使用[插件机制](../extensions/plugins.md)的能力契约。宿主支持内置页面和已安装插件贡献。

插件主题可以使用或不使用 `@molr/ui`，只需遵守 SDK/Host 契约。远程页面必须经过来源与权限确认；不能仅修改浏览器配置就获得执行权限。页面映射始终由主题定义，用户仍然只选择主题。

插件页面使用隔离 iframe 和私有 MessageChannel。`PluginFrame` 逐项检查命名操作及贡献声明的能力，不向页面传递宿主 Cookie、CSRF 或 Bearer；Runtime 校验已安装内容及权限。

## 桌面 App 模式

Electron 在连接前后保留内置连接管理界面。连接 Runtime 时，独立且启用 Chromium 沙盒的 WebContentsView 通过专用 preload 向主页面暴露 `window.molrApp`；接口类型定义在 `@molr/ui-host/app`。WebUI 的 `AppFrame` 在认证门禁和页面主题之外完成握手，显示拖动区域、窗口控制与切换连接。语言、配色和明暗模式继续使用公共 Provider。普通浏览器没有桥接接口，保持原有网页布局。

App 模式的完整字标位于标题栏，工作区的连接状态和重试功能随字标一起呈现，左侧导航从顶部开始排列。登录页背景延伸到透明标题栏。连接管理页和 WebUI 标题栏在所有平台、全屏与非全屏下都固定为 48 CSS px，Logo 和右侧操作按钮垂直居中。macOS 使用 Electron `titleBarStyle: hidden` 与 `titleBarOverlay: true` 保留原生红黄绿按钮。主进程启动时从可信内置页面的原生安全区域测得按钮高度，再按当前页面缩放计算等距的上、左边距，使原生按钮在 48px 标题栏内居中；原生坐标取整时允许不足 1 个逻辑点的误差。页面缩放引起的 viewport resize 由 preload 通知主进程，通知不携带尺寸参数，主进程读取真实缩放值。非全屏通过 `env(titlebar-area-x)` 为 Logo 避让按钮；全屏时取消按钮专用留白，Logo 使用普通的 16px 左边距。按钮实际尺寸不在业务代码中硬编码。Windows/Linux 继续使用右侧窗口按钮。

标题栏中的网页内容属于应用模态范围：对话框和抽屉遮罩覆盖整个窗口，打开期间网页标题栏控件与其余背景内容一同不可交互。macOS 原生窗口按钮由系统管理，仍可用于关闭、最小化和全屏。

内置连接管理页使用共享完整 Logo 的昼夜动态版本，遵守系统减少动态效果设置。桌面维护操作与 App 标题栏操作失败复用共享 Toast，不插入占用页面布局的错误块；安装器详细输出仍保存在维护日志中。

桌面主进程校验当前 WebContents、主 frame、已配置连接来源和参数。远程页面能读取当前连接、控制当前窗口、断开及发起下述 OAuth 流程；连接增删和本机服务管理仍由内置 UI 的独立接口负责。插件及自定义主题 iframe 不获得桌面接口。远程视图填满无边框窗口，加载失败、崩溃或握手超时回到内置恢复界面。断开保留连接分区与登录状态，不停止 Runtime。

主进程在创建窗口后读取连接存储中的 `lastConnection`，复用对应持久化分区恢复连接，覆盖进程重启和 macOS 关闭窗口后重开。仅发起连接时保存选择；主动返回管理页清除选择，关闭窗口及加载失败保留选择。新增连接不会自动选中，删除所选连接会清除选择。恢复使用正常连接与故障恢复流程，不自动启动已停止的本机服务。

认证通过后，`AppAppearanceSync` 在账号的数据作用域内订阅已保存的 `/api/settings`，通过 `setAppearance` 同步配色和显示模式。主进程只接受当前服务主 frame 的固定枚举值，原子保存到桌面配置目录的 `appearance.json`；连接管理页启动时先读取外观和平台，再挂载界面。返回列表及重启保留最近一次登录服务的偏好，“跟随系统”保存为 `system`，不固化成某次解析的明暗值。登录页和保存失败的设置不覆盖桌面偏好，桌面同步不反向修改服务设置。连接管理页 Logo 右侧不再显示附加文案。

安装时，管理员凭据经可信管理 IPC 和子进程标准输入传给安装器，不进入连接存储、命令行参数或日志。安装完成返回列表，一次性链接仅短暂保存在主进程内存。首次打开对应本机视图时，`consumeInitialLogin` 提供一次性的自动兑换许可；许可绑定该视图与安装导航，其他连接和普通 URL 参数不能开启自动兑换。重载或链接过期后使用正常登录。

## 桌面通知

应用图标未读数通过同一 scope 的 `setBadge(scope, count)` 更新，`end(scope)` 在退出时清除并结束该 scope，旧 scope 的清理不能影响后续登录。主进程仅接受非负安全整数，不接受页面提供的图片或路径。Windows 在主进程生成固定红白数字叠加图标；macOS/Linux 调用 `app.setBadgeCount`，Linux 包的 `desktopName` 与实际 desktop 文件一致。WebUI 独立的角标开关默认关闭；启用时通过支持后台运行的串行轮询读取未归档会话未读总数，消息、会话和助理事件触发刷新，每 30 秒补偿遗漏事件，保留请求退避。普通 UI 查询仍只在前台轮询。

WebUI 的 `NotificationAdapter` 在 App 中选择原生适配器，通过 `molrApp.notifications` 调用主进程的 Electron Notification；浏览器继续使用 Web Notifications。现有桌面通知开关触发系统通道初始化，主进程不再为 Runtime 弹出自定义通知授权框，也不依赖网页的通知权限。macOS 的通道初始化可能触发系统授权，因此不在页面加载时调用 `Notification.isSupported()`；该返回值仅表示通道支持，不能显示为系统已授权。

每次登录生命周期使用独立通知 scope。主进程校验当前页面、主 frame、连接来源、scope、文本长度和内部路由；退出、导航、断开及关闭开关清理通知。保留原生对象以支持已读撤回和过期点击隔离。发送等待原生 show／failed 事件并限制等待时长，失败回退应用内提醒；系统专注模式可能抑制展示。状态与测试结果放在对应设置行中。macOS 原生授权、展示和点击需使用签名 App 验收。

## 桌面 OAuth 回调

主页面通过 `window.molrApp.oauth.authorize(providerID)` 发起已注册服务的授权，通过 `oauth.cancel()` 取消等待。`authorize` 返回 `{ status, attemptId?, connectionId? }`；`status` 为 `connected`、`cancelled`、`failed` 或 `unknown`。调用不会返回授权码或 token。普通浏览器与 iframe 不拥有这一接口。

客户端先监听临时 `127.0.0.1` 端口，再用当前连接分区的会话和 CSRF proof 请求 Runtime 准备授权。Runtime 管理 state、nonce 和 PKCE，客户端原生对话框展示授权网站及目标连接，随后打开系统浏览器。监听器只接受匹配 Host、路径、state 的单次 GET 回调，将白名单字段直接提交到固定 Runtime 接口。主进程逐次检查当前视图和登录身份；切换连接、主页面导航、关闭窗口、取消或超时都会关闭监听器。请求体、回调地址与凭据不写日志，也不传给插件。

本机与远程 Runtime 使用同一流程，包括用户已明确启用的局域网 HTTP。授权码在客户端与 Runtime 之间传输，token 由 Runtime 服务适配器换取并保管；这不为 HTTP 增加传输加密。回调失败或状态未知不自动重试换取 token。已注册管理员使用的 ChatGPT 适配器；授权方法可传入连接 ID、版本、名称和敏感操作验证凭据。契约及适配器职责见 [HTTP API](../reference/http-api.md#桌面-oauth-授权)，运行方式见 [Desktop README](../../../apps/desktop/README.md#local-oauth-callback-and-runtime-handoff)。
