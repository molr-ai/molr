# 资源授权额度

本页的计算、网络及文件系统硬配额适用于 Linux。macOS 计算授权只保留时长，网络使用无额度的授权开关，工作区不支持容量配额；用户组仍可限制任务并发。网络撤权会终止使用该授权的受管进程组，不采用 Linux 的连接层动态更新。节点能力、接口值和边界见 [macOS 原生命令权限](../../admin/sandbox/macos.md)。

2026-10-03：已加入账号隔离、管理员用户组与成员独立配额；共享资源目录及双层检查见[多用户与成员配额](users-and-groups.md)。

更新：2026-10-02。当前实现与验收边界以本文和测试为准。用户操作见 [资源与权限](../../user/guides/permissions-and-budget.md#计算网络与工作区额度)。

## Full Access 例外

计算授权 `Scope.FullAccess=true` 仅允许 `execute`，禁止 `Constraints`、`Temporary`、路径／模型范围和只读选项。它与同一资源的普通计算授权独立存在；普通调用只匹配普通授权，显式 Full Access 只匹配 Full Access 授权。修改授权不能借此叠加普通额度。

Full Access 调用不应用计算、网络、工作区及组并发配额，不计入普通任务十个并发上限。外部系统已有的限制仍然有效。组引用的 `AllowFullAccess` 默认 false，管理员明确委派后普通成员才能授权；移除委派使已有 Full Access 权限失效。普通调用仍按下述额度执行。

## 模块职责

`internal/quota` 统一模型预算核算、网络账本、调用额度统计和周期计算。`policy` 保留身份／授权检查，通过 quota 完成费用预留；模型预留、工具进入 Running、插件 HTTP 调用登记继续与相应额度检查共享原事务。`auth` 管理组额度配置，`app` 负责身份与资源解析、服务装配和返回展示数据。cgroup、网络网关和文件系统 project quota 仍在执行端生效，数据库不替代内核硬限制。

模型、工具和插件 HTTP 调用的额度占用跟随本地调用生命周期：模型仅 `reserved` 占用预留与并发，工具仅 `running` 占用并发，HTTP 连接的 `prepared/running` 占用并发。调用退出时正常结算或记为 `unknown`；`unknown` 保留结果／费用未知证据及原周期调用次数，但不再占用费用预留、并发或跨周期调用额度，也不授权自动重试。`released` 仍只表示已证实未收费，与未知费用区分。未知费用后续取得可信回执可幂等补结算，费用归入原调用周期。

模型统一通过退出收尾路径读取持久化回执，取消上下文不跳过收尾。Runtime 获得独占锁后、调度工作线程启动前，先补结算旧预留的已有回执，再将遗留本地占用结束；持久化结果和后台 Shell 任务保留，由各自现有恢复逻辑处理。不增加租约、续期或定期清理。并发表示本地在途调用，不能保证失联的外部服务已停止执行。未知费用释放可能导致少量实际消费未被统计，这是个人预算保护的明确取舍。网络流量账本和存储额度维持各自现有规则，不随调用未知状态自动退款。

额度查询使用数据库侧账号／资源／状态／时间筛选和复合索引。工具和插件 HTTP 调用通过覆盖索引计数，不向业务层读取调用记录；周期计数、活动计数和未知结果计数共享同一事务快照，周期边界使用纳秒精度 UTC 私有时间键。周期外的活动调用额外计入调用量，`Carried` 单独标示该部分；周期内的活动调用只计一次，`unknown` 只计入其发生周期。显示与准入复用 `ModelTotals` / `CallTotals`，成员额度按用户累计，组 ID 和 Grant ID 都不是账本身份。模型金额统计及汇率逐调用向上取整语义保留。

网络账户按稳定账户键直接读取数据库记录；同一执行端事务协调所有层级。用量读取复用调用上下文中的事务，不创建独立事务或持锁等待数据库；查询计算周期变更视图，下一次预留持久化变更。连接槽位不持久化，重启依旧终止旧执行。

## 数据与审批

`policy.Grant.Constraints` 将计算、网络、存储额度与 `Scope` 分开；普通计算、网络及 managed-workspace 授权必须显式提供额度；模型、工具与外部目录范围授权不需要额度。`Temporary` 在指定时间前替换基础额度，到期恢复。`PermissionRequestInput` 支持 `grant_id`、`grant_version` 和最多七项 `additional_requests`；主申请加附加项在一个数据库事务中创建或修改授权，审批重试幂等。创建审批请求前逐项校验真实 `resource_id`、资源类型、支持操作、模型归属和已有授权版本；不接受只填写描述的请求。错误通过工具结果的 `ok=false`、`error.field` 和 `error.message` 返回，附加项字段带 `additional_requests[i].` 前缀。校验失败不写入请求、聊天卡片或幂等收据，不触发 `permission_pending`。批准时继续按用户最终填写值重新校验。原申请、最终 `Granted` 与 `GrantedAll` 分别留存。运行任务失效处理在组合审批事务提交后执行，失败回滚不能提前终止任务。

权限请求列表最多读取 200 条，模型上下文最多读取 40 条，均在同一读取事务内优先取待处理项，再按创建时间倒序补足已处理记录；同一创建时间按请求 ID 升序。创建请求只读取该助理的待处理项，先复用相同请求，再检查 20 条待处理上限。

`permission_list` 与模型上下文保留授权版本、额度、用量及可申请能力。前端三种授权入口共用额度表单，支持临时额度；组合卡片逐项预填、折叠编辑并一次批准，顶层授权时间统一应用到全部子项。`GET /api/resource-usage?assistant_id=…&resource_id=…` 验证所有者和助理绑定后读取本机或远程用量。该查询在数据库中排除撤销、过期及 Full Access 授权，按键顺序只读取第一条有效普通授权；授权选择与临时额度计算使用同一时间点，无匹配时不返回普通额度。

## 计算

新授权为同一 owner/assistant 在当前沙盒创建共享父 cgroup，每个执行为其子 cgroup。CPU、内存、进程／线程在父级累计限制；`temp_bytes` 限制单次执行的 `/tmp` tmpfs 内存临时盘，实际写入计入计算内存，随该次执行清理；它不占用 `/work` 的持久存储配额，界面明确标为“内存临时盘 /tmp”。实际超时也作用于单次执行。CPU 单位为百分之一核。计算修改停止相关任务，新任务使用最终批准值；当前不承诺无中断地延长已启动进程的截止时间或提升其 RLIMIT。

部署 `authorization_ceilings` 与沙盒基础保护配置分开，Runtime 和远程后端分别验证。重启回收共享父组中的遗留执行，不复用仍在运行的旧进程。

GPU 设备访问放在 `ComputeConstraints.gpu.device_ids`，缺省／空列表不授权 GPU。该字段是硬件范围，不是显存或算力额度。部署及用户组范围均校验基础配置与临时配置；修改、撤销和临时配置到期沿用计算任务终止规则。助理申请保留完整计算配置，普通 Shell 根据 `compute_id` 自动获得有效设备集合。任务数量沿用普通执行并发限制，不新增 GPU 并发账本。

## 网络

`network_mode` 缺省为自动，`none` 明确关闭出站网络。Runtime 根据当前助理、沙盒、有效授权和真实部署目标生成网络映射；模型工具不再暴露 `network_ids`。旧调用可携带明确的 ID 子集，但它不是授权，仍需实时检查。

每个实际连接按部署规则的稳定顺序选择唯一网络来源；不会因额度耗尽换用另一个来源。账本键是 owner/assistant/实际网络来源，不使用 Grant ID，防止新建授权或重复连接资源清零。流量使用双向转发载荷口径，DNS 请求与响应计入解析时选中的有效网络来源，调用解析器之前先取得查询额度；端口转发不属于此出站额度。

网关通过已有可信控制通道向父进程申请流量预留和连接槽位。持久化预留先于写入，结算后释放未用部分；读方向在收到数据后、交付前扣额度，避免闲置读预占导致 TLS 死锁。失败未结算预留仍占用后续周期额度。账本由 `internal/quota` 管理，保存在实际执行端的 SQLite：本机使用 `runtime.db`，独立 Sandbox 使用 `sandbox.db`。助理和成员账户的预留、结算在同一事务提交；连接槽位仍随 Runner 生命周期管理。调用量有界，当前每次最多 64 KiB；尚未做更大吞吐批量预取优化。

每日／每周／每月按固定 IANA 时区的自然周期计算，每周从周一开始，DST 使用实际日历边界。基础周期与时区不可编辑，临时额度必须使用同一周期。改变金额不会清零历史消耗。并发槽位由同一个沙盒 Runner 共享；连接结束或执行销毁释放，重启终止旧执行。

额度模块在进程内最多复用 64 份已解析的命名时区，预算校验和周期计算共用一次加载结果。周期边界仍按每次调用的当前时间计算；账户时区变更立即使用新时区，`Local` 沿用当前宿主时区。

网络撤销和到期在连接层检查，不并入整个 Shell 的截止时间。闲置 TCP 连接也定期重查；远程 Runtime 通过租约续约链路更新当前授权。网络额度调整不取消计算任务。

## 工作区

内置工作区登记为 `managed-workspace` 存储资源，仍使用同一助理的 `/work`。容量支持依赖已预配置的 Linux project quota；申请和界面明确区分该能力与旧版单文件／磁盘低水位保护。`resourcequota.ApplyWorkspace` 校验目录项目身份与已有文件归属，使用内核字节和 inode 硬配额；Shell 禁止更改项目归属的 ioctl 与 quotactl。文件工具、导入和 Shell 共用此文件系统边界。

选择助理的工作区额度时，先使用共享资源目录的账号定位工作区资源，再按调用账号、助理和该资源筛选授权。此步骤只加载当前工作区的授权，保留历史记录用于有效授权优先和到期／撤销后的基础容量回退。用户组共享容量另由组额度检查校验。

Runtime 不为已有目录自动创建 project ID，不自动提权或重新挂载。默认用户服务上的该能力可能不可用，必须明确报告，不把定期目录扫描当成硬限制。原 10 GiB 配置只作用于上传附件库；外部共享目录仍由其资源和部署管理。临时扩容到期恢复基础限制，既有文件保留。

## 远程与迁移

能力协议版本为 8，传输端点继续沿用 `/v2/sandbox/` 路径；版本协商显式拒绝旧后端，避免丢失新额度字段。请求携带可信的计算、网络和工作区约束，后端再次执行部署边界校验。`quotas` 控制请求绑定已存在的执行身份，仅更新原映射内的网络授权，不添加新的网络目标。

计算、网络及 managed-workspace 授权必须明确包含 `Constraints`。创建和编辑接口拒绝缺失额度，执行选择和远程后端拒绝缺失计算／网络额度，不提供部署限额回退。已有旧授权通过一次性数据维护直接删除，Runtime 不保留启动清理、迁移或转换代码。模型／工具、外部目录范围权限及审批历史保留。自动网络选择按实际来源去重，采用最近更新的额度授权。网络历史用量与未结算预留存于各执行实例的数据库，数据库快照包含该账本；远程执行端仍须独立备份。

## 授权有效期

组合申请在顶层填写 `expires_at`，子项继承它；审批使用顶层 `ExpiresAt` 作为整组有效期，`null` 表示永久。临时额度恢复时间独立保存，不能晚于授权到期。申请创建前逐项验证资源存在性、归属、类型、操作和额度，失败不产生审批记录或卡片。

## 验证方法

Runtime 测试覆盖并发预留、跨周期结算、事务回滚、撤权和组合审批。真实 Linux 沙盒专项检查多个执行共享计算限制和网络用量；工作区硬容量需要支持 project quota 的文件系统及实际配置，普通单元测试不能证明它已生效。

端到端入口为 `MOLR_E2E_SANDBOX_SERVICE=1 npm run test:webui -- resource-quotas.spec.ts`，要求 Linux、systemd 用户服务、静态 BusyBox 和指定 Go 版本。该标志为每个临时 Runtime 启动独立委派服务；环境不满足而跳过时，不能报告沙盒验收通过。
