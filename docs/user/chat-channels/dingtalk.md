# 钉钉聊天入口

钉钉入口连接应用机器人与一位 Molr 助理，支持企业内人与机器人的单聊。每个机器人在同一 Molr 实例中只能绑定一位助理；绑定只接受配对用户的消息，不接收群聊。

## 准备机器人

在[钉钉开发者后台](https://open-dev.dingtalk.com/)创建应用并启用机器人能力，将消息接收模式设为 **Stream**，开通机器人发送单聊消息所需的权限，设置应用可见范围并发布。接收图片和文件还需要机器人文件下载权限。操作人需要相应的组织开发者权限。

准备应用的 Client ID（AppKey）和 Client Secret（AppSecret）。Runtime 主动连接钉钉，不需要为接收消息提供公网回调地址。运行主机必须能访问钉钉 HTTPS、WSS 和附件下载服务。不要让多个程序同时使用同一机器人接收消息；开发验收使用独立测试机器人。

## 连接与配对

1. 打开助理聊天页右上角「… → 切换聊天入口」，点击「连接钉钉」。已连接其他聊天入口时先解绑，尚未完成的配对先取消。
2. 填入应用凭据，点击连接。凭据加密保存，不写入助理上下文或状态接口。
3. 在钉钉中搜索并打开该机器人，将页面显示的一次性配对码作为一条**单聊文字消息**发送。配对码有效期十分钟，请勿转发。
4. 配对成功后，页面显示「已连接」，钉钉收到连接确认，WebUI 输入框切换为锁定状态。随后可在钉钉发送消息。

配对前继续使用 WebUI 聊天。配对码只在创建时显示；关闭页面后如未完成配对，取消配对再重新连接。错误凭据、权限缺失或 Stream 配置错误会显示连接异常；检查应用配置后取消或解绑，再次连接。应用凭据更新也使用此流程。

通过钉钉收发的消息和附件会传输到钉钉。连接确认消息的发送仍受钉钉接口权限限制：WebUI 显示已连接表示身份配对成功，投递是否成功另行处理。

## 聊天与附件

- 文字和 Markdown 双向收发；长回复拆分发送。旧聊天记录和助理上下文保留，不补发绑定前的消息。
- 接收图片、文件、富文本中的图片和视频附件。语音优先使用钉钉提供的转写，否则保存为音频附件；理解取决于文件格式与模型能力，不保证所有钉钉语音格式都可理解。
- 助理明确发布的图片和其他附件均作为**可下载文件**发送，图片不显示为原生图片消息。每个附件受 Runtime 上传上限和配额限制，渠道上限为 20 MiB；钉钉自身的格式与大小限制仍适用。
- 附件失败会明确提示未读取或发送失败，文字成功不代表附件成功。
- 不支持钉钉交互卡片。Molr 必要的任务或权限卡片转成标题、摘要和需登录的 Molr 链接；审批仍在 WebUI 完成。手机需要能访问该链接指向的 Molr 地址。
- 支持通过应用接口发送后台任务回复，无须保留临时 SessionWebhook；实际投递仍受机器人可见范围、凭据、权限和限流约束。

## 异常和解绑

断线后自动重连，连续连接失败采用 5 秒至 640 秒的退避。发送限流最多尝试五次，至少等待一分钟，并遵守平台返回的更长等待时间。超时或响应不完整记为「结果未知」，不自动重发，请先检查钉钉。平台接受消息不表示用户已读。

解雇助理或禁用账号会暂停收发，返聘或恢复账号后继续。复制助理不会复制绑定。入口互斥：绑定后 WebUI、SDK 和插件的普通聊天写入都被拒绝，历史、文件、配置和审批继续可用。

在聊天入口弹窗点击「解绑钉钉」并确认，取消待发送回复并移除当前连接凭据，恢复 WebUI 输入。已被钉钉接受的消息不能撤回。本地解绑不删除钉钉应用，也不撤销其在钉钉的权限。
