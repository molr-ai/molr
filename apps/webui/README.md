# Molr WebUI

连接真实 Go Runtime 的独立 Web 应用。`apps/ui-design` 继续保留交互原型；本应用不引用它的 demo store、模拟任务或示例数据。

## 首次引导与内嵌部署

发行构建将 WebUI 内嵌到 Runtime，同源提供网页和 API。新安装的管理员登录后进入 `SetupGate`，共享 ProviderConnectionDialog 的连接与自动发现能力，完成模型、价格和预算确认后由 `/api/setup` 原子创建默认 Molr 助理。已初始化账号和普通成员不强制显示引导。

局域网 HTTP 使用 Runtime 按端口隔离的 Cookie；开发代理转换为当前 WebUI 端口并在上游恢复。界面使用 getRandomValues 生成幂等键，不依赖安全上下文中的 randomUUID。完整发行包浏览器验收入口为 `node scripts/test-quick-start.mjs`（仓库根目录执行，需 Linux systemd 用户管理器、已构建发行包、空闲 11434/18878 端口和 Playwright Chromium）。

## 启动

先启动已初始化的 Runtime，然后在仓库根目录运行：

```bash
npm run dev
```

开发服务监听 `0.0.0.0:5191`，默认将 `/api` 代理到 `http://127.0.0.1:8080`。登录使用 Runtime 初始化时创建的账号，没有前端默认账号，也不通过 HTTP 初始化服务器。

```bash
MOLR_RUNTIME_URL=http://127.0.0.1:8081 npm run dev
npm run build:webui
npm run preview:webui
```

预览端口为 `5192`。开发代理面向本机 `tls_mode: local` 的 Runtime；先校验浏览器 Origin 与当前 WebUI 来源一致，再重写后端 Host / Origin，不转发伪造的代理身份。Runtime 仍只监听回环。代理不会移除 Secure Cookie 属性；连接 HTTPS Runtime 时，前端也应通过 HTTPS 提供。

多个 worktree 并行验收时，为每个 WebUI 分配独立端口并通过 `MOLR_RUNTIME_URL` 连接各自的 Runtime。开发和预览代理自动给登录、会话、CSRF Cookie 加上浏览器访问端口后缀（如 `molr_dev_session_p5295`），仅把当前端口的凭证转发给对应 Runtime，因此同一浏览器、同一 IP 的多个实例可以同时登录和独立退出。相同端口的新标签页仍共享登录状态。Cookie 属性及 Origin / CSRF 校验保持不变。

升级前的无后缀 Cookie 不会被代理继续使用，需要在升级后的 WebUI 重新登录一次；代理不会清除旧 Cookie，以免影响尚未升级的实例。端口隔离用于避免开发实例相互覆盖，不是同主机上不可信应用之间的安全边界。生产静态部署继续使用 Runtime 的原始 Cookie 名称；生产多实例应使用独立域名。

## 已接入的功能

个人设置与业务数据按账号隔离；资源配置和插件管理仅管理员可用，成员使用组内分配的资源。完整操作见[用户与用户组](../../docs/users-and-groups.md)。

- 认证：Cookie 登录、已有 MFA / 恢复码验证、刷新及新标签页恢复、退出、会话撤销、修改密码。
- 助理列表顶部搜索按名称即时筛选，清空恢复全部助理；列表平铺展示，置顶优先，不提供分组操作。
- 助理：聘请、重命名与切换模型、置顶、克隆、解雇、归档会话查看、返聘。克隆只复制明确选择的数据和有效授权，返聘默认不恢复旧权限与计划。
- 聊天：分页加载最新消息及更早历史、真实用户消息、附件上传和鉴权下载、服务端接受状态、持久化赞/踩、固定类型卡片、执行状态和停止操作。仅展示 Runtime 明确发布的消息，不将模型内部文本或计划唤醒事件伪装成聊天消息。 图片附件在当前预览组件内按文件 ID 和媒体类型复用下载及临时 URL；增删附件不重取未变图片，移除或卸载时取消对应请求并释放 URL。失败预览在下一次图片附件列表变化时重试。
- 聊天文本复用共享消息组件，支持 Markdown 标题、列表、引用、表格、代码块，以及 `$…$` 行内和 `$$…$$` 独立 LaTeX 公式。用户和助理消息底部均提供复制原文图标，保留 Runtime 存储的全部格式标记与空白；复制成功有反馈，局域网 HTTP 开发入口也可复制。历史消息和归档聊天沿用同样的渲染与复制行为。
- 计划：本人和所有助理共用安排总览。清单按发生时间展示接下来的 50 个事件并支持分页；日历显示单月，支持切月、日期详情与未安排事项，两视图共用筛选。聊天头部「计划」打开当前助理的同一数据。
- 执行：计划详情包含每次执行的状态、说明快照、发生时间和结果；个人可开始／完成并填写交接说明，助理任务保留实际控制、修订、费用和交付物。聊天创建的一次性任务自动关联计划，定时发生点原子创建对应任务。
- 交接：前置计划完成后在应用内提示，或明确启用自动交接；自动交接防重复并保留权限和预算边界。前置仅支持一次性计划，已有执行历史或后续依赖的计划应暂停而非删除。旧记录和旧链接兼容。
- 资源：以「模型 / 工具 / 沙盒」三个入口展示。工具页查看 Runtime 内置工具；沙盒页管理本机与远程 Linux Sandbox，存储、计算、网络归入对应沙盒，支持连接测试、默认沙盒选择和资源授权；详情见 [远程沙盒部署](../../docs/deployment/remote-sandbox.md)。模型支持提供商发现、配置、重命名和断开。权限管理使用抽屉，保留聊天内容与草稿；新增授权先选资源类型「模型」，再复用按 Provider 分组且支持搜索的模型选择器；授权范围精确到所选模型，权限列表显示模型名及所属提供商，抽屉与弹窗始终显示当前助理。有效期复用组件库 DateTimePicker，支持1天、7天、1个月、永久及自定义时间。权限选项以 Runtime 返回的资源能力为准：模型显示「查看模型／调用模型」，存储显示「读取文件／写入文件」；权限列表和克隆选择复用相同文案，切换资源时重置动作与范围。
- 提供商连接使用左侧提供商列表、右侧表单（移动端上下排列）；各提供商分别保留未提交草稿。 测试连接、保存和刷新模型期间，提供商字段、本机发现结果的选择及重新检测统一禁用，避免旧请求结果对应到新地址；操作失败后恢复选择。OpenAI、DeepSeek、百炼、智谱、Moonshot、Ollama、vLLM、SGLang 和自定义服务共用现有 `openai-compatible` 适配器。预设地址参考 [OpenAI](https://developers.openai.com/api/reference/resources/chat)、[DeepSeek](https://api-docs.deepseek.com/api_samples/chat_curl/) 和 [Ollama](https://docs.ollama.com/api/openai-compatibility) 官方文档；认证支持 API Key 和本地免认证；OAuth 仅作为未来 provider 能力预留。连接前可测试当前表单的服务地址和认证信息，返回模型数量；测试不创建资源、不保存 API Key。风险说明复用共享 Alert 提示块。连接后自动获取多个模型；连接表单的更多配置仅包含名称和默认地址；网络访问范围由 Runtime 部署配置统一限制。模型的上下文、工具能力和价格通过独立配置窗口管理，也可在提供商卡片中手动添加模型；未知价格明确标示，不视为免费。敏感操作验证默认关闭，保存 API Key 时不重复询问密码。可在用户设置 → 安全中开启，开启后才弹出独立身份验证窗口，使用真实 MFA 状态决定是否显示验证码；取消保留草稿，验证失败可重试。数据导出遵循同一开关；修改密码与安全设置始终需要确认身份。安全页同时提供验证器绑定／解绑及恢复码下载。API Key 由 Provider 管理，设置页不再提供独立的模型凭证标签；编辑连接可修改名称、地址或更换 Key，只显示已配置状态，不回显密钥。Provider 与 Key 同事务保存；更换 Key 复用独占凭证，失败时一起回滚。
- 执行详情：保留验收标准、暂停/恢复/取消、修订与交付物下载。每次执行归属明确计划。
- 设置：语言、主题、减少动态效果、默认模型、助理独立预算、回答偏好、共享/私有记忆、用量、已离职助理、设备会话、敏感操作验证开关、验证器管理以及数据导出。
- 用户设置从头像进入；移动端助理页顶部显示头像和用户名，点击进入用户设置，底部移除「我的」与管理入口。管理员设置入口位于用户设置内；最后一栏「关于」展示构建版本、commit 和 GitHub Star 入口。用户设置含「个人资料」「常规」和「连接」等栏目：个人资料支持预设头像、图片上传及清除，保存到账号并同步到桌面和移动端导航；常规以 App 风格列表展示语言、时区、币种等偏好，选择或切换后即时保存，时区从列表选择；独立「主题」tab 复用 UI Design 的六套主题预览卡，集中管理配色、明暗模式和减少动态效果，保存到 Runtime 并在其他设备登录时恢复；连接读取实际 Runtime 地址与当前会话信息，断开时撤销当前会话并返回登录。默认模型与回答偏好按设置字段保存；预算在助理信息中独立管理。
- 搜索：真实多来源检索、筛选、分页与页面跳转；关键词防抖完成时同时回到第一页，输入未稳定时暂停查询，避免以旧关键词请求新分页。仅修改首尾空白保留当前页；聊天结果通过 `#/assistants/<id>?message=<messageID>` 自动加载历史并定位、高亮目标消息，支持刷新和浏览器前进／后退，失效目标明确提示。定位历史期间不会把会话末尾自动标为已读，可返回最新消息继续聊天。

管理员首次配置时，在资源页连接 Provider，直接填写所需的 API Key；自定义服务填写基础服务地址，例如 `https://example.com/v1`。可先测试连接，再保存并自动获取模型列表。需要调整上下文、工具能力或价格时，使用独立的模型配置窗口；显式填 `0` 表示免费模型。后续通过“编辑 Provider”修改地址或更换 Key。已连接或已断开的 Provider 均可删除，确认后清理连接、模型目录、相关权限及独占凭证；助理和聊天保留，失效模型会提示重新选择。聘请助理时，Runtime 会在同一事务中自动授予所选模型的 `read` 和 `execute`，调用地址跟随 Provider 当前配置，无需再次手动授权；可在聊天更多菜单 → 权限中撤销。其他资源仍需按需授权，付费模型还需设置预算。凭证由 Runtime 加密保存；单独连接资源不会自动授予助理执行权限，聘请时明确选择模型的授权行为如上。

## 组件与数据边界

- `@molr/sdk`（`src/api/` 保留兼容导出）：匹配 Go JSON 字段的 DTO、Cookie / CSRF 请求、幂等写入、版本并发控制、分页和文件上传。会话凭证始终是 HttpOnly Cookie，CSRF proof 单独读取并放入请求头；密码与 API Key 不进入 localStorage。
- `src/state.tsx`：会话、结构化语言资源、查询生命周期和 SSE。读取请求在切换或卸载时取消，避免旧助理数据写入新会话。写入结果不确定时保留草稿，重试复用幂等键。
- `src/interfaces/official/features/`：按助理、聊天、计划、资源、任务、搜索和设置拆分业务交互；只在确认后发送写入请求。
- `@molr/ui`：复用 Logo、主题、断点、表单、Select、多选、菜单、弹层、Toast、Tabs、聊天消息/输入框/状态/反馈。`AssistantList` 和 `SearchPanel` 的组件、样式及键盘交互也由包提供，原型复用同一实现；搜索数据源以 Runtime 支持的类型为准。
- 聊天中的任务、资源、日程和权限申请统一使用 `ChatCard` 的类型／状态、标题／说明、`details` 信息行和底部操作区，最大宽度 480px，窄屏随容器收缩。`ConversationCard` 读取真实业务记录，不伪造进度；权限卡片批准后显示实际批准的资源、动作、范围和有效期。UI Design 使用同一组件与样式。
- 页面样式仅负责应用布局，文案统一放在 `src/messages.ts`。移动端使用同一套组件及底部抽屉，不挂载多个完整工作区。进入聊天详情时底部导航向下渐隐，返回助理列表时向上渐显；减少动态效果时直接切换。导航采用圆角悬浮样式，内容区延伸到菜单背后，各页面滚动内容末尾预留底部安全空间。聘请入口位于搜索按钮右侧，使用仅图标的 ghost 按钮。

通用表单与确认操作通过 `useAction` 的同步执行锁防止同一时刻重复提交；锁随每个 Hook 实例独立维护，并在成功、失败或取消后释放。`busy` 状态用于按钮反馈，不承担并发互斥。

聊天记录在消息区域内独立滚动，长会话不应扩大整个页面的滚动范围。共享消息操作区为复制结果的无障碍提示提供定位容器，使隐藏提示随消息一起滚动；默认主题与测试主题均沿用此行为。

WebUI 的页面外层高度不得超过 WebView 视口，长内容在页面内部滚动；登录、会话恢复和错误状态也遵守此约定。`tests/page-height.spec.ts` 遍历全部路由、个人／管理员设置子页、资源／沙盒分类、计划日历与插件页面，覆盖两种内置主题、桌面／手机及缩短到 420px 的窗口。设置子页从导航自动发现；新增顶级路由必须同步更新测试的 `RoutePage` 覆盖表。运行 `npm run test:webui -- page-height.spec.ts` 可执行专项回归。

IM 通过 SSE 更新，事件按 180 ms 防抖合并，从首个事件起最多等待 500 ms 就触发刷新。消息事件按会话 ID 刷新，其他会话不重新读取历史。聊天首次读取最新 50 条；后续刷新（包括重连、恢复可见性和定时对账）使用 `after_sequence` 从当前最新消息序号之后按升序增量拉取，多页结果逐页追加、按 ID 去重。向上翻页使用保留的历史游标，仅加载更早的一页。 空响应复用已有消息数组，不重新合并或排序全部历史；分页游标、元数据修订及错误恢复仍正常更新。服务端接受状态和赞/踩事件按 `message_id` 精确刷新已有消息。消息请求进行中收到的新刷新会合并排队，切换会话或卸载时才取消请求。

普通查询在同一登录会话内按路径和读取方式共享请求、结果与错误；同一版本只读取一次，进行中的请求遇到刷新时合并为一次后续读取，不持续取消。最后一个订阅者离开后取消未完成请求，重新进入页面会重新核对；账号切换清除缓存，权限拒绝清除该查询的旧数据。默认主题的助理列表使用分页活动摘要，统一取得做梦状态和最多 80 个 Unicode 字符的最新消息预览，列表行不单独请求完整状态或消息。当前聊天仍读取完整执行状态。 消息发送完成只清理仍与发送时相同的草稿；期间发生过导航或聊天卸载时，不再自动切回原聊天或清除新的搜索定位，重新进入后编辑的草稿会保留。

当前 Runtime 不为所有业务模块广播实时事件。共享查询按路径去重并串行请求，以本机写入和 SSE 定向刷新为主：动态数据通常每 30 秒校准，设置、模型、插件、授权和能力等配置每 5 分钟校准；Runtime 信息及不可变详情不定时刷新。页面重新可见、网络恢复和 SSE 重连会补查。隐藏或离线时暂停共享查询，瞬时错误按 2、4、8 秒递增退避，最长 60 秒，并遵守更长的 Retry-After；权限等终止错误不自动重试。聊天历史、工作台轨迹和计划分页只校准各自的窗口，不再触发所有查询失效。这里没有伪造的 token 流。草稿按账号和助理保存在 UI Host 内存及当前标签页的 sessionStorage，刷新可恢复、主题间共用；不通过 Runtime 跨设备同步，存储不可用时退回页面内存。

Shell 任务按钮与面板共享查询：运行中分别请求 5 秒和 2 秒节奏，取当前订阅中最快者；空闲时每 30 秒校准。任务开始／结束通过 `shell.tasks` SSE 定向刷新。输出每次请求结束 1.5 秒后按 cursor 读取，读取不触发业务修改通知；隐藏和离线暂停，任务结束且服务端确认输出已稳定、当前流读空后停止。做梦执行记录在排队／运行／提交期间每 5 秒刷新，空闲每 30 秒刷新并更新记忆目录，配置每 5 分钟校准。微信扫码与通知初始化重试复用同一串行、可见性和退避策略。

`tests/chat-sync.spec.ts` 验证共享查询、列表请求不按行增加、跨会话事件隔离及当前会话更新；`tests/query-store.spec.ts` 验证连续刷新、共享取消、权限拒绝与会话清理。

首次读取超过 300 ms 才显示骨架，快速请求直接呈现内容。当前登录会话在内存中保留最多 100 份查询或聊天快照：重访页面先显示已有内容、后台刷新，普通刷新不会清空现有界面。普通查询的快照读取不创建缓存条目，未提交订阅的渲染不会占用缓存容量或挤掉已加载的结果。退出时清空缓存，收到 401/403/404 时移除对应缓存；不写入 localStorage，也不跨账号复用。

局部错误提示的重试倒计时仅在提示可见且具有重试按钮时更新，按 Retry-After 截止时间结束；到期、关闭、移除按钮或卸载后停止计时。`tests/error-retry-countdown.spec.ts` 通过实际组件和浏览器虚拟时钟覆盖精确到期、截止时间替换与清理；开发服务的 `/tests/fixtures/error-retry.html` 可交互查看模拟限流，不发送后端请求。

导航的 `ConnectionLogo` 表达真实 SSE 状态，替代原来的连接小点。浏览器离线时显示淡出的静态图案，恢复联网后自动重试；连接过程中播放 loading。终止性错误或 20 秒未建立连接会进入失败状态，可点击 Logo 重试；移动端未显示 Logo 的页面仍可使用状态提示中的重试按钮。重连失败横幅的背景和文字复用 Alert danger 的颜色变量；连接横幅出现时，页面不重复显示“服务暂时不可用”错误，登录页与其他业务错误仍保留各自反馈。收到 SSE `open` 后播放一次恢复动画，再回到正常 Logo；首次成功连接直接显示正常状态。SSE 出错后立即核对当前会话；确认失效时返回登录，网络错误保留连接重试状态。核对请求在重连成功、重新连接或卸载时取消，旧账号的迟到响应不会退出新账号。重试保留最近收到的事件游标，恢复时补拉聊天增量并刷新其他查询；退出登录时关闭连接、取消请求与计时器。

浏览器安全沿用 Runtime 的鉴权、Origin 校验和与会话绑定的 CSRF proof。可读 CSRF Cookie 不是会话凭证，服务端仍校验该会话存储的摘要，并拒绝缺少/伪造的 proof；相关防御原则见 [OWASP CSRF 指南](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)。

### 偏好设置草稿

保存默认模型和回答偏好时提交点击保存时的快照；等待期间仍可继续编辑，成功响应只更新此后未改动的字段，并更新已保存版本，方便继续保存新草稿。其他客户端修改了同一组偏好时，仍提示冲突并由用户选择刷新。

### 记忆文件编辑

文件与来源读取遵循最近一次打开操作；新建、切换助理或目录、离开页面和关闭弹窗会使旧读取失效。每次编辑独立保存文件引用、版本与草稿状态，迟到的读取或保存完成回调不会改变新草稿的目标或关闭新的弹窗。

### 登录链接

登录链接生成成功后直接展示一次性链接弹窗，作为该操作的成功反馈，不另显示通用保存 Toast，以免遮挡窄屏弹窗的操作按钮。

用户设置 → 安全 → 登录链接，可生成 15 分钟、1 小时或 24 小时有效的一次性链接，并选择登录后的页面。创建需要现有的身份验证，完整链接仅在创建后显示一次；列表可查看使用/过期状态与撤销。列表按最近的有效到期时间刷新；没有待到期链接时不创建到期计时器，页面重新可见时校准状态。点开链接先显示确认页及真实到期时间，只读取链接状态，不消费链接；点击「确认登录」后才兑换正常 Cookie 会话，并自动前往创建时指定的页面，启用 MFA 时仍要求验证码。关闭确认页不影响原链接使用；由于凭证只保留在内存中，刷新确认页后需重新打开原始链接。Token 使用 URL fragment 并立即清除，既不存浏览器持久化存储，也不作为 API Bearer 使用。链接可以用于新设备或独立验收环境，不能跨 Runtime 登录。

### 聊天气泡的本轮信息

助理气泡下方的 info 按钮按需读取 `GET /api/conversations/{conversationID}/messages/{messageID}/metrics`。同一执行发布的多个气泡共享统计与前端缓存。执行中只在弹层展开且页面可见时每 2 秒查询；关闭后中止请求和轮询。页面可见性监听仅在弹层打开期间注册，重新打开时读取当前可见状态。普通消息渲染只读取已有快照，不为尚未打开的弹层创建条目。缓存按打开／刷新及关闭时间保留最近记录，通常最多 100 条；活跃订阅和进行中的请求不被回收，可暂时超过上限，释放后回收旧的闲置条目。关闭后没有数据的占位条目立即释放。仍在缓存中的 `Finalized=true` 快照不重复查询，被回收的记录再次打开时按需重取；刷新页面或退出登录清空，旧请求的返回不能写入新会话。后端每次从同一事务快照读取执行状态、模型 receipts 和原始计时，动态汇总，不存储聚合结果或统计版本。

`npm run test:webui -- turn-metrics-cache.spec.ts turn-metrics.spec.ts` 覆盖占位分配、缓存上限、活跃订阅保护、重新打开、取消、会话切换、真实轮次统计与工作台定位。

输入 token 包含缓存输入；本轮汇总的缓存命中率为缓存输入 token 除以输入 token，百分比最多保留一位小数，输入为零或数据缺失时显示 `—`；费用按调用时的 receipt 累加，统一换算为偏好币种展示；未知费用显示待确认。首 token RT 是请求发出到首个有效文本、推理或工具参数片段的时长，概览取有效样本平均值；token/s 为有效采样调用的输出 token 总和除以生成时间总和，排除首 token 等待、工具及排队时间。单片段响应无法测量生成速度。总耗时从 Runtime 首次处理本轮到终止，包含工具及重试等待，不包含首次排队。旧记录或非流式响应缺失的计时展示 `—`，不视为零。

本轮信息弹层不再展开每次调用详情。部署能力开启且个人设置显示开发工作台时，显示「在开发工作台中查看」，入口位于独立底部操作区，使用工作台图标、次要按钮与右箭头。点击进入当前助理的工作台并定位本轮执行，自动加载必要的历史、选中轮次并打开触发快照；未采集或已过期时明确提示。未设置显示时隐藏入口。模型协议层请求 SSE 并保留原始流和计时，同时兼容返回完整 JSON 的服务；中断或缺少最终 usage 的响应保持费用未知，不自动重新发送模型请求。聊天消息仍通过 `conversation_publish` 发布，不把私有模型推理写入聊天。

2026-09-30 验证：本轮信息的按需查询、缓存复用及工作台入口已通过桌面和移动端回归；个人开关关闭或部署能力未开启时隐藏入口，开启后跳转到对应助理并定位本轮，覆盖跨页补载旧轮次、刷新恢复及未采集提示。

## 消息通知与系统提醒

服务端统一保存提醒状态，默认／测试主题共用聊天提醒和主动提醒。不设独立通知页面，提醒直接跳转对应聊天、授权、任务或计划，业务历史保留在来源页面。聊天一次展示一条，按发生顺序排队，新提醒不打断当前条；关闭成功才显示下一条，失败保留原条，不使用通知滚动区。已读／关闭通过 API 保存并用 SSE 同步到其他设备，刷新不会重新激活。消息未读仍由会话管理，Toast 和桌面弹窗只是投递方式。普通保存、表单校验和客户端连接状态保留为局部反馈。


“用户设置 → 通知设置”管理当前浏览器、当前账号的新消息提醒、内容预览、提示音和桌面通知。默认关闭主动提醒、内容预览和提示音。提示音与桌面通知独立控制，关闭桌面通知仍保留应用内提醒且不影响提示音；总开关关闭后停止主动提醒。系统提醒在查询详情或等待跨标签页声音去重期间也遵守最新开关，关闭的通道不再发出尚未投递的提醒。桌面主侧栏和手机底部导航始终汇总未归档会话的未读数（超过 99 显示 99+），独立于通知开关及所选界面包。

不支持桌面通知或普通局域网 HTTP 环境只展示可用设置，不要求用户配置域名和证书；仍可使用角标、应用内提醒和提示音。可信 HTTPS 或本机 loopback 环境提供桌面通知开关与按需授权按钮；权限只由用户点击请求。前台页面使用应用内提醒，后台页面在用户启用并授权后使用桌面通知。

宿主层 `src/notifications/` 订阅现有 SSE，不依赖具体聊天界面包。Runtime 的会话事件提供 `ConversationID` 引用，消息内容通过原有鉴权接口按 ID 获取。首次加载以会话序号快照为基线，避免历史回放提醒；服务端通知以活动通知 ID 快照为基线，避免用客户端时钟判断新旧；IndexedDB 原子事务按账号、会话序号去重，BroadcastChannel 协调正在阅读的标签页，短时间消息按会话合并。关闭 Toast／桌面弹窗不标记已读；已读事件、禁用和退出登录清理通知，关闭桌面通知只清理该通道的通知，关闭提示音只停止声音。存储不可用时自动通知停止，聊天及未读数继续工作。 每个通知协调器在首次消息去重及后续有消息且距上次清理至少一分钟时，回收超过七天的去重记录；短时并发消息复用一次清理，事务失败后重试，时钟回拨时重新核对。

提示音使用本地 Web Audio 合成短音，无额外音频下载。点击启用或试听时解锁音频；刷新后按浏览器策略可能需要再次交互，自动消息不会排队等待解锁。消息去重后，IndexedDB 原子事务为同一账号的所有会话与标签页提供 5 秒全局冷却；连续消息不补播。试听是明确的用户操作，不占用自动提醒冷却。桌面通知请求静音，由应用的声音设置控制提示音，避免平台默认声音与应用声音叠加（最终行为仍受平台支持和系统设置影响）。

`NotificationAdapter` 定义权限查询、请求、展示、关闭和释放接口，桌面宿主可注入原生适配器。浏览器适配器使用专用 Service Worker 展示通知和处理点击，通知内容不写入页面持久化存储。该 worker 不缓存页面、不接收 Push，页面必须保持运行并连接 Runtime；页面关闭、休眠或被系统挂起时不保证送达。Web Push 与桌面后台接收尚未实现。`send` 成功只代表浏览器接收展示请求，系统免打扰等设置仍可能阻止弹窗。


资源额度审批真实沙盒回归使用 `MOLR_E2E_SANDBOX_SERVICE=1 npm run test:webui -- resource-quotas.spec.ts`。每个测试 Runtime 单独运行于 systemd 用户委派服务，测试结束自动停止；无该标志时专项显式跳过。覆盖组合申请、修改批准值、自动网络选择、共享流量用量及刷新恢复。

插件配置、连接列表、调用记录和隔离页面的读取使用 SDK `api.read`，不发布业务修改通知；保存配置、修改连接和主动连接测试仍发布通知。`tests/plugin-read-queries.spec.ts` 通过真实 Runtime 验证宿主与 MessageChannel 的读取／写入边界。

### 消息反馈

消息的赞／踩使用共享 `ChatMessageMeta` / `ChatFeedback`：原版图形，选中时袖套实色、手掌浅红／浅灰填充，无按钮边框和底色。图标尺寸、线宽与同排复制／信息按钮一致，按钮间距为 8 px。点赞轻弹、点踩下压回弹，取消与刷新恢复不播放激活动效；遵循系统及账号的减少动态效果偏好。反馈仍通过原有 Runtime 接口持久化。

消息反馈点击后立即更新选中态并播放动效，保存超过 300 ms 时在按钮下方显示小圆点；期间只锁定该消息的赞／踩，输入框和其他消息仍可操作。成功后保持选择，不重复播放动画；失败时恢复原选择并提示重试，随后重新同步服务端状态。取消反馈同样即时显示。

关于页构建信息由 Vite 在构建时写入：版本默认读取根 `package.json`，commit 默认读取当前 worktree 的 Git HEAD；可使用 `MOLR_VERSION` 和完整十六进制 `MOLR_COMMIT` 覆盖（无 Git 元数据的源码包需要显式提供 commit）。`build:release` 将同一版本与 commit 传入 WebUI 和 Runtime。网页显示 12 位短 commit，链接保留完整 ID；运行时无需读取 Git，也不会随服务器后来切换分支而变化。

## 页面代码按需加载

登录与会话恢复只加载应用壳所需脚本；默认主题、测试主题、管理员页面、插件管理与隔离页面入口通过动态导入加载。页面下载期间保留工作区导航，延迟显示加载占位；下载失败沿用页面错误边界，并可用「重试」重新加载当前网址。重新加载保留账号 Cookie 和当前标签页已保存的聊天草稿。

共享 UI 包仅把 CSS 声明为导入副作用，构建器可以从首屏移除尚未使用的组件及 Markdown／公式渲染依赖。此声明要求组件模块不依赖必须在导入时执行的全局初始化；新增这种初始化时需要显式登记。样式仍由组件或应用的显式 CSS 导入保留。

`tests/lazy-pages.spec.ts` 在生产构建上检查未登录时不下载业务页面、慢速下载时导航可用、下载失败后重试，以及真实聊天的 Markdown、公式与样式。先运行 `npm run build:webui`，再设置 `MOLR_E2E_PREVIEW=1` 运行此测试；测试服务使用 Vite preview 和独立 Runtime，其他回归默认仍使用开发服务器。
