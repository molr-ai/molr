# Molr 产品官网

包名为 `@molr/website`，用于 `molr.ai` 的独立官网。通过配置在正常主页、上线预告和网站更新页之间切换。上线预告和更新页沿用居中的动态 Logo；正常主页提供产品介绍、场景界面示意和导航。

在仓库根目录运行：

```bash
npm ci
VITE_SITE_MODE=live npm run dev:website
npm run build:website
npm run preview:website
```

开发服务监听 `0.0.0.0:5189`，构建预览监听 `0.0.0.0:5190`，均支持局域网访问。生产产物为 `apps/website/dist/`，可独立部署到静态托管平台的域名根路径。根目录 `npm run build` 构建所有提供 build 脚本的工作区。

## Cloudflare Workers 部署

仓库根目录的 [`wrangler.jsonc`](../../wrangler.jsonc) 部署 `apps/website/dist/` 到 `molr` Worker。保留 Cloudflare Workers Builds 对 GitHub 仓库的授权和 `main` 自动部署。

| 设置 | 值 |
| --- | --- |
| 根目录 | 仓库根目录 |
| 构建命令 | `npm run build:website:release` |
| 部署命令 | `npx wrangler@4.45.0 deploy` |
| 构建变量 | `NODE_VERSION=22.21.0`、`VITE_SITE_MODE=live` |

发布构建命令默认检查最近 100 条公开 GitHub Release 元数据，按版本号选取正式版、预发布及 nightly 各一个，下载最多三份 manifest 并验证渠道目录，再构建官网；不依赖 GitHub CLI。Cloudflare 自己管理部署认证，GitHub 无需配置 Cloudflare Account ID／API token。普通本地构建仍使用 `npm run build:website`，不会自动联网读取发行信息。`MOLR_RELEASE_SCAN_LIMIT` 可调整检查条数，Cloudflare 构建变量与 GitHub 仓库变量应保持一致；窗口内缺少的渠道不会触发历史扫描。

在 Cloudflare Worker 的 Settings → Builds → Deploy Hooks 创建绑定 `main` 的 hook，将 URL 保存到 GitHub 仓库 secret `CLOUDFLARE_DEPLOY_HOOK`。`.github/workflows/website.yml` 在 release 完成后请求重新构建，并等待官网清单及安装脚本更新；main push 仍由原生仓库集成触发。详细配置、变量和重试见[发行维护](../../docs/dev/releasing/releases.md)。Runtime 按[部署指南](../../docs/admin/README.md)独立部署。

## 网站状态开关

将 `apps/website/.env.example` 复制为同目录下的 `.env.local`，设置 `VITE_SITE_MODE`：

| 配置值 | 展示内容 |
| --- | --- |
| `coming-soon` | 上线前的「即将上线 / Coming soon」多语言轮播，当前默认值 |
| `maintenance` | 网站更新时的「马上回来 / Be right back」多语言轮播 |
| `live` | 显示个人 AI 助理主页，包含产品场景、安装与文档入口 |

也可在仓库根目录直接指定环境变量：

```bash
VITE_SITE_MODE=maintenance npm run dev:website
VITE_SITE_MODE=live npm run build:website
```

修改 `.env.local` 后重启开发服务。此开关在构建时确定，生产环境切换时需要重新构建并部署 `apps/website/dist/`；`npm run preview:website` 展示已构建产物中的模式。未设置或留空时保持 `coming-soon`，其他非法值会在启动或构建时报错。

`src/App.tsx` 根据模式选择 `HomePage` 或通用的 `SiteStatusPage`。正常主页位于 `src/HomePage.tsx`，样式在 `src/home.css`，中英文文案在 `src/home-content.ts`；上线预告和更新页共用 `src/StatusMessage.tsx` 的轮播与 `src/BrandPage.tsx` 的视觉布局。配置校验位于 `src/site-mode.ts`，各模式文案集中在 `src/site-content.ts`。

## 正常主页

本地开发和验收通常使用 `VITE_SITE_MODE=live npm run dev:website` 查看完整主页。未设置 `VITE_SITE_MODE`（包括未在 `.env.local` 中配置）或留空时，仍使用 `coming-soon`。

首屏保留“你的个人 AI 助理”标签、“从好奇出发。”主标题与“长久相伴，与你一同成长。”副标题；移除长段概述后，通过响应式间距保留原区域的留白。主页依次介绍设备连接、全天候工作、反馈与记忆、模型选择，以及计划与权限边界。“连接你的设备，拓展助理的能力”展示多台设备接入及各自的权限边界，Runtime 的 sandbox 模式提供远程存储、计算和网络，场景示意不代表跨 Runtime 执行迁移；“全天候工作”以 Molr 服务持续运行为前提；“从你的反馈中学习”突出定期自动回顾与手动记忆管理；“本地模型，也是一等公民”独立展示云端与本地模型的助理体验；“让每次委托，都有安排与边界”整合计划、资源权限和预算。各段共用一致的图文组件与场景示意，手机上先文后图，中英文同步维护。主页不显示场景示意、示例内容或开发中提示；多端接续指浏览器登录同一账号、连接同一服务。导航以留白连接首屏，不使用底部分隔线。聊天／计划／资源场景按钮位于界面下方，相隔 32px，切换静态界面内容，不连接 Runtime；上方保留与按钮行等高的留白，保持界面与首屏操作区的原有间距，英文窄屏换行时同样保持。首屏背景光晕在底部渐隐，避免在界面演示下方形成硬切边；演示框阴影和按钮间距保持独立。

首屏 App 预览在 `src/ProductPreview.tsx` 中维护，沿用当前官方 WebUI 的独立图标导航、8px 工作区间距及无边框圆角卡片；聊天复用 `@molr/ui` 的助理列表、预设头像、消息、附件、状态和输入框，计划与资源沿用应用页头和分隔线列表，资源分类为模型、工具、沙盒。预览内部为不可操作的静态示意，场景切换按钮仍可通过鼠标和键盘操作。窄屏聊天隐藏主导航，计划与资源在内容下方显示独立导航卡片；中英文和配色随官网偏好更新。

导航包括主页、文档、GitHub、语言和明暗切换。首屏提供桌面应用下载按钮和“更多下载选项”下拉，按浏览器提供的操作系统与架构匹配安装包；无法匹配时默认选择列表第一项。下拉按清单原顺序列出实际发布的平台和架构，选择后更新主下载链接。主按钮第一行显示“下载 Molr 桌面版”，第二行以小字号、70% 不透明度显示“系统 · 架构”。下载按钮组固定宽度 280px，受容器宽度约束，切换平台时保持宽度不变。下载图标与文字间距为 12px，下载与下拉图标均为 20px，下拉区域宽 56px，图标在按钮内垂直居中；下拉选项以单行“系统 · 架构”显示，例如“Windows · AMD64”和“macOS · Apple Silicon”。下拉选项与桌面安装区三个平台面板统一使用 Phosphor Icons 的 Apple、Windows、Linux 系统图标，通过 `SystemIcon.tsx` 按需导入，继承语义文字颜色，原始 MIT 许可随第三方通知交付；仅在系统与架构均匹配浏览器检测结果时显示“当前设备”标签，手动选择其他平台不会改变该标签。版本号只在下拉内展示，主按钮下方不再展示版本、文件格式或客户端说明。可用时使用 User-Agent Client Hints 获取架构；无法使用时读取浏览器平台信息，macOS 的 Intel User-Agent 不作为可靠的处理器判断。不根据浏览器型号生成下载地址。下载区下方保留“更多安装方式”链接，跳转底部安装区；文档通过顶部导航访问。无可用安装包时，主按钮显示下载图标和“即将推出”，使用虚线边框、透明底色并保持不可交互；不显示空的下载下拉。“更多安装方式”使用向下箭头。

官网安装入口不提供渠道切换。桌面下载按 stable、preview、nightly 的优先顺序取第一个可用发布；后端与沙盒只使用正式渠道最新版，不回退到预发布或 Nightly。对应发布为空时显示“即将推出”，读取失败可重试。渠道选择和命令参数在管理员文档中说明。顶部下载与底部桌面下载共用目录读取逻辑。

底部安装面板提供“桌面应用 / 部署后端 / 部署沙盒”三个按钮入口，选中项使用中性底色。默认选择部署后端，对应 server 模式；部署沙盒对应 sandbox 模式。模式与资源权限分别配置。命令固定使用 curl，省略版本和架构参数，安装器自动检测系统与架构并安装正式渠道最新版。页面不再提供安装选项或下载工具选择，具体参数在详细安装指南中说明。后端与沙盒仅提供命令安装和 Agent 安装；下载安装包与 Docker 部署只在详细安装指南中介绍。Agent 指令要求正式渠道最新版和当前模式。所选产物的版本号统一放在安装入口行右上角。内容区直接呈现说明与操作，不重复显示桌面应用、后端、沙盒或 Agent 安装标题。

主页装饰配色复用 `@molr/ui` 的 `paletteBrandColors`：安装按钮使用标准 primary 配色，青柠用于品牌装饰与安装区标题，海盐蓝、鸢尾紫与暖砂用于首屏装饰。场景示意使用统一中性表面；安装区保留森林深色背景；入口使用共享 Button 组成按钮组，安装方式复用共享 Tabs，下载和复制操作使用共享按钮样式。各段场景统一使用主题中性底色与界面表面色；场景按钮组选中态使用中性底色，不使用青柠强调色。首屏界面示意的彩色背景在界面底部之前收住；下方场景共用一致的背景和内边距。配色仅作用于主页。

主页语言保存到 `molr-website-locale`，首次和无法读取偏好时跟随浏览器；存储不可用时仍能在当前页面切换。外观复用 `@molr/ui` 的 `molr-theme` 偏好，默认跟随系统，按钮手动切换浅色／暗色。导航前有键盘跳转到正文的入口，320px 起适配小屏。

## 语言、动画与主题

两种状态页按固定顺序轮播中文、英文、日语、法语、韩语、西班牙语、德语、意大利语、葡萄牙语和阿拉伯语。首句优先匹配浏览器语言，无匹配时从英文开始；每句 5.2 秒，包含柔和显现、停留和隐去。文字使用轻微位移与虚化衔接，固定高度避免不同文字带来布局跳动，阿拉伯语使用从右向左的排版。正常主页首次按浏览器中英文偏好显示，可通过导航按钮切换并保存选择，不轮播。保存的主页语言不改变两种状态页的浏览器语言行为。

后台标签页暂停轮播，恢复后重新开始当前句的显示过程。系统启用减少动态效果时，停留在浏览器首选语言，不进行文字过渡。轮播文字对读屏软件隐藏，标题保持稳定的可读名称，避免循环播报。

`src/use-locale.ts` 根据当前模式和浏览器的中英文偏好设置页面标题、描述、Open Graph 元信息、HTML `lang` 与 Logo 的读屏操作名称；这些信息不会随每一帧轮播反复变化。Vite 将对应模式的标题、元信息和中英文兜底文案写入 HTML，HTML 启动脚本在 React 加载前设置同样的页面语言。

官网通过 `@molr/ui` 复用动态 Logo、`useTheme` 和语义颜色变量，外观沿用共享主题偏好，默认跟随系统。Logo 按本地 08:00–20:00 播放安静模式，其余时间播放活泼模式，等待时点击可继续；文字轮播与 Logo 时间轴独立。启用减少动态效果时使用静态 Logo。

Vite 的 `publicDir` 指向共享 UI 包的 `public/`。`/theme-init.js` 在首次绘制前设置配色，`/brand/` 提供 Logo 和 favicon；字体与样式直接从 HTML 加载，关闭 JavaScript 时显示中英文双语兜底内容。页面包含独立标题、描述、canonical 和 Open Graph 元信息。

品牌与组件的展示应用位于 [`apps/ui-design`](../ui-design/README.md)，不属于官网页面内容。

## 验证

在仓库根目录运行 `npm run test:website`。首次使用需 `npx playwright install chromium`；也可通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指定已安装的 Chromium。

测试分别构建三种模式，在监听 `0.0.0.0` 的临时预览服务上检查中英文、桌面与手机、深浅色、元信息和无 JavaScript 兜底，并验证状态页的十种语言轮播、后台暂停与减少动态效果，以及主页场景切换、语言／主题刷新持久化、存储不可用、占位入口、安装锚点、设备检测、两种安装方式切换及复制结果。构建产物使用临时目录，测试结束后清理；截图保存在忽略提交的 `apps/website/test-results/site-modes/`。

## 产品文档

`live` 模式提供 `/zh/docs/` 与 `/en/docs/` 总入口，以及各语言下的 `user/`、`admin/`、`dev/` 三类指南。构建只读取 `../../docs-routes.json` 登记的 `docs/` Markdown，无需复制正文。清单通过 `section` 区分指南，并维护阅读顺序、分组、URL 及中英文标题。中文正文位于 `docs/{user,admin,dev}/`，英文在 `docs/en/` 下镜像相同结构；两种语言都必须有正文。URL 中的语言优先于保存偏好和浏览器语言，切换语言使用 History API 跳转到同篇文档，并按对应章节保留定位，支持刷新和前进／后退。没有语言前缀的入口按偏好补全路径。顶部菜单可切换指南；侧栏、搜索和前后篇限定于当前指南及语言，正文可显式链接其他指南。明暗偏好与官网共享。

文档搜索通过侧栏按钮或 Ctrl／Cmd + K 打开弹出面板，范围为当前语言与当前文档栏目。搜索图标置于输入框内，初始与无结果状态使用居中的图标和提示文字。结果区分标题、章节和正文匹配，标题优先排序，展示命中片段与关键词高亮；章节与正文命中可跳转到对应章节。支持方向键选择、Enter 打开、Escape 关闭和焦点恢复；保留搜索词，空查询不扫描全文。搜索索引在文档加载时建立，排除 Markdown 标记、注释和链接目标，保留正文与代码内容。搜索输入与移动端目录开关保留当前正文和已绘制的图表，切换文档时更新正文，切换明暗模式时更新图表。阅读导航提供桌面侧栏、移动端折叠目录、本页章节锚点和前后篇导航。侧栏分组使用加粗标题与组间分隔线，标题前的空心圆在当前文档所属分组中显示为实心圆，组内链接沿竖线缩进；当前页面同时使用底色、加粗和侧边标记定位。侧栏标题与搜索按钮固定在导航滚动区域之外，长目录在剩余高度内独立滚动；手机无需展开目录即可打开搜索。搜索结果在弹窗内独立滚动。左右目录的原生滚动条使用透明轨道，滚动时显示滑块，停止约 700 ms 后隐藏；保留滚动区域宽度，显隐不引起布局跳动。顶部“文档”菜单将当前用户、管理员或开发者文档类别加粗标识。导航下方仍有内容时显示缓慢上下移动的向下箭头，滚到底或内容能完整容纳时隐藏；搜索、窗口缩放和手机展开目录会重新判断。箭头不占用导航高度，系统／浏览器启用减少动态效果时保持静止。官网与文档间的站内链接通过 History API 无刷新切换，文档切页保留侧栏和搜索词并关闭搜索面板，并收起移动端目录；普通切页回到顶部，章节链接定位目标，浏览器前进后退恢复阅读位置。修改键、新标签页、下载和外链保留浏览器原生行为。Markdown 相对链接转换为官网路径，并保留章节片段；引用未登记官网路由的仓库文件时展示仓库路径，避免链接到未公开的仓库或不存在的网页。文档表格与 Prompt 区块使用一致的表面底色和中性标题底色，随主题与明暗模式切换。原始 HTML 不执行。以 `> [!WARNING]` 开头的引用块使用共享 Alert 的 warning 样式，显示警告图标和本地化标题；相邻提示用空行中的 `<!-- -->` 分隔，避免 Markdown 将其合并。`> [!INFO]` 使用共享 Alert 的 neutral 样式，显示信息图标和本地化提示标题。普通引用保持原样。`> [!PROMPT]` 渲染为独立的示例 Prompt 块，支持一键复制正文与成功／失败反馈，局域网 HTTP 使用同步复制方式；相邻示例同样用 `<!-- -->` 分隔。

构建会为每篇已登记文档生成 `dist/{zh,en}/docs/**/index.html`，包含对应语言的 HTML `lang`、标题、描述、Open Graph、canonical 及双向 `hreflang`，可在支持目录索引的静态服务器直接访问和刷新。正文由 JavaScript 渲染。静态托管建议为未知路径配置 404；支持 SPA fallback 的托管会显示文档未找到提示。`coming-soon` 与 `maintenance` 模式不开放文档页面，也不生成文档 HTML 入口。

运行 `npm run test:website` 会检查桌面和手机逐字搜索时正文与图表的节点保留、搜索结果切页及图表主题更新，并检查各篇文档、生成的 HTML 元信息、相对链接与深层锚点、搜索、语言和主题、手机目录，以及 320px 至 1440px 的布局。

## 本地安装分发

`installer-plugin.ts` 从 `scripts/install.sh` 输出 `/install.sh`。生产构建使用 `MOLR_CATALOG_DIR` 指定经过验证的渠道目录，输出到 `/releases/`。目录只含公开版本信息与 GitHub 下载地址，二进制不进入 Worker。安装区运行时读取 `/releases/catalog.json`，自动展示正式发布的平台、最新版安装命令及 Agent 指令；无版本时显示空状态，读取失败时可重试。

`MOLR_RELEASE_URL` 配置脚本默认发布源，默认为 `https://molr.ai/releases`；安装区默认使用当前站点 `/releases`，跨域源可用 `VITE_RELEASE_SOURCE` 指定。验收使用 `MOLR_CATALOG_DIR=.cache/release-catalog VITE_SITE_MODE=live npm run dev:website`。未指定 catalog 时输出空目录，不把开发包当作公开发行版。保留 `MOLR_RELEASE_DIR` 供本地校验包下载，放在 `/packages/`，不能与 catalog 同时配置。

安装区采用通栏布局。后端与沙盒共用“命令安装 / 让 Agent 为我安装”两个 tab；用途说明与 tab 之间仅用留白分组，切换后端／沙盒时保留安装方式并更新模式。下载安装包与 Docker 安装见详细安装指南。

“让 Agent 为我安装”复制当前语言、模式和安装正式渠道最新版的任务；系统和架构由 Agent 检测。server 模式要求返回访问地址与登录链接；sandbox 模式要求节点地址、连接方式与能力验证。两种模式共用官方安装指南。指令链接始终使用 `https://molr.ai`，开发预览不写入本地地址。发布目录读取失败或没有版本时仍可复制，并请 Agent 按文档检查可用方案。

`installer-plugin.ts` 将 `docs-routes.json` 中已审查的 `admin/deployment/agent-install.md` 中英文正文显式输出为 `/agent-install.md` 和 `/en/agent-install.md`，与文档页共用来源；开发服务与生产构建均可直接读取，不依赖 JavaScript。与 `/install.sh` 一样，这两个安装资源在三种站点模式下都可用，响应类型为 `text/plain; charset=utf-8`，使用 `Cache-Control: no-cache`。新增其他 Markdown 不会自动公开。修改说明后同步维护中英文并运行 `npm run docs:generate`。

桌面应用安装区采用通栏布局，依次展示产品说明、完整版与远程客户端的区别、下载区。下载区按 macOS、Windows、Linux 分组，只展示默认发布实际包含的平台；每组按处理器架构提供下载和 SHA-256 校验，保留未签名／未公证提示。版本号在安装入口行右上角统一显示；说明分隔线下方保留 24px 间距；平台卡片在桌面、平板和手机上分别为三列、两列和单列；命令安装和桌面应用的加载中、无版本与读取失败共用居中图标与中性表面的状态区，读取失败可重试。

## 公开文档范围

`../../docs-routes.json` 是经审查的文档入口清单。`docs-plugin.ts` 仅从这些条目读取公开 Markdown，为页面内容和搜索提供同一份数据；新文件不会因为落在文档目录就自动打包。新增路由前审查内容并更新文档索引，不登记内部规划或本地验收记录。

`internal-docs/` 不进入 Git、静态资源或构建产物。共享发布插件拒绝导入该目录，开发服务器也拒绝直接读取；文档路径不允许目录越界和符号链接。目录调整后检查旧路由、全文搜索、正文链接和生成的 JavaScript，不能仅从导航中隐藏页面。
